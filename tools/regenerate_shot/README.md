# regenerate_shot

Повтор генерации плана по сохранённому запросу без нового согласования опор и промпта. Его запускает кнопка «Перегенерировать» на странице «Производство», когда опоры и промпт устраивают, а результат нет. Инструмент только готовит новую попытку и записывает вопрос отправки; платную отправку выполняет приложение после ответа `send` по показанным SHA и цене, следующие повторы согласуются отдельно.

## Контракт

```sh
python3 -B tools/regenerate_shot/regenerate_shot.py M32
python3 -B tools/regenerate_shot/regenerate_shot.py M32 --source asset --json
```

- Источник запроса (`--source auto` по умолчанию): сначала последний пакет плана в `plan/batches` или `plan/awaiting` с подготовленной попыткой (`request_dir/request.json`), при отсутствии подготовленных попыток — снимок принятого комплекта `assets/shots/Mxx/generation-request.json`. Повреждённый последний `request.json` останавливает повтор с конкретной ошибкой; другой источник вместо него не подставляется. Исходный снимок и принятые файлы не переписываются.
- Снимок принятого комплекта содержит `schema_version: 1`, обязательное непустое поле `provider` (при сравнении с настройками пробелы по краям и регистр несущественны), `command`, `model`, `parameters`, `outputs`, `inputs`, `prompt`, `prompt_sha256` и `path_base: "asset_directory"`. `kind` по умолчанию `video`; для изображения указывается `"image"`. `prompt` — строка с именем файла, `prompt_sha256` — его SHA-256 из 64 шестнадцатеричных символов. Входы — список файловых дескрипторов с `path`, сохранённым `sha256` и именованным `slot`; для них используется флаг `input`. Другие флаги (например, `image`) сохраняются явно без `slot`. Общие изображения задаются через `root: "source"`. Это контракт снимка, который записывает `accept_shot`.
- `request.json` подготовленной попытки читается в общем замороженном формате: обязательный `provider` — непустая строка; промпт — объект `{ "path": "prompt.txt", "sha256": "…" }`, каждый вход содержит явный `flag`. Модель, параметры и `outputs` берутся непосредственно из документа; `model_selection` сохраняется при наличии. `cli_argv` не исполняется. Форма промпта и входов определяется видом документа и не подменяется другой.
- Отсутствующий провайдер, отсутствующие обязательные поля или неверные данные останавливают инструмент с кодом 3 и конкретным сообщением до создания пакета. Число результатов не выводится из `imageCount`; параметры команды сохраняются без преобразований.
- Создаётся новый пакет `plan/batches/Mxx-attempt-NN` (`shot_workflow init`, `retry_of` указывает на исходный пакет) и неизменяемая попытка `request/` через общий локальный механизм подготовки с теми же входами, промптом, моделью и параметрами. Этап пакета `request_choice`. Перед этим запрос сверяется с блоком `generation` в `plan/project.json`: провайдер сохранённого запроса, отличающийся от выбранного `generation.<kind>.provider`, разрешение или пропорции останавливают повтор.
- Промпт и входные файлы копируются без изменения байтов. Сохранённые хеши проверяются до создания нового пакета; несовпадение останавливает повтор. Явные ссылки на общие изображения `root: "source"` читаются из `source` проекта. В новом `request.json` сохраняется явный провайдер источника без подстановки Kling. Общая подготовка не ограничивает команды, имена моделей и входные флаги возможностями Kling; если подключён адаптер провайдера, он дополнительно проверяет свои ограничения. Подготовка сама по себе не означает наличие отправки в этот сервис.
- Выводятся `request_sha256`, провайдер, модель, параметры, число входов, длина промпта и таблица стоимости. Для подключённого Kling используется `cost_check` (остаток запрашивается у аккаунта, `--no-account` отключает). Для провайдера без адаптера цена и баланс неизвестны; обращения к Kling и его тарифам не выполняются.
- В новом пакете записывается штатный `pending_decision` для `request_choice` с вариантами `send/park/revise`: продолжение выполняют кнопки приложения. Вопрос не означает согласия на отправку; инструмент сам ничего не отправляет.
- `--cli` подменяет исполняемый файл Kling, `--pricing` файл тарифов (тесты и прогоны без расхода: наблюдения не попадают в общий `pricing.json`). `--json` печатает одну строку JSON со сведениями пакета и стоимостью.

## Тесты

Подставной CLI без сети: отказ без обязательных данных и при расхождении провайдера с настройками, общая подготовка и повтор сохранённого запроса другого провайдера без вызова Kling, вопрос отправки для приложения без обращения к отправке, повтор из пакета, канонический снимок принятого комплекта, отказ при неверной форме промпта или отсутствии `outputs`, сохранение параметров, выбора модели и байтов входов, общие референсы source, проверка хешей и остановка при расхождении с настройками проекта.
