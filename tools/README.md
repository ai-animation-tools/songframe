# Карта инструментов

Инструменты лежат в комплексе SongFrame, а данные клипа в отдельной папке проекта. Каждый инструмент при запуске определяет проект в таком порядке: аргумент `--project <папка>` (можно ставить в любом месте команды), переменная окружения `SONGFRAME_PROJECT`, файл `current-project.json` в постоянном каталоге состояния приложения, который пишет приложение или [current_project](current_project/README.md), и наконец текущая папка, если в ней есть `plan/project.json`. В примерах ниже `--project` опущен: команды даны от корня комплекса для уже выбранного проекта. Все пути в выводе и аргументах вида `plan/...`, `assets/...` отсчитываются от папки проекта.

Перед выполнением выбрать нужную строку и прочитать README её папки. В README указаны назначение, условия, команды и результат; читать исходник ради выяснения параметров не требуется. Каждый инструмент находится в собственной папке с README; его тесты хранятся рядом со скриптом. Общие для инструментов корень проекта `ROOT`, корень комплекса `TOOLS_ROOT`, хеш файла и чтение JSON — в [tools/common.py](common.py). Импорты и поиск данных не зависят от текущей папки.

Проектное название и имя MP4 читать из `plan/project.json` проекта (образец в [шаблоне](../templates/project/plan/project.json)), имена и подписи референсов — из `references` в реестре сцен `plan/scenes.json`. Общие функции чтения и проверки описаны в [scene_registry](scene_registry/README.md#данные-проекта).

## Команды

Приложение запускает инструменты общим `PythonLauncher` со встроенным Python; инструкции подготовки — в [scripts/runtime](../scripts/runtime/README.md). Терминальные примеры ниже используют dev Python. Автоматическое распознавание вызывается напрямую без обязательного `unshare`, модель читается локально; `SONGFRAME_LOCAL_DIR` передаёт общий с приложением каталог состояния. Без него CLI использует постоянный userData, на Linux — `${XDG_CONFIG_HOME:-$HOME/.config}/songframe`. Пользователь запускает инструменты только кнопками приложения; отдельного режима командной строки у готового приложения нет. Разработчик при отладке вызывает их из checkout как `python3 -B tools/<имя>/<имя>.py --project <папка> …`.

## Тесты

Полная локальная проверка: `python3 -B tools/run_tests/run_tests.py`. Выборочная: добавить `--only` и имена наборов. Тесты Kling используют локальную подмену; платных генераций нет. Стиль кода проверяют `ruff check tools` и `ruff format --check tools` по настройкам `pyproject.toml` в корне; переформатирование существующего кода выполняется отдельным поручением.

Linux AppImage включает FFmpeg/ffprobe: общий launcher передаёт встроенные бинарники первыми в PATH. Веса faster-whisper устанавливаются отдельно по [инструкции](../README.md#модель-распознавания); окно разметки показывает рекомендацию по CPU/RAM/CUDA и позволяет выбрать свою папку. `transcribe_local` поддерживает автоматический выбор CUDA либо CPU и принудительный `--device cpu`. Рабочие представления не требуют Git; проверка индекса/истории требует внешний Git. Приложение передаёт встроенный официальный Kling CLI через `SONGFRAME_KLING_EXECUTABLE` и `SONGFRAME_KLING_SCRIPT`: его исполняет Electron без отдельного Node.js. В самостоятельных вызовах без этих переменных сохраняется внешний `kling` из PATH; явный `--cli` имеет приоритет. Локальной разметке Kling не нужен.
