# regenerate_shot

Повтор генерации плана по сохранённому запросу без нового согласования опор и промпта. Использовать по аргументу `regenerate=true` скилла `ai-clip-scene` или кнопкой «Перегенерировать» в приложении, когда опоры и промпт устраивают, а результат нет. Конкретное явное поручение пользователя `regenerate=true` разрешает одну новую попытку показанного сохранённого запроса по проверенной цене. Вызов скрипта агентом сам по себе такого разрешения не даёт; стоимость и баланс проверяются перед отправкой, следующие повторы согласуются отдельно.

## Контракт

```sh
python3 -B tools/regenerate_shot/regenerate_shot.py M32
python3 -B tools/regenerate_shot/regenerate_shot.py M32 --submit
python3 -B tools/regenerate_shot/regenerate_shot.py M32 --source asset --json
```

- Источник запроса (`--source auto` по умолчанию): сначала последний пакет плана в `plan/batches` или `plan/awaiting` с подготовленной попыткой (`request_dir/request.json`), затем снимок принятого комплекта `assets/shots/Mxx/generation-request.json`. Исходный снимок и принятые файлы не переписываются.
- Снимок принятого комплекта содержит `schema_version: 1`, `provider: "Kling"` (регистр имени несущественен), `command`, `model`, `parameters`, `outputs`, `inputs`, `prompt`, `prompt_sha256` и `path_base: "asset_directory"`. `kind` по умолчанию `video`; для изображения указывается `"image"`. `prompt` — строка с именем файла, `prompt_sha256` — его SHA-256 из 64 шестнадцатеричных символов. Входы — список файловых дескрипторов с `path`, сохранённым `sha256` и именованным `slot`; для них используется флаг `input`. Другие флаги (например, `image`) сохраняются явно без `slot`. Общие изображения задаются через `root: "source"`. Это контракт снимка, который записывает `accept_shot`.
- `request.json` подготовленной попытки читается в формате `kling_request prepare`: промпт — объект `{ "path": "prompt.txt", "sha256": "…" }`, каждый вход содержит явный `flag`. Модель, параметры и `outputs` берутся непосредственно из документа; `model_selection` сохраняется при наличии. `cli_argv` не исполняется. Форма промпта и входов определяется видом документа и не подменяется другой.
- Другой провайдер, отсутствующие обязательные поля или неверные данные останавливают инструмент с кодом 3 и конкретным сообщением до создания пакета. Число результатов не выводится из `imageCount`; параметры команды сохраняются без преобразований.
- Создаётся новый пакет `plan/batches/Mxx-attempt-NN` (`shot_workflow init`, `retry_of` указывает на исходный пакет) и попытка `request/` через `kling_request prepare` с теми же входами, промптом, моделью и параметрами. Этап пакета `request_choice`. Перед этим запрос сверяется с блоком `generation` в `plan/project.json`: другой провайдер, разрешение или пропорции останавливают повтор.
- Промпт и входные файлы копируются без изменения байтов. Сохранённые хеши проверяются до создания нового пакета; несовпадение останавливает повтор. Явные ссылки на общие изображения `root: "source"` читаются из `source` проекта. Новый запрос подготавливается штатным `kling_request`.
- Выводятся `request_sha256`, модель, параметры, число входов, длина промпта и таблица `cost_check` (остаток запрашивается у аккаунта, `--no-account` отключает).
- `--submit`: ровно одна отправка `kling_request submit --confirm`, запись расхода `cost_check learn`, этап `submitted`, одно ожидание `watch` (`--max-minutes`, по умолчанию 20) и этап `downloaded` при успехе. При вердикте `insufficient_balance` или `cost_or_balance_unknown` отправка не выполняется. Техническую сводку делает `contact_sheet --package` отдельно.
- `--cli` подменяет исполняемый файл Kling, `--pricing` файл тарифов (тесты и прогоны без расхода: наблюдения не попадают в общий `pricing.json`). `--json` печатает одну строку JSON со сведениями пакета, стоимостью и состоянием попытки.

## Тесты

Подставной CLI без сети: отказ без обязательных данных и для чужого провайдера, повтор из пакета с отправкой и получением, канонический снимок принятого комплекта, отказ при неверной форме промпта или отсутствии `outputs`, сохранение параметров, выбора модели и байтов входов, общие референсы source, проверка хешей и остановка при расхождении с настройками проекта.
