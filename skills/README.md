# Скиллы комплекса

Скиллы агента для производства клипа. Они лежат в комплексе, а работают с папкой текущего проекта, которую определяют так же, как инструменты: `--project`, переменная `SONGFRAME_PROJECT`, файл `current-project.json` в постоянном каталоге состояния приложения, затем текущая папка с `plan/project.json` (см. [current_project](../tools/current_project/README.md)).

| Скилл | Назначение | Состояние |
| --- | --- | --- |
| [ai-clip-audio](ai-clip-audio/SKILL.md) | Разметка трека по строкам текста песни: `align_lyrics` поверх локального распознавания, подтверждение границ в редакторе таймингов приложения | Готов |
| [ai-clip-scenario](ai-clip-scenario/SKILL.md) | Два прохода: кастинг `plan/cast.json` и трактовка `plan/treatment.json`, затем реестр сцен `plan/scenes.json` через `scene_scaffold`, проверка `lint_registry` и `continuity_brief` | Готов; `output=proposal` возвращает JSON для согласования в приложении |
| [ai-clip-scene](ai-clip-scene/SKILL.md) | Подготовка, согласование и приёмка плана или партии: независимые image backend Codex/Kling и video backend Kling; субагенты, согласования в приложении через `shot_workflow ask/wait/decide`, `regenerate=true`, `stage=`, `accept=`; `output=proposal` возвращает JSON одного этапа для приложения | Готов |

Источники навыков редактируются только в `skills/` комплекса. В checkout комплекса `.agents/skills` (Codex) и `.claude/skills` (Claude Code) используют ссылки на эти исходники.

При открытии управляемого проекта приложение устанавливает **реальные копии** `ai-clip-scenario/SKILL.md`, `ai-clip-scenario/agents/openai.yaml` и производственного `ai-clip-scene` с его `SKILL.md`, `agents/openai.yaml`, `references/*.md`, `workflow.md` и `evals.md` в `.agents/skills` и `.claude/skills` проекта. Относительные назначения и последние установленные SHA-256 хранятся в `.songframe/managed-skills.json`; неизменённые копии обновляются при следующем открытии. Одноимённые пользовательские навыки, изменённые файлы и неизвестные ссылки сохраняются; конфликт виден в статусе проекта и не мешает ручному просмотру. Заменяются только старые ссылки прямо на `skills/ai-clip-scenario` или `skills/ai-clip-scene` текущего комплекса, без поиска перемещённых checkout.

Команды установленных навыков используют проектный `.songframe/run-tool`. Режим `output=proposal` возвращает JSON без записи: приложение передаёт инструкции через stdin существующему CLI агента с доступом только для чтения и показывает предложение для применения. Наличие копий, обнаружение навыка самим CLI и выполнение задания — отдельные проверки; подключение файлов само по себе не подтверждает discovery или вход в аккаунт.

Производственный `output=proposal` возвращает описание с промптами опор, видеопромпт либо черновик запроса; после принятия описания проектный image backend выбирает отдельное задание Codex с `image_gen` либо frozen Kling image-запрос с отдельным SHA/ценой и отправкой. Выбор полученного original создаёт непринятого кандидата; опоры утверждаются отдельно. Вопросы с `executor=app` и применение предложений ведёт приложение; читающий агент не пишет пакет и не отправляет Kling. Ручной режим сохраняет `ask --executor agent` и `wait`. Глобальные текстовый агент и профиль Codex `imageAgent` независимы от проектных `generation.video`/`generation.image`; Kling image и video используют отдельные адаптеры в одном workflow.
