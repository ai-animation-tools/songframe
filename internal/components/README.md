# Закреплённые компоненты

[manifest.json](manifest.json) — встроенный реестр точных артефактов производственного CPU-пути. [manifest.go](manifest.go) читает отдельный снимок и проверяет ссылки, пути, SHA, обязательные части ML-контракта. Чтение не обращается к сети, PATH, профилю или нативной библиотеке. [manager.go](manager.go) реализует обнаружение, проверку и состояние по функциям; [ComponentsService](../app/components.go) предоставляет Wails-границу. [install.go](install.go) ведёт загрузку/офлайн-импорт, прогресс и публикацию; пользовательский экран «Компоненты» использует тот же сервис.

## Состав и происхождение

| Компонент | Закрепление | Фактическая проверка |
| --- | --- | --- |
| FFmpeg/ffprobe | BtbN `n8.1.3-9-g29e619e767`, `autobuild-2026-09-30-13-08`, GPL Linux/Windows amd64 | SHA архивов совпали с исходным media-lock и GitHub assets; состав, SHA entrypoints/LICENSE, ELF/PE imports; Linux recipes |
| ORT CPU | Microsoft `1.31.0`, standalone C runtime Linux/Windows amd64 | Загруженные архивы и SHA GitHub assets, обязательные файлы, symlinks, export `OrtGetApiBase`, ELF/PE dependencies |
| Voc FT | `UVR-MDX-NET-Voc_FT.onnx` | Размер/SHA принятого lock, реальные protobuf-метаданные, IR 6 / opset 13 |
| Русский CTC + vocab | HF revision `df5ba1d9e0f9a34c44eec437b441f4ae43c842eb`, quantized ONNX | SHA обоих файлов, один input_values → logits с 39 классами, IR 7 / opset 14; 39 непрерывных vocab ID |

FFmpeg берётся из закреплённых пакетов, без самостоятельной урезанной сборки. Потребители FFmpeg — инструменты `build_review`, `build_animatic`, `accept_shot`, `apply_montage`, `derive_shot`, `asset_package`, `video_review`, `contact_sheet`, `verify_asset_replay`, `cut_speech`, аудиодекодирование разметки и чтение длительности исходников; поля `consumers` указывают владельцев.

`capabilities` связывают операции с компонентами, FFmpeg features и probe. Входные видео декодируются автоматически: список проверенных H.264/VP8/VP9 не является обещанием поддержать произвольный внешний codec. JPEG/WebP обрабатываются в Go и требованием к FFmpeg не являются. WebM здесь читается; новый WebM-экспорт не добавлен. `libmp3lame`, `anullsrc`, `apad` нужны проверкам разработки. Whisper, Qwen, CTranslate2 и CUDA в выбранный набор не входят; декодирование PCM для принятого CTC сохранено.

`recipe` закрепляет pipeline, параметры MDX и CTC margin/adaptive, на которых проверена автоматическая разметка. Восемь потоков (`regression_threads_per_job`) — параметр регрессионной проверки, а не обязательный default для любого компьютера. Ручные секунды, VAD trimming и Whisper не являются входом. Произвольный `transcribe_local --filter` и вручную изменённые старые filter manifests не создают обещания конечного whitelist для всех внешних CLI-сценариев.

## Значение полей

- `bytes` — точный объём загружаемого файла; `unpacked_bytes` — сумма обычных файлов всего архива, без округления файловой системы. Для одиночной модели это размер файла.
- `install_bytes` — сумма обязательных обычных `files`. Для FFmpeg это нижняя граница: дополнительно сохраняются `doc/**`; установщик проверяет свободное место с запасом на полный распакованный объём и файл загрузки. В Windows ORT полный ZIP включает большой PDB, его устанавливать не требуется.
- `root` — каталог верхнего уровня архива; `files.path` и `entrypoints` относительны ему. Для отдельного файла `root` пуст. `entrypoints` задаёт роли явно: `ffmpeg`, `ffprobe`, `ort-library`, `model`, `vocab`.
- `files` — обязательный проверяемый состав с SHA/размером. Для symlink задаётся относительный `target`, без SHA содержимого; цель также обязана входить в `files`. `preserve` сохраняет лицензионные материалы; ffplay, development headers и PDB не являются обязательным runtime.
- `verified` относится к проверке байтов/метаданных. `native_status`, платформенная матрица и `license.status` отдельно показывают остаток проверки; это не состояние установки `ready`.
- `abi.required_api=27` — API закреплённого Go binding; `header_api=31` — максимум header ORT 1.31.0. Реально выбранный API определяется при загрузке. Binding может откатиться до 17; для принятой конфигурации проверяется 27.

Linux FFmpeg требует glibc 2.28. Linux ORT требует glibc 2.28, GLIBCXX 3.4.22 и CXXABI 1.3.11. Windows ORT импортирует VC++ 14 runtime и UCRT, которых нет в архиве: DLL Visual C++ ставит установщик SongFrame рядом с `songframe.exe` ([рецепт Windows](../../packaging/windows/README.md)), UCRT входит в Windows 10/11. Нативный Windows-прогон не выполнялся. macOS и остальные OS/arch без подтверждённого пакета не получают подставные URL или готовность.

Binding `SetSharedLibraryPath` настраивается до первого успешного глобального Init. Ошибка Init допускает повтор; после успеха путь не меняется. Shutdown требует закрытых sessions и запрещает следующий Init. Поэтому первая установка может заработать в том же сеансе, а смена уже загруженного runtime требует перезапуска. На Linux проверены именно скачанный standalone runtime, реальные sessions обеих моделей, короткий CPU inference, отмена и повтор. CreateSession binding не принимает context: отмена во время загрузки обрабатывается сразу после возврата native вызова и закрывает session. Сам Run(ctx) прерывается через terminate. Проверка раннего установленного пакета и Windows остаётся впереди.

## Проверки

```sh
wails3 task check:components
sh scripts/check-media-capabilities.sh /путь/к/папке/bin
```

Первой команде не нужны FFmpeg, модели или соседние репозитории. Вторая — проверка разработчика на Go-инструменте `scripts/packtool` (нужен Go): принимает один каталог с исполняемыми `ffmpeg` и `ffprobe`, генерирует короткие синтетические входы в `/tmp`, ограничивает процессы по времени и удаляет временную папку. Она не устанавливает компоненты и не проверяет системный WebView. Подробности фиксированных входов — [testdata/components](../../testdata/components/README.md).

При наличии распакованных пакетов и моделей можно отдельно проверить обязательные файлы, без исполнения DLL/EXE:

```sh
SONGFRAME_COMPONENT_ROOTS='{"ort-cpu-linux-amd64":"/путь/onnxruntime-linux-x64-1.31.0"}' \
  go test ./internal/components -run TestManifestArtifactFiles -count=1 -v
```

Карта может включать любой непустой набор ID из manifest; для модели значением служит папка, содержащая файл с закреплённым именем. Неизвестный ID, несовпадающий hash/размер или неверный symlink дают ошибку. Без переменной этот добровольный тест пропускается; обычные проверки остаются автономными.

## Лицензии и границы готовности

Ссылки на первичные источники находятся в `license.sources`/`evidence`. Для FFmpeg сохраняются GPL, документация и configure; полнота транзитивных notices проверяется при упаковке. Для ORT сохраняются MIT LICENSE и ThirdPartyNotices из каждого архива. Для CTC/vocab Apache-2.0 заявлена закреплённой карточкой HF; отдельного LICENSE там нет. Для Voc FT MIT заявлена проектом UVR в разделе о моделях, отдельной лицензии внутри ONNX/рядом с asset не найдено. При комплектовании сохраняются исходные тексты, карточки и атрибуция; лицензия приложения не подменяет эти условия.

Реестр не является разрешением автоматически отправлять платные запросы или запускать производство.


## Обнаружение и состояние

`NewManager` получает каталог состояния приложения. Настройки путей находятся в `components.json`; конструктор читает их без запуска программ и загрузки ORT. Ошибка JSON/чтения возвращается в `Snapshot.Problem`, сохраняя доступность project-view/timing-view. `State` делает только лёгкие stat/LookPath; модельные веса при просмотре не хешируются.

`Configure` атомарно сохраняет явный выбор. Подтверждения SHA/native/capabilities неизменившихся файлов сохраняются по fingerprint (фактические пути, размер, mtime, mode); новый/изменённый файл снимает `ready` только своей зависимости. Изменение папки загрузок не перечитывает внешние модели и не создаёт их ONNX sessions заново. Поля `Selection`: `ffmpegDirectory` — папка с двумя программами; `ortDirectory` — общий корень runtime, `ortLibraryFile` — выбранная библиотека с приоритетом над ним; `vocalsFile` — готовый файл Voc FT; `ctcDirectory` — общий корень alignment.onnx/vocab.json, `ctcModelFile`/`ctcVocabFile` — независимые overrides готовых файлов. Выбор одной модели или словаря не перенастраивает соседнюю карточку. Пустое поле возвращает автоматический поиск. Пути приводятся к абсолютным при выборе; исчезнувший явно выбранный путь объясняется без тихого перехода на другой источник. Внешние установки не копируются, не удаляются и не изменяют PATH ОС. У явно выбранного ORT требуются открываемый обычный файл библиотеки и успешный native probe, но не LICENSE, ThirdPartyNotices или symlink aliases нашего дистрибутива. Семантическая версия читается из runtime. Зависимости подтверждаются нативным загрузчиком; C API 27 и CPU provider остаются обязательными. Управляемая установка и staging по-прежнему проверяют полный закреплённый состав, SHA, notices и aliases. Модели/словарь сохраняют SHA принятого lock при любом источнике. При отсутствующем рабочем файле диагностика сначала называет entrypoint, затем остальные файлы в стабильном порядке; неверная папка ORT объясняется отсутствием библиотеки ONNX Runtime.

Управляемый состав ожидается в `<managedDirectory>/<artifact.id>/<artifact.version>/` с удалённым корнем архива; по умолчанию managedDirectory — `<каталог состояния>/components`. Для FFmpeg после неполного/непригодного управляемого пакета допускается PATH. Если managed подходит лишь для части функций, `Check` сравнивает его с PATH для запрошенных функций. Следующий набор функций или исчезнувший/изменённый PATH пересматривает прежний выбор. Явная внешняя пара не переключается. Снимок содержит фактически выбранные пути; будущая производственная задача должна закреплять их для своего запуска.

`Check(ctx, operationIDs, force)` принимает только известные ID. Помимо manifest есть project-view/timing-view без компонентов, prepare-vocals и ctc-existing-vocals: готовый вокальный WAV не требует установленного Voc FT. Ошибка кодировщика не блокирует PCM, ошибка одной ONNX не делает неисправными ORT и вторую модель. Модель с подтверждённым SHA, которая ещё не дошла до native session из-за отсутствующего или непригодного ORT, получает `blocked` с объяснением нужной зависимости. Это не native готовность и не инструкция нажать проверку; после появления ORT следующая обычная проверка использует сохранённый SHA. Собственные ошибки SHA или native-графа не заменяются ожиданием runtime. Статусы: missing/unchecked/ready/blocked/incompatible/error/cancelled/restart_required; `checking` относится к выполняющейся проверке и очищается до её ответа. `Cancel` отменяет проверку, не затрагивая просмотр проекта. Загрузка пакетов автоматически не начинается.

Обычный Check использует подтверждения SHA и native probes текущего сеанса, пока пути/размеры/mtime не изменились. Force заново проверяет файлы и повторяет functional probes; неудача не перекрывается старым ready. После перезапуска сервис формирует подтверждения фоновой проверкой найденных компонентов; `State` самостоятельно работу не запускает. Смена файлов с сохранением размера/mtime выявляется Force и обработкой реальных ошибок открытия; кэш не заменяет проверку ошибок производства. Одновременные проверки и Configure во время проверки отклоняются, Cancel остаётся доступен. В приложении сервис запускает проверку один раз после старта и после успешного изменения путей или установки; просмотр страницы только читает снимок, пользовательская кнопка проверки не требуется.

Production [media.go](media.go) использует Go stdlib и встроенные [синтетические входы](fixtures/README.md), без shell и зависимости от cwd. Каждая команда ограничена 15 секундами, stdout 1 MiB/stderr 16 KiB; temporary files удаляются. Проверка подтверждает формат/функции на коротком видео 192×108, не производительность 1080p. Системные кодеки WebView этим не проверяются.

Дополнительные добровольные integration-проверки (пути задаёт разработчик):

```sh
SONGFRAME_TEST_MEDIA_BIN=/путь/к/bin \
SONGFRAME_ORT_LIBRARY=/путь/onnxruntime/lib/libonnxruntime.so.1.31.0 \
SONGFRAME_ORT_MODEL_DIR=/путь/к/моделям \
  go test ./internal/components -run 'TestManagerIntegration|TestProbeFFmpegNative|TestORTIntegration' -count=1 -v
```

Менеджерная проверка создаёт только временный профиль. ORT lifecycle-сценарии выполняются в отдельных процессах, потому что successful Init глобален. Нужен C-компилятор/CGO; сборка Windows с выключенным CGO не является поддержанным путём. Сборка Windows с CGO (кросс-компиляция с MinGW ABI) описана в [рецепте Windows](../../packaging/windows/README.md); нативный прогон в Windows выполняется отдельно.


## Установка и сохранность

`Catalog` возвращает только закреплённые пакеты текущей OS/arch и общие модели, с объёмом загрузки, установленного набора и верхней оценкой временного места. Байты в каталоге относятся к конкретному артефакту с закреплённым SHA, а не выдаются за текущую live-метадату сервера. Просмотр страницы не делает HEAD/GET. После явного начала загрузки известный HTTP Content-Length должен совпасть с ожидаемыми bytes ответа (для Range — оставшаяся часть); при отсутствии заголовка действуют ограничение фактического объёма и финальный SHA. Несовпадение известной длины отклоняется до изменения полезного кэша. `Install` сериализован с `Check`/`Configure`; `Installation` и `CancelInstall` доступны независимо от длинного Wails-вызова. `InstallRequest.localFiles` сопоставляет ID компонента с выбранным архивом/моделью: внешний файл читается без перемещения или удаления. Для онлайн-установки найденный FFmpeg предварительно проходит functional probe, внешний ORT — открытие библиотеки и native loader/API/CPU probe; модели и управляемый состав — SHA. Пригодная установка повторно не загружается. `Connect` заменяет выбранный путь новым готовым файлом или распознанным архивом. `Download` получает закреплённый пакет и переключает выбранный компонент на managed после успешной публикации; отдельного пользовательского «забывания пути» не требуется.

Загрузка находится в `<managed>/.downloads`, докачка использует сильный ETag, If-Range и подтверждённый Content-Range. Если продолжение не подтверждено, выполняется полный GET; SHA и точный размер проверяются в любом случае. Отмена и сетевой обрыв сохраняют полезную часть, несовпавший SHA удаляет только загрузку. Отмена хеширования не удаляет полную копию. До загрузки проверяются доступное место и возможность записи; реальные ошибки записи/Sync также обрабатываются без изменения действующей установки.

[extract.go](extract.go) распаковывает ZIP/tar.gz/tar.xz только в staging: устанавливает `files` и `preserve`, отвергает traversal/абсолютные пути, дубликаты и неожиданные типы, создаёт разрешённые manifest symlinks после обычных файлов. ZIP/gzip/tar принадлежат Go stdlib, XZ распаковывается pure-Go [github.com/ulikunitz/xz v0.5.17](https://pkg.go.dev/github.com/ulikunitz/xz@v0.5.17), без внешнего `xz` или shell. Модели сохраняют прежние закреплённые байты.

После проверки обязательных файлов staging становится отдельным неизменяемым поколением `<managed>/<artifact.id>/<version>-<suffix>`. Маленький `active.json` атомарно переключает обнаружение на это поколение; старая библиотека/модель никогда не перезаписывается. После rename metadata всех опубликованных файлов сравниваются с проверенным staging без учёта нового префикса пути: несовпадение отклоняет подключение. При совпадении подтверждение SHA переносится на новый fingerprint, чтобы последующая фоновая проверка не перечитывала большие веса. Native готовность это не подтверждает. До публикации active любая ошибка или закрытие приложения оставляет прежний pointer рабочим; незавершённый staging или неиспользуемое поколение не участвует в обнаружении. Без действительного `active.json` компонент считается не установленным и ставится заново. Старые поколения автоматически не удаляются: для установки это не нужно, а удаление не должно затрагивать уже загруженный ORT.

`component-installation.json` в каталоге состояния содержит последние 100 записей журнала и фазу. После перезапуска незавершённая фаза показана как `cancelled`, сеть самостоятельно не запускается. `installed` означает проверенные опубликованные файлы; `ready` конкретной функции появляется отдельно после `Check` и native probe. Установка не запускает производство и не переносит согласия платных запросов.

Автономные `TestInstall*`/`TestExtract*` покрывают сеть httptest, обрыв, Range/ETag/fallback, отмену/повтор, перезапуск, неверный SHA, недостаток места/запись/публикацию, сохранность прежнего active, офлайн-импорт, Unicode, распаковку всех форматов и ссылки. Добровольный `TestInstallNativeOffline` принимает `SONGFRAME_TEST_OFFLINE_ORT` и `SONGFRAME_TEST_OFFLINE_VOCAB`, устанавливает реальные read-only источники во временный профиль и проверяет состав после нового Manager без inference/сети.


Для регрессии внешнего ORT без структуры дистрибутива можно явно передать `SONGFRAME_TEST_EXTERNAL_ORT_LIBRARY` и запустить `go test ./internal/components -run '^TestExternalORTNativeWithoutDistributionFiles$' -count=1 -v`. Тест копирует только библиотеку во временную внешнюю раскладку и проверяет Manager/loader/API в дочернем процессе. Источник не меняется, docs/aliases не копируются; новые пользовательские пути не сохраняются. Mock-регрессии отдельно покрывают неверную папку, стабильность причин/путей, native отказ/restart_required при online reuse, capabilities внешнего FFmpeg и неизменную целостность managed ORT.


## Один выбор на компьютере

`Manager.Connect(ctx, componentID, path)` распознаёт готовый файл или закреплённый ZIP/tar.gz/tar.xz по сигнатуре, без пользовательского выбора режима. FFmpeg/ffprobe подключаются как пара из папки выбранной программы; ORT — по фактическому выбранному library file; готовые ONNX/vocab подключаются по месту без копирования сотен MiB. Domain API также принимает папку пары/моделей и нормализует ORT root/lib. Нативный Linux/Windows picker в приложении выбирает файл; смешанный выбор файла и папки не обещается там, где Wails его не поддерживает.

Архив проходит обычную проверку SHA/staging/публикацию, затем только успешно установленная карточка переключается на managed. `Manager.Download` аналогично заменяет неисправный внешний путь после успешной загрузки; пригодный уже управляемый payload сначала проверяется и повторно не скачивается. Внутреннее намерение managed не входит в `InstallRequest` transport DTO. При освобождении общего CTC-корня effective path соседа сохраняется в его независимом override; выбранный компонент получает настоящее managed обнаружение и сохраняет его проверки целостности. Ошибка архива не меняет прежнее подключение и не удаляет внешний файл. Повторный выбор корректного архива уже установленного runtime подтверждает SHA источника и сохраняет существующее поколение: новая native identity и лишний перезапуск не создаются. Каждый успешный компонент batch переключается отдельно; ошибка следующего не откатывает уже успешно установленное.

[component_connect.go](../app/component_connect.go) связывает `Connect`/`Download` с существующим владельцем автоматических проверок. После выбора/публикации renderer получает актуальную готовность через polling, не вызывает `Check` и не предлагает второй технический режим. `Connect` не копирует готовый raw model/vocab только ради подключения; несовпадающий размер сразу исключает неверный файл, а совпавший размер всегда требует SHA принятого lock.
