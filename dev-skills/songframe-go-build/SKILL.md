# Сборка SongFrame Go

Работай в корне `songframe-go/`, соседнем с `songframe/` в рабочей области. Перед сборкой прочитай его `AGENTS.md` и `packaging/README.md`: актуальные зависимости сборщика, состав пакета и детали smoke принадлежат этому руководству. Если checkout Go-приложения отсутствует, сообщи об этом; Electron-сборка не заменяет запрошенную Go-поставку.

Скилл собирает Linux AppImage x86_64 или Windows amd64 NSIS по явно выбранной платформе. Целевая Linux-поставка также включает deb-пакет; пока его рецепта нет, сообщи об этом и не подменяй deb AppImage. Для Windows прочитай [локальный Windows-рецепт](../../packaging/windows/README.md), выполни `wails3 task package:windows` и проверь `.sha256`/`.build.json` готового setup. CGO=1, GUI subsystem, встроенные ресурсы и payload проверяются автоматически; это не native Windows-тест. Если пользователь проверяет VM сам, не запускай её. При поручении положить комплект в общую папку VirtualBox найди настроенный путь через VBoxManage, положи только setup и краткую инструкцию и выполни явно запрошенную очистку старых тестовых файлов. Windows prerequisites и ручная проверка описаны в указанном рецепте; команды Linux ниже при Windows-сборке не запускать. Linux-проверки готовность Windows не подтверждают. Сборка не разрешает commit, push, изменение версии, создание тегов или публикацию.

Рецепт адаптирован по [forktopus-release](https://github.com/forktopus/forktopus/blob/main/.agents/skills/forktopus-release/SKILL.md) и [AppArmor bootstrap Forktopus](https://github.com/forktopus/forktopus/blob/main/scripts/appimage/main_linux.go), с [обёрткой AppRun](https://github.com/forktopus/forktopus/blob/main/build/linux/appimage/AppRun). Здесь используются местные задачи Wails и локальные артефакты: release/bump и получение файлов исключительно из CI к этой сборке не относятся. Атрибуция MIT исходного bootstrap должна сохраняться в исходниках и составе лицензий поставки.

## Объём поручения

Изменение рецепта не разрешает пересборку или запуск артефакта. Не добавлять дорогую сборку, Docker или полную матрицу по собственной инициативе; проверять изменённую область адресно. SHA/receipt использовать внутри инструментов, пользователю без запроса их не перечислять и в общую папку не копировать.

## Сборка

- Версию ранней поставки прочитай из `packaging/VERSION`; без поручения не увеличивай её. Учитывай незакоммиченные изменения и не выдавай их пакет за чистый снимок HEAD.
- Выполни из корня `songframe-go/`:

  ```sh
  wails3 task package:linux
  ```

- Готовые AppImage, метаданные `*.build.json` и контрольные суммы `*.sha256` лежат в `build/release/`. Используй фактически созданное имя файла; не выводи его из имени Electron-приложения. Сверь метаданные с текущей версией, исходниками и файлом, а SHA-256 — с контрольной суммой.
- Не копируй AppImage за пределы штатного `build/release/` без поручения. Разовые запросы, отчёты и тестовые профили создавай в `/tmp`, вне Git; прежние результаты не перезаписывай.

Минимальная Linux-система — Ubuntu 24.04 / glibc 2.39, архитектура x86_64. В AppImage включены GTK4 и WebKit6; FFmpeg/ffprobe, ORT и модели устанавливаются отдельно через компоненты приложения. Модели, runtime компонентов, Python, Node и Git не должны случайно попасть внутрь минимальной поставки. Требования сборщика и зависимости пользователя различаются: Node может требоваться для сборки frontend, но не для запуска готового AppImage.

## Обычная локальная проверка

Сначала запускай конечный AppImage на хосте с отдельным новым профилем:

```sh
wails3 task smoke:host APPIMAGE=/absolute/file.AppImage OUTPUT=/tmp/new-host-dir
```

Для обычной локальной сборки это первичная проверка. Она запускает сам AppImage через пользовательский systemd manager, без extract-and-run и без разрешающего AppArmor-профиля процесса агента. Успех из shell агента не подтверждает запуск двойным кликом. Проверка prerequisites обязана использовать реальный bwrap: Go clone может дать ложный успех записи uid_map. Полную контейнерную матрицу не запускай автоматически; выбирай проверки по изменению и поручению. Если нужно проверить переносимость и отсутствие скрытых системных библиотек, используй дополнительный Docker smoke. Затруднения тестового Docker не подменяют результат запуска на целевой машине.

## Дополнительная проверка минимального AppImage

Штатная проверка конечного файла в Docker на новом профиле:

```sh
wails3 task smoke:appimage APPIMAGE=/absolute/file.AppImage OUTPUT=/tmp/new-dir
```

Подставь абсолютный путь к собранному AppImage и новую, ещё не занятую папку отчётов. Проверка должна подтвердить запуск интерфейса и передачу управления frontend в чистом окружении без установленных Python, Node, Git, FFmpeg/ffprobe и ORT, с пустым профилем компонентов. Успешная сборка сама по себе эту проверку не заменяет. Если Docker или другой необходимый инструмент недоступен, сообщи конкретную невыполненную проверку; запуск на машине разработчика не доказывает чистоту зависимостей.

Песочница WebKit должна оставаться включённой. Не устанавливай `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS`, не отключай системный AppArmor и не меняй системный sysctl ради успешного smoke. Container security options штатного сценария разрешают user namespaces внутри тестового контейнера; это не desktop AppArmor gate. На Ubuntu ограничение user namespaces обрабатывается отдельным bootstrap до GTK/WebKit: профиль разрешает namespaces для конкретного исходного файла AppImage, применяется после повторного exec. При необходимости пользователь может явно выполнить `./file.AppImage --setup-apparmor`; это отдельная настройка с правами администратора, её не запускают ради проверки упаковки. Отмена настройки должна завершать запуск понятной ошибкой, а не обходить sandbox.

## Отдельная CPU-проверка компонентов

Выполняй её, когда запрошена проверка установки и inference; GUI smoke проверяет другую границу. Используй внешние, предусмотренные manifest файлы компонентов, отдельный новый профиль; синтетический сигнал создаётся встроенной проверкой, настоящий проект не нужен. Точный формат запроса и артефакты компонентов сверяй с `packaging/README.md`.

Запрос JSON содержит абсолютный путь нового профиля и внешние файлы. Для `ffmpeg` можно передать готовую программу с соседним `ffprobe`, чтобы повторно не распаковывать большой архив; ORT/CTC/vocab устанавливаются в новый профиль и проверяются реально.


```json
{
  "profileDirectory": "/tmp/new-component-profile",
  "localFiles": {
    "ffmpeg": "/absolute/ffmpeg-archive.tar.xz",
    "ort-cpu": "/absolute/ort-archive.tgz",
    "ctc-ru": "/absolute/model.onnx",
    "ctc-vocab": "/absolute/vocab.json"
  }
}
```

Запуск готовой поставки:

```sh
./file.AppImage --appimage-extract-and-run \
  --component-smoke-input /absolute/request.json \
  --component-smoke-report /absolute/result.json \
  --smoke-timeout 10m
```

Прочитай JSON-отчёт и проверь фактическую установку, probes и CPU inference; код завершения без отчёта не доказывает выполнение всего сценария. Компонентная команда и `--help` завершаются без создания WebKit и обходят подготовку user namespaces. Обычный GUI `--smoke` требует действующей песочницы и не должен попадать в этот обход. Не используй рабочий профиль пользователя или исходные клипы для smoke.

В ответе сообщи путь готового артефакта, версию, результат фактически выполненных проверок и существенные ограничения. Служебные SHA/receipt пользователю без запроса не перечислять. Укажи существенные непроверенные ограничения; Linux-результат не переносится на Windows или более старую glibc.

Linux-рецепт обязательно вызывает `linux_runtime_policy.py prune` после Wails generator, а перед упаковкой — `check`. GTK3/WebKit4.x и ссылки на них в ELF делают финализацию ошибочной; вложенные `libgst*-1.0` удаляются, GStreamer берётся из системы вместе с плагинами. Медиа WebView в готовом AppImage проверять `--native-check-dir` (12 наблюдений): GUI smoke `<audio>` не создаёт. Защиту проверять малым синтетическим набором из packaging/README; не пересобирать AppImage ради одной правки правила без поручения пользователя.
