# build_animatic

Детерминированно собирает единственный полный аниматик. Использовать по поручению на полную сборку; для локального стыка применять [build_review](../build_review/README.md).

```sh
python3 -B tools/build_animatic/build_animatic.py --plan-only
python3 -B tools/build_animatic/build_animatic.py
```

Входы: `plan/scenes.json`, принятые `accepted_edit.video` в assets, карточки `plan/animatic/cards/Mxx.png` и `source/track.mp3`. При устаревших карточках сначала выполнить [update_scene_views](../update_scene_views/README.md). `--plan-only` только проверяет входы. MP4 сборки в Git проекта не хранится (правило `.gitignore` шаблона проекта). Обычный запуск заменяет проверенную сборку в `plan/animatic/latest` и обновляет текстовые представления; кэш — `plan/animatic/.cache`.

Конец реестра сверяется с длительностью декодированного трека, как в разметке. Начальная метка MP3 `start_time` не уменьшает длину песни; задержка кодека и контейнерные метаданные не должны вызывать ложный отказ сборки.

Входной трек может быть моно или иметь другую частоту дискретизации. Выходной MP4 всегда содержит стерео AAC 44,1 кГц; исходный MP3 не изменяется.

Название и имя выходного MP4 — из [plan/project.json](../../templates/project/plan/project.json); метаданные MP4 и README берут значения оттуда же. Квитанция карточек содержит `project_inputs: {name}`, манифест сборки — `project_inputs: {name, animatic_video}`. Только эти поля проекта влияют на соответствующий результат: настройки генерации и форматирование JSON не требуют обновления. При смене имени файла обновить внешние ссылки на скачивание; после успешной сборки прежний MP4, указанный в манифесте, удаляется из latest.

Три вида входов (`media`): `video` — принятый клип; `card` — текстовая карточка с референсами; `keyframes` — карточка из принятых опор пакета плана. Для `keyframes` квитанция карточек содержит `last` с `plan/animatic/cards/Mxx.last.png`, и фрагмент собирается как удержание первой опоры, растворение в последнюю и удержание последней (40 / 20 / 40 % окна). Хеши обеих карточек входят в `source_hashes` манифеста; отчёт содержит счётчики `video`, `cards`, `keyframes`.

Свежесть в приложении проверяется по существующим `source_hashes` манифеста: байты выбранных монтажных клипов, первой/последней карточки и песни; поля проекта сравниваются по `project_inputs`. `source_hashes` содержит только медиафайлы, поля `project.json` в нём не хранятся. Снимок `project_inputs` обязателен: отсутствие или повреждение требует обновления результата. Для производных карточек сборщик дописывает туда только использованные исходные опоры или референсы (`shots[].card_sources`), а `shots[].keyframes` сохраняет выбранные ID, время и пути опор из квитанции карточек. Появление принятого монтажа вместо карточки и смена выбранных утверждённых опор тоже требуют пересборки; новые непринятые кандидаты и альтернативы при уже выбранном видео свежесть не меняют.

Хеши больших файлов в приложении кешируются по `dev/ino/size/mtime/ctime`: повторный опрос не перечитывает MP4, обычная замена файла или изменение байтов снимает кеш. Сборки сверяются по `project_inputs`, `source_hashes`, полям клипов и квитанции карточек. Если сведений не хватает, приложение сообщает о необходимости пересборки. Для устаревшей сборки `approval.current=false`; прежний `approved_animatic` остаётся записанным до следующего решения пользователя.

Плеер с полосой глав, карточками сцен и переходом по `#Mxx` открывает приложение комплекса: оно читает `latest/manifest.json`. Готовая сборка содержит только MP4, `manifest.json` и `README.md` со ссылками на видео и манифест. После успешной полной сборки прежняя HTML-страница удаляется; проверка `--plan-only` и ошибка сборки сохраняют прежний latest.

Принятый монтаж не подменяется оригиналом и повторно не обрезается, нумерованные версии не создаются ([правила аниматика](../../templates/project/plan/animatic/README.md)). При сравнении пересборки с сохранённым результатом применять [допуск различий только в тексте карточек](../../templates/project/plan/animatic/README.md#детерминированность-и-замена-результата). Проверки — в [тестах](#тесты).

## Тесты

Выбор принятых клипов/карточек, растворение между опорами, состав файлов готовой сборки и совпадение видео при холодном и тёплом кэше.

```sh
python3 -B tools/build_animatic/test_build_animatic.py
python3 -B tools/run_tests/run_tests.py --only test_build_animatic
```

Тесты находятся рядом со скриптом; рабочие сцены не изменяют, временные результаты создают вне проекта. Для полного набора — [run_tests](../run_tests/README.md).
