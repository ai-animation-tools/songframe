# check_workspace

Проверяет, что после приёмки сцен и обновления представлений рабочее дерево согласовано: у принятых планов не осталось рабочих пакетов, пакетов очереди и карточек, у незавершённых планов карточки есть, в `plan/batches` нет пустых и бесхозных папок. Готовые пакеты для монтажёра и собранные видеопробы сохраняются как результаты производства. Использовать после приёмки, перед коммитом и из приложения комплекса. Файлы не изменяет.

```sh
python3 -B tools/check_workspace/check_workspace.py
python3 -B tools/check_workspace/check_workspace.py --json
```

## Контракт

- Порядок в папке проверяется по наличию комплекта `assets/shots/Mxx/manifest.json`: такой план не должен иметь карточки и остатков приёмки, даже если его постановка изменилась. В выводе `accepted` перечисляет планы, принятые по текущей постановке, `stale` — планы с комплектом, постановка которых (или источника `derived_from`) изменилась после приёмки ([правило](../scene_registry/README.md#принятие-планов)); текст сообщает о них отдельной строкой «Постановка изменена после приёмки, нужно новое производство: …». Изменённая постановка — состояние производства, а не несоответствие: код возврата от неё не меняется. Владелец папки в `plan/batches` определяется по полю `shot` в `workflow.json`, `request.json` или `request/request.json`, иначе по коду `Mxx` в начале имени папки.
- Готовый результат [export_edit_bundle](../export_edit_bundle/README.md) распознаётся по структуре `bundle.json` (проект, песня, список планов со статусом, длительностью в кадрах и путём видео/карточки), а также по непустым `shots.csv`, `lyrics.csv`, `timeline.edl`, `timeline.fcpxml` и `README.md`. Поддерживаются пакеты с копиями медиа и со ссылками на проект; название папки произвольно. Снимок экспорта не обязан совпадать с текущим реестром после последующей приёмки.
- Готовая проба [build_review](../build_review/README.md) распознаётся по рецепту версии 1 со статусом `review_pending`, параметрами планов, звуком, числом кадров и хешем результата, а также по непустому MP4 рядом с одноимённым JSON. Старый абсолютный `output` в рецепте не мешает переносу проекта между компьютерами. Проверка распознаёт состав результата; техническую исправность медиа и совпадение хешей она не проверяет.
- Наличие `workflow.json`, `request.json` или `request/request.json` сохраняет проверку папки как рабочего пакета даже рядом с готовым результатом. Одного похожего имени, неполного экспорта или незавершённой пробы недостаточно для исключения папки из проверки.
- Новая попытка уже принятого плана («Подготовить повтор», доработка, запрос в очереди) — штатная работа и несоответствием не считается. Остаток приёмки без `--clean` — пакет на этапе `accepted` или пакет, чей запрос совпадает по SHA с запросом принятого комплекта.
- Виды несоответствий: `card_of_accepted`, `card_missing`, `card_unknown`, `receipt_stale`, `package_of_accepted`, `package_unowned`, `package_unknown`, `empty_folder`, `queue_of_accepted`. Любое несоответствие даёт код возврата 1; пустой список — 0.
- До создания `plan/scenes.json` проверка завершается с кодом 1 и сообщением «Сначала необходимо создать сценарий: отсутствует plan/scenes.json.». Файл не создаётся, проверка не считается проведённой. При `--json` ошибки чтения и проверки возвращаются в stdout как `{"error": "сообщение"}` с кодом 1; обычный режим пишет сообщение в stderr. Успешно проведённая проверка возвращает `{"accepted": [...], "stale": [...], "problems": [...]}`. Повреждённый `plan/production-status.json` или неверное поле `shots` — ошибка чтения.
- Исправления выполняют штатные инструменты: карточки и квитанцию — `update_scene_views`, пакеты принятого плана — `accept_shot --clean` при приёмке; бесхозные папки разбирает пользователь.

## Тесты

Чистое дерево без замечаний, план с изменённой постановкой в `stale` без несоответствия, несоответствия на временном проекте, определение владельца папки по JSON и по имени, CLI с реестром и без сценария в обычном и JSON-режиме. Настоящие экспорты с копиями и без них, неполный/повреждённый пакет под похожим именем, рабочие и бесхозные workflow рядом с экспортом, готовая и неполная проба после приёмки.

```sh
python3 -B tools/check_workspace/test_check_workspace.py
python3 -B tools/run_tests/run_tests.py --only test_check_workspace
```

Сохранённые ручные монтажи в `plan/montage` и пробы с `montage.json` удерживают необходимые рабочие пакеты; они не считаются лишними после приёмки сцен.
