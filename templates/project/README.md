# Клип «{{project_name}}»

Это карта навигации проекта: где лежит единственный редактируемый источник каждого вида сведений и какие правила хранения действуют. Клип ведётся в приложении SongFrame: исходники, тайминги, кастинг, сценарий, производство сцен, проверки и сборка выполняются кнопками его страниц, агента запускает приложение. Код инструментов, Python и клиенты провайдеров генерации находятся в приложении; в папке проекта лежат только данные клипа. Состав папки `plan` описан в [её карте](plan/README.md).

## С чего начать

| Что нужно | Где в приложении | Где в проекте |
| --- | --- | --- |
| Загрузить трек, текст, идею, обложку и референсы | «Исходники» | `source/manifest.json` · [референсы и их промпты](source/README.md) |
| Разметить песню | «Тайминги» | [plan/audio](plan/README.md) |
| Собрать кастинг и сценарий | «Кастинг» · «Сценарий» | `plan/cast.json` · `plan/treatment.json` · `plan/scenes.json` |
| Подготовить и сгенерировать сцену, продолжить отложенную генерацию | «Производство» | [Очередь пакетов](plan/awaiting/README.md) · `plan/batches` |
| Понять следующий шаг | «Проект» · «Проверки» → «Статусы планов» | `workflow.json` пакетов в `plan/batches` и [очереди](plan/awaiting/README.md), комплекты `assets/shots/Mxx`; принятие аниматика — [plan/production-status.json](plan/production-status.json) |
| Найти выбранный ролик, кадры или речевое аудио | «Сцены» | **[Каталог материалов](assets/README.md)**: папка на план |
| Посмотреть и принять полный монтаж | «Аниматик» | [Последняя полная сборка](plan/animatic/latest/README.md) · [правила сборки](plan/animatic/README.md) |
| Интервалы и действия | «Сцены» | [Монтажный список](plan/edit-list.md) · [Раскадровка](plan/storyboard.md) |
| Персонаж, транспорт, локация | «Кастинг» | `plan/cast.json` |
| Передать материалы монтажёру | «Проект» → «Пакет для монтажёра» | Пакет создаётся вне проекта: таблица планов, EDL, FCPXML, исходники |

В пустом проекте нет файлов, которые создают действия приложения: `source/manifest.json` (сохранение исходников), `plan/audio/timing.json` (разметка), `plan/cast.json`, `plan/treatment.json` и `plan/scenes.json` (кастинг и сценарий), `plan/animatic/latest/manifest.json` (сборка аниматика). Производные документы (`ROADMAP.md`, `plan/edit-list.md`, `plan/storyboard.md`, `plan/context/characters.md`, `plan/audio/timing.md`, `assets/shots/manifest.json`) появляются после первого обновления представлений.

## Источники сведений

| Сведения | Единственный редактируемый источник |
| --- | --- |
| Название проекта, имя MP4 аниматика и настройки генерации | [plan/project.json](plan/project.json) |
| Состав исходников: трек, текст песни, идея клипа, обложка, референсы с кодами и видами | `source/manifest.json` |
| Общая история и замысел | Файл идеи клипа из манифеста (по умолчанию `source/description.md`) |
| Сущности клипа, их изображения, роль, внешность и начальное состояние | `plan/cast.json`; карта `references` в `plan/scenes.json` выводится из кастинга |
| Трактовка первого прохода сценария | `plan/treatment.json`; после появления реестра сцен части редактируются в `plan/scenes.json` |
| Постановка, камера, непрерывность, общие визуальные правила, порядок и кадровые границы Mxx | `plan/scenes.json` |
| Сохраняющееся состояние героев и предметов | `state_from`/`state_changes` там же; сводку до/после вычисляет приложение |
| План, собранный из материала другого плана без своей генерации (стоп-кадр, повтор, замедление) | необязательное `derived_from: {"shot": "Mxx"}` там же; источник существует, не совпадает с планом и сам не производный; как используется материал — текстом в `action` |
| Общие изображения персонажей, транспорта, локаций и их исходные промпты | Только [source](source/README.md); в assets ссылки с `root: "source"` и SHA-256 |
| Оригинал, принятый монтаж, кадры, промпт, WAV и рецепт обработки сцены | `assets/shots/Mxx/manifest.json` по [контракту assets](assets/README.md#локальный-манифест-и-воспроизведение) |
| Незавершённая работа над планом | `workflow.json` его пакета в `plan/batches` или [plan/awaiting/Mxx](plan/awaiting/README.md) |
| Состояние просмотра и принятия полной сборки | [plan/production-status.json](plan/production-status.json) |
| Речевые и музыкальные оценки | `plan/audio/timing.json`; монтажные окна они не задают |
| Отложенные запросы и рабочие пакеты | [plan/awaiting/Mxx](plan/awaiting/README.md) и `plan/batches` |
| Последняя полная сборка | [plan/animatic/latest](plan/animatic/latest/README.md); её манифест снимок сборки, не источник постановки |

Производные представления (монтажный список, раскадровка, визуальный справочник, разметка трека, ROADMAP, индекс assets, README сцен и карточки) формирует приложение: кнопка «Пересобрать карточки» в строке «Карточки и списки» на странице «Проверки», а также сборка аниматика и приёмка сцены. Проверка «Карточки и списки» находит рассинхрон. Вручную производные файлы не правят: исправления вносятся только в источник.

## Правила хранения

- Исходники в `source/` доступны только для чтения; список защищённых файлов определяет `source/manifest.json`. Новые референсы добавляются на странице «Исходники», манифест записывает приложение. Описание идеи клипа меняется только по решению владельца.
- Всё в assets считается одобренным. Комплект выбранной сцены определяется её локальным манифестом; общий индекс assets производный. Подтверждения принятия, цитаты и время сообщений в assets не хранятся.
- Оригиналы, выбранные клипы, необходимые промежуточные кадры и технические параметры сохраняются; оригинал не заменяется обрезкой. Завершённые видеопробы очищаются по [правилу хранения assets](assets/README.md#очистка-завершённых-видеопроб).
- Хранится только текущий полный аниматик в `plan/animatic/latest`; карточки в `plan/animatic/cards`, производный кэш в `plan/animatic/.cache`.
- Текущая подготовка относится к `plan/batches` (исключена из Git, кроме `.gitkeep`); отложенные запросы хранятся самодостаточно в `plan/awaiting/Mxx` по [правилам очереди](plan/awaiting/README.md). Они не определяют готовность уже выбранного ассета.
- Кода в проекте нет: разовые скрипты, снимки перед изменениями и отчёты проверок хранятся вне проекта.

## Сборка и проверка

Страница «Проверки» проверяет данные сцен, карточки и списки, комплекты сцен, порядок в папке проекта и статусы планов; там же собирается проба стыков. Полная сборка выполняется на странице «Аниматик» по [правилам аниматика](plan/animatic/README.md). MP4 полной сборки в Git не хранится (`.gitignore`).

Провайдеры генерации в новом проекте не выбраны: `generation.video` и `generation.image` в `plan/project.json` равны `null`. Перед AI-действиями явно выберите агента в настройках приложения и нужного медиапровайдера в настройках проекта, затем сохраните их. Только `provider_selected: true` подтверждает выбор медиапровайдера; имя `provider` без этого маркера не разрешает запуск. Вход в платного провайдера генерации выполняется на странице «Среда».

Git в проекте необязателен и служит хранилищем материалов и истории. Commit и push выполняются только по решению владельца.
