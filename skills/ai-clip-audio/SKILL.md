# Разметка трека

Один проход в начале проекта. Результат: `plan/audio/timing.json` с оценкой начала и конца каждой строки песни и частями трека. Оценки подтверждает пользователь на слух в приложении (страница «Тайминги»), поэтому скилл не добивается точности вручную и не слушает трек сам.

## Вызов

| Задача | Codex | Claude Code |
| --- | --- | --- |
| Разметить текущий проект | `$ai-clip-audio` | `/ai-clip-audio` |
| Другой проект | `$ai-clip-audio project=/путь/к/папке` | `/ai-clip-audio project=/путь/к/папке` |
| Готовое распознавание | `recognition=/tmp/recognition.json` | то же |
| Другая модель | `model=/папка/модели` | то же |
| Пересчитать всё, включая подтверждённые строки | `reset=true` | то же |

Папка проекта без аргумента берётся из текущего проекта комплекса (`python3 -B tools/current_project/current_project.py --json show`). Все команды запускаются из корня комплекса; `--project <папка>` добавляется к каждой, если проект задан аргументом.

## Этапы

1. **Проект.** `current_project --json show`: `is_project` должен быть `true`. Иначе остановиться и попросить выбрать проект в приложении.
2. **Исходники.** Прочитать `source/manifest.json`: нужны `track` и `lyrics`. Прочитать `source/text.md` и проверить формат: одна строка песни на строку, заголовки частей только в квадратных скобках. Если встречаются строки вроде «Припев» или «Куплет 2» без скобок, остановиться и попросить поправить текст на странице «Исходники»: `source/` для скилла только чтение.
3. **Среда.** Использовать Python из подготовленного [runtime](../../scripts/runtime/README.md), а в dev без runtime допустим `python3`. Проверить импорт `faster_whisper` выбранным интерпретатором и папку модели. В Linux AppImage встроены Python и FFmpeg/ffprobe; модель устанавливается отдельно по [инструкции](../../README.md#модель-распознавания). Папка внешней модели передаётся через `--model` или `SONGFRAME_MODEL_DIR`; умолчание CLI — medium в каталоге данных ОС. Для ручного запуска из подготовленного checkout добавьте `build/runtime/linux-x64/bin` первым в PATH. Приложение рекомендует модель по ресурсам и доступной CUDA, допускает другую папку и CPU; крупнее medium использовать можно. Если чего-то нет, показать инструкции подготовки runtime/модели и остановиться: установка и загрузка требуют сети и выполняются по поручению. Настраивать `unshare` или AppArmor не требуется: автоматическая разметка запускается напрямую, модель загружается только локально.
4. **Разметка.** `python3 -B tools/align_lyrics/align_lyrics.py --json` (с `--recognition`, `--model`, `--project` по аргументам; при `reset=true` добавить `--reset`, иначе подтверждённые строки сохраняются). Распознавание идёт несколько минут на CPU. В среде с субагентами делегировать ожидание субагенту и вернуть в основной чат только сводку.
5. **Сводка.** Прочитать записанный `timing.json` и сообщить: число строк, сколько строк с неполным совпадением слов и сколько нераспознанных (по `note`), список частей с временем. В чат выводить только проблемные строки, не всю таблицу.
6. **Передача.** Сказать пользователю открыть «Тайминги» в приложении: прослушать строки, поправить границы и отметить подтверждённые. Статус проекта становится «трек размечен» уже после записи файла; подтверждение отражается в `status` разметки.
7. **Представления.** Если в проекте есть `plan/scenes.json`, выполнить `python3 -B tools/update_scene_views/update_scene_views.py`, чтобы обновился `plan/audio/timing.md`. В новом проекте реестра ещё нет, представления появятся на этапе сценария.

## Что скилл не делает

Не изменяет `source/`, не задаёт монтажные окна сцен (они принадлежат `plan/scenes.json`), не отправляет трек во внешние сервисы, не подтверждает строки вместо пользователя и не делает commit.
