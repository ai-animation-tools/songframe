# Kling: видео

Платный сервис генерации видео [kling.ai](https://kling.ai/). Общий контракт провайдера — в [README](../README.md).

## Подключение

- Приложение обращается к MCP-серверу Kling `https://kling.ai/mcp` собственным Go-клиентом [internal/providers/kling/mcp](../../../internal/providers/kling/mcp/session.go): JSON-RPC без идентификатора сеанса сервера (`initialize`, затем `tools/call`), загрузка локальных файлов — тикет `file_upload` и multipart-запрос. Клиент встроен в приложение: официальный Kling CLI и Node для него не нужны.
- Вход выполняется на странице «Среда» кнопкой входа: приложение регистрирует собственного OAuth-клиента SongFrame (динамическая регистрация, PKCE, ответ браузера на `127.0.0.1:8787–8790/callback`) и само открывает страницу входа Kling в браузере. Пока идёт ожидание (до 5 минут), строка Kling показывает ссылку на эту страницу — на случай, если браузер не открылся, — и кнопку отмены. Строка проверки среды только подтверждает наличие встроенного клиента; состояние входа страница узнаёт одним запросом к сервису.
- Токены хранятся в каталоге состояния приложения ([internal/store](../../../internal/store/profile.go)) в файле `providers/kling/credentials.json`. Каталог по умолчанию — `songframe-desktop` в папке настроек ОС (Linux `${XDG_CONFIG_HOME:-~/.config}/songframe-desktop`, Windows `%APPDATA%\songframe-desktop`); переменная `SONGFRAME_LOCAL_DIR` задаёт другой каталог. Файл заменяется атомарно, с правами `0600` там, где ОС их поддерживает. Срок токена доступа объявляет сервер; токен обновляется под межпроцессной блокировкой `credentials.lock` заранее (за минуту до истечения) или после ответа 401. Если сервер выдаёт новый токен обновления, клиент сохраняет его, иначе оставляет прежний; при повторном входе прежний токен обновления отзывается. Файл официального CLI `~/.kling/.credentials` не используется, поэтому вход в SongFrame и в официальный CLI независимы.
- Адаптер — [internal/providers/kling](../../../internal/providers/kling/adapter.go): возможности, нормализация запроса, отправка, опрос, получение, остаток и базовая таблица цен [pricing.json](../../../internal/providers/kling/pricing.json), встроенная в бинарник. Приложение подключает его строкой таблицы [internal/mediaadapters](../../../internal/mediaadapters/mediaadapters.go). Общий цикл попытки ведёт [internal/mediarequest](../../../internal/mediarequest/attempt.go), стоимость и остаток — [internal/costcheck](../../../internal/costcheck/costcheck.go).
- Отладка: `SONGFRAME_KLING_DEBUG_FILE` — файл для записи ответа сервиса при неизвестном исходе отправки (без токенов); `SONGFRAME_KLING_BASE_URL` — адрес поддельного сервера в тестах.
- За изменениями MCP-сервера Kling следит владелец: изменение протокола (имена инструментов, вход, загрузка) требует правки клиента.

## Значения реестра

| Поле | Значение | Почему |
| --- | --- | --- |
| `paid` | `true` | Каждая отправка списывает кредиты: цена, остаток и отдельное подтверждение |
| `lipSync` | `null` | Синхронизации губ с заданным звуком у сервиса нет: см. «Липсинк» |
| `manualLipSync` | сайт `kling.ai/app/creations/grid`, режим Avatar | Пошаговая инструкция ручной генерации речевого плана |
| `learnsPriceFromCharges` | `true` | Сервис не сообщает цену заранее; приложение запоминает фактические списания |
| `generationHistory` | галерея созданных работ `kling.ai/app/creations` | Где пользователь выясняет неизвестный исход отправки |
| `requestParameters` | `true` | Разрешение, пропорции и число вариантов задаются в настройках проекта |
| `defaultModelLabel` | «Автоматически по задаче» | Пустая модель — выбор по требованиям плана |

Реестр — [media-providers.ts](../../../frontend/src/shared/media-providers.ts), его Go-часть — [internal/mediaproviders](../../../internal/mediaproviders/mediaproviders.go).

## Возможности и выбор модели

- Каталог читается вызовами `tools/list` и `who_am_i` одним свежим снимком на обновление ([возможности адаптера](../../../internal/providers/kling/capabilities.go)). Приложение не хранит собственный список моделей и не выдумывает их лимиты; порядок известных моделей в настройках задаёт поле реестра `modelOrder`.
- Запрос видео собирает приложение по правилам адаптера ([`RequestRules`](../../../internal/providers/kling/app.go)): команда `image_to_video`, опоры по порядку в слотах `first_image`, `keyframe_N`, `tail_image`, разрешение из настроек, `aspect_ratio` не передаётся (пропорции задаёт кадр `first_image`, приложение сверяет его размеры с проектом), `prefer_multi_shots=false` там, где модель это допускает, `enable_audio=false`. Указанная в настройках модель — предпочтение: приложение проверяет её, затем `kling-video-v3_0` (дешевле, но без промежуточных кадров), `kling-video-v4_0` и остальные модели команды. Модели, не объявляющие разрешение проекта или нужный слот кадра, не проходят проверку: например, `v3_0_turbo` объявляет только `first_image` и не примет план с конечной опорой. Turbo автоматически не выбирается — при одной опоре `v3_0` даёт более правдоподобное движение и дешевле; её выбирают вручную через «Изменить». Длительность, разрешение, число результатов и опоры ради предпочтения не уменьшаются. «Изменить» на вопросе «Отправить» выбирает другую модель и её параметры. Обоснование `model_selection` входит в замороженный запрос и SHA.
- `watermark=true` новые запросы не допускают: если модель объявляет параметр, он выключается явно. Получение видео ждёт явный адрес без логотипа (`urlWithoutWatermark`); без него попытка остаётся в `watermark_free_pending` и продолжает тот же ID.

## Стоимость и отправка

- Остаток читается инструментом `query_membership_and_credits` (`availableRemainCredits`). Оценка стоимости — по базовой таблице цен адаптера [pricing.json](../../../internal/providers/kling/pricing.json), встроенной в бинарник (только чтение), и наблюдениям фактического расхода в каталоге состояния (`providers/kling/pricing-observations.json`); при чтении они объединяются. Фактическое списание (`creditsConsumed`) записывается после отправки.
- Явный отказ сервиса (ответ инструмента с `isError`, например «Invalid parameters» при неверной длине звука или «too many requests»), сбой загрузки локального файла, отсутствие входа и недоступность сервера до отправки означают, что задание не создано: попытка остаётся `prepared`. Таймаут или обрыв после отправки запроса, ошибка 5xx и неразборчивый ответ — неизвестный исход. Ожидание ответа на отправку — до 300 с. Каждая попытка хранит свой `task_trace_id` (UUID v7), который уходит сервису с запросом: по нему можно обратиться в поддержку Kling, но найти задание сам сервис не позволяет.
- **Неизвестный исход.** ID задания (`generationId`, непрозрачная строка около 70 символов) сервис возвращает только отправившей программе. Инструмента со списком заданий у сервера нет, а `query_tasks` принимает только этот ID: числа из адреса галереи (`materialId`, `slotId`) им не являются и отклоняются как «Invalid generationId». Поэтому исход выясняет пользователь в галерее созданных работ и загружает найденный оригинал вручную либо отмечает, что задание не создано ([порядок](../../../docs/production-workflow.md#неизвестный-исход)).
- Отмены после отправки нет ([официальное руководство](https://kling.ai/app/mcp/guide)); результат нужно получить в течение срока доступности (24 часа).

## Липсинк

Липсинка у сервиса нет. Единственный звуковой вход — слот `audio_1` режима `omni_ref_video` модели `kling-video-v4_0` (5–30 с) — объявлен как звуковой референс: на пробе с точным WAV песни и прямым требованием в промпте совпадения губ с `音频1` губы персонажа не двигались, а звук попал только в дорожку ролика. Отдельного lip-sync к готовому видео у сервиса нет, у Flash и прочих режимов звуковых слотов нет. Поэтому `lipSync` в реестре — `null`, и план с отметкой «Липсинк» делается [ручной генерацией](../../../docs/production-workflow.md#ручная-генерация): по пакету с опорой, срезом речи и промптом пользователь создаёт видео в режиме Avatar на сайте сервиса (в MCP этого режима нет) и загружает результат в попытку. Avatar отдаёт ролик 1904×1072; приёмка приводит его к кадру проекта.

## Указания агенту

Запрос видео собирает приложение по правилам ниже; агент пишет описание и видеопромпт под него.

- Опоры уходят настоящими кадрами: первая — `first_image`, последняя — `tail_image`, промежуточные — `keyframe_N`. При одной и двух опорах приложение выбирает `kling-video-v3_0`, при трёх и больше — `kling-video-v4_0` (не более 10 изображений), если предпочтение проекта не подходит лучше. `requestSeconds` выбирай по сетке длительностей этой модели из `capabilities`; `v2_5` и `v2_6` дают только 5 и 10 с и для окон 5–9 с удвоили бы запрос.
- Видеопромпт — по-английски: Kling точнее следует английскому тексту. По-русски — только `translation`.
- Обозначения входов — `图片1`, `图片2`… по порядку опор, звук — `音频1`. Первая фраза: «图片1 is the first frame, 图片2 is the final state.»; при одной опоре — «图片1 starts the shot.», а конечное состояние описывается словами.
- Единый план идёт с `prefer_multi_shots=false`, а модель, допускающая только `true`, получает `true`: в обоих случаях промпт описывает один непрерывный план без монтажных склеек.
- Звук генератора выключен: звук клипа — исходная песня в монтаже, промпт звук не описывает.
- Видеопромпт не длиннее 3 000 символов (предел приложения: документированный предел API — 3 072). Пиши столько, сколько нужно плану; если предел превышен, сократи описание окружения, а не события. Предел веб-интерфейса сервиса к API не относится.
