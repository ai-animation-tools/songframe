# derive_shot

Собирает локальную пробу производного плана из текущего принятого видео обычного плана и отдельно принимает показанные байты. Провайдер генерации не вызывается. Источник выбирается только по `scene.derived_from.shot`; произвольный файл, оригинал генерации и цепочка производных планов не принимаются. Источник должен иметь статус `completed`, текущие SHA-256 комплекта и принятого клипа. Производный план с `lipsync: true` блокируется: локальная обработка не гарантирует синхронность губ.

```sh
python3 -B tools/derive_shot/derive_shot.py --project /путь/к/клипу build --shot M05 --recipe plan/derived/M05/recipes/выбор.json --work-dir plan/derived/M05/новая-проба --json
python3 -B tools/derive_shot/derive_shot.py --project /путь/к/клипу accept --work-dir plan/derived/M05/новая-проба --confirm SHA256_РЕЗУЛЬТАТА --json
python3 -B tools/derive_shot/derive_shot.py --project /путь/к/клипу recover --json
```

Общий launcher выбирает проект. Все пути аргументов относительны к проекту. `--work-dir` — новая, ещё не существующая папка строго `plan/derived/Mxx/<id>`; входной рецепт находится отдельно, например в `plan/derived/Mxx/recipes/<id>.json`. `--replace` у `accept` разрешает заменить уже выбранный комплект. Каждый успешный вызов возвращает JSON; с `--json` ошибка также возвращает JSON `{status: "error", message: "..."}` и ненулевой код завершения.

## Четыре явных рецепта

Рецепт — простой JSON ровно с полями выбранного режима. Кадры целые, нумерация с нуля на сетке 30 FPS; правая граница исключается. Число выходных кадров `N` задаёт текущее окно целевого плана в реестре, а не пользовательский рецепт.

| Рецепт | Результат |
| --- | --- |
| `{"mode":"trim","start_frame":12}` | Ровно N последовательных кадров от указанного начала; недостаточного источника недостаточно для сборки |
| `{"mode":"fit","start_frame":12,"end_frame_exclusive":72}` | Весь выбранный участок длиной L кадров с множителем скорости L/N; допускаются ускорение и замедление с выбором/дублированием кадров FFmpeg |
| `{"mode":"still","frame":42}` | Единственный выбранный кадр повторяется N раз |
| `{"mode":"repeat","start_frame":12,"end_frame_exclusive":72}` | Выбранный цикл повторяется до N кадров; последний цикл обрезается до нужного хвоста |

Автоматического выбора участка, скрытых удержаний, генерации недостающего движения и интерполяции нет. Выходное видео — 1920×1080, 30 FPS без аудио.

## Проба и подтверждение

`build` сначала готовит временную папку и после проверки публикует весь `work-dir` одним переименованием. `candidate.mp4` содержит ровно принимаемое видео без звука; `preview.mp4` использует его видеопоток без перекодирования и музыку из окна целевого плана. Если файла песни нет, превью — точная копия кандидата.

`preview.json` содержит `schema_version: 1`, `shot`, `source_shot`, `source_scene_sha256`, `source_accepted_video_sha256`, `target_scene_sha256`, `target_frames`, обязательный `audio_source`, `recipe`, дескрипторы `video` и `preview` с `path`, `sha256`, `bytes` и `result_token`. `audio_source` сохраняет переносимый `path` из `registry.audio.path` и `sha256` фактических байтов песни либо `null`, если файла нет. `recipe.json` сохраняет показанный рецепт; `build.json` — путь и хеш его входного файла, точный фильтр, границы цели, хеш манифеста источника и версию FFmpeg. Токен связывает этот снимок с рецептом и точными байтами обоих результатов.

После сборки инструмент больше не меняет `work-dir`, в том числе при приёмке и повторе после ошибки. `accept` повторно сверяет постановку источника и цели, текущий принятый клип источника, весь его комплект, музыку, рецепт и готовые результаты. Замена, удаление, появление файла песни или изменение его пути при сборке либо после неё требуют новой пробы. Контекст музыки принадлежит только пробе: принятый манифест его не хранит, поскольку выбранный клип не содержит звука. Приёмка не рендерит: файл по `accepted_edit.video.path` копируется из подтверждённого `candidate.mp4`. Повтор уже успешно принятого подтверждения возвращает тот же результат после проверки актуального выбранного комплекта.

## Принятый комплект

Новый манифест имеет `kind: "derived_video"`. `generation` сохраняет сведения исходной генерации и поля `source_shot`, `source_scene_sha256`, `source_accepted_video_sha256`. Копируются только достижимые файловые дескрипторы исходной генерации и их JSON-зависимости: полный оригинал с `original_media`, промпты, снимок запроса, входы, подготовка и необходимые дополнительные файлы. Ссылки `root: "source"` остаются ссылками. Чужие README, revisions и вся папка исходника целиком не копируются; платный запрос или попытка не подделываются. Все относительные пути исходной генерации сохраняются, чтобы ссылки внутри неизменяемых JSON продолжали разрешаться в точные исходные байты. Результат и монтажный источник размещаются в свободной локальной подпапке `derived-output/`; если такое имя уже занято исходным комплектом, выбирается `derived-output-1/`, `derived-output-2/` и далее. Точные пути принадлежат манифесту.

Файл `edit-source.mp4` внутри выбранной выходной подпапки — точные байты принятого клипа источника, использованные в пробе. `accepted_edit.rebuild.source` и `stages` позволяют воспроизвести операцию штатным `asset_package --from-original`; принятый результат копируется побайтово. Для повторения `accepted_edit.repeat` содержит `full_cycles`, `tail_frames`, `cycle_frames`. [Экспорт для монтажёра](../export_edit_bundle/README.md) сохраняет эти числа в CSV/JSON и раскладывает цикл и хвост на события EDL; FCPXML использует готовый принятый клип.

## Транзакция и восстановление

Новый комплект, статус производства и представления сначала полностью строятся и проверяются в staging. Из копии проекта исключаются только служебные пути `plan/derived`, `plan/derived-history`, `plan/montage-history`, `assets/replaced` и `plan/animatic/.cache`; одноимённые папки исходников и подготовки сохраняются. `plan/production-status.json` принимает текущий `target_scene_sha256`; остальные записи и поля сохраняются. После проверки создаётся журнал в `plan/derived-history/<id>/journal.json` с резервными копиями файлов в `before/` и целого прежнего комплекта в `before-kit/`. При `--replace` прежний комплект целиком переносится в `assets/replaced/Mxx/<id>/`, включая пользовательские файлы; новый публикуется переименованием папки. История и старые оригиналы остаются.

Журнал имеет `schema_version`, `id`, `shot`, `state`, `result_token`, `work_dir`, `files: [{path,before,after}]` и `directory: {path,before,after,backup,retired,before_files,after_files}`. `before`/`after` файлов — SHA-256 или `null`; карты `before_files`/`after_files` содержат все относительные пути файлов комплекта и SHA-256, отсутствующая прежняя папка обозначается `null`. Отпечаток папки — SHA-256 JSON массива пар `[path,sha]`, упорядоченных по пути, с отступом 2 и завершающим переводом строки. Состояния: `preparing`, `publishing`, `committed`, `rolled_back`, `failed`.

Любая ошибка публикации откатывает комплект, статус и представления. `recover` завершает откат журналов `publishing` после аварии; приложение использует тот же журнал при старте и открытии проекта без запуска Python. Перед восстановлением проверяются все выбранные файлы, папка комплекта, архив и резервные копии. Посторонняя правка после аварии останавливает автоматический откат и сообщает путь журнала. Восстановление повторяемо, staging после успеха или полного отката удаляется; готовый кандидат остаётся для повторной приёмки.

## Проверки

```sh
python3 -B tools/run_tests/run_tests.py --only test_derive_shot test_export_edit_bundle
```

Проверяются реальные пиксели и порядок кадров всех четырёх режимов, обе стороны изменения скорости, точный хвост повтора, число кадров и отсутствие аудио кандидата, копирование видеопотока превью, текущий принятый источник в revisions, воспроизведение, сохранение оригинала и JSON-зависимостей, общие референсы, immutable проба, замена с архивом, сохранение путей и внутренних JSON-ссылок при коллизиях имён, идемпотентное подтверждение, отказ после изменения входов, липсинк и устаревший источник, откат частичной публикации и восстановление после аварии. Все проверки используют временные копии проекта-образца и настоящее локальное FFmpeg, без сети и генераций.

При принятии новой сборки прежний `shots.Mxx.source_review` этого плана удаляется: новая приёмка опирается на новый снимок `generation`. Подтверждения других планов и их материалы сохраняются.
