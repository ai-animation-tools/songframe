# update_scene_views

Обновляет производные документы, индекс assets и карточки из канонических источников. Использовать после изменения `plan/scenes.json` или локального комплекта выбранной сцены.

## Контракт

```sh
python3 -B tools/update_scene_views/update_scene_views.py
python3 -B tools/update_scene_views/update_scene_views.py --check
python3 -B tools/update_scene_views/update_scene_views.py --check --staged
python3 -B tools/update_scene_views/update_scene_views.py --check --ref HEAD
```

Обычный запуск записывает представления и карточки; `--check` проверяет без изменений. `--staged` проверяет индекс Git, `--ref` — заданный снимок; оба разрешены только вместе с `--check` и предназначены для проверки снимка Git перед порученными commit/push (правила в [AGENTS.md](../../AGENTS.md) комплекса и шаблоне проекта). Не запускать staged/ref-проверку вместо проверки рабочего дерева.

Название берётся из `plan/project.json`, подписи и изображения референсов — из `references` в реестре сцен. Квитанция карточек содержит хеш реестра и снимок `project_inputs: {name}`. Смена настроек генерации, имени MP4 или форматирования `project.json` не меняет карточки; новое название требует обновления представлений до сборки. Снимок проверяется по точным ключам и строковым значениям; повреждённое поле означает устаревшую квитанцию.

Поле `project_inputs` обязательно; его отсутствие требует обновить представления. `--check` сравнивает единственный канонический формат квитанции без исправления файлов.

Проверка оформления не требует корректных `generation.video` и `generation.image`: настройка провайдера не блокирует документы и локальные карточки. Перед генерацией исполнитель проверяет только блок выбранного медиа.

Обязательные источники: `plan/scenes.json`, `plan/project.json`, `plan/production-status.json` и `plan/audio/timing.json`. Если источника нет в рабочих файлах или выбранном снимке Git, CLI завершается с кодом 1 и коротким сообщением без traceback; представления не записываются. При отсутствии `plan/scenes.json` сначала создайте сценарий. Неожиданные ошибки программы сохраняют traceback для диагностики.

Папка `plan/animatic/cards` производная: обычный запуск удаляет PNG, которых нет в квитанции, то есть карточки принятых планов (у них появился `assets/shots/Mxx/manifest.json`) и последние опоры ушедших пакетов; `--check`, `--staged` и `--ref` сообщают о таких файлах как об устаревших представлениях. Карточка исчезает в том же запуске, который обновляет ROADMAP после приёмки сцены.

Если у плана без комплекта есть пакет в `plan/awaiting/Mxx` или `plan/batches/*` с полностью принятыми опорами (`workflow.json`, этап не `accepted`), вместо текстовой карточки рисуется карточка опор, а при двух и более опорах — ещё `Mxx.last.png`. Квитанция карточек записывает пути и хеши опор; устаревшие `*.last.png` удаляются. Проверка по снимку Git сверяет записанные хеши без повторного чтения пакетов.

ROADMAP показывает план с комплектом как «Готово» только при совпадении отпечатка постановки из `plan/production-status.json` → `shots`, иначе «Постановка изменена» ([правило](../scene_registry/README.md#принятие-планов)); поэтому правка постановки принятого плана тоже требует обновить представления. Карточки и индекс assets зависят только от наличия комплекта: устаревший комплект остаётся материалом сборки.

Производный план (`derived_from`) помечается «из Mxx» в ROADMAP, монтажном списке, раскадровке и заголовке текстовой карточки — подробности в [project_views](../project_views/README.md) и [render_animatic_cards](../render_animatic_cards/README.md).

В `plan/context` формируется только `characters.md` — единый визуальный справочник с вычисленным списком речевых планов. Промпты референсов хранятся в `source` и этим инструментом не изменяются; полный аниматик не пересобирается — для него [build_animatic](../build_animatic/README.md).

## Тесты

Запись и проверка представлений на временном проекте, карточки опор из пакета очереди и удаление устаревшей последней опоры, проверка индекса и коммита временного репозитория Git по записанным хешам. Отсутствующие источники проверяются через настоящий CLI: ненулевой код, краткое сообщение и отсутствие записи; неожиданный `ValueError` продолжает передаваться вызывающему коду.

```sh
python3 -B tools/update_scene_views/test_update_scene_views.py
python3 -B tools/run_tests/run_tests.py --only test_update_scene_views
```

Рабочие представления обновляются и проверяются без установленного Git. Режимы `--staged` и `--ref` требуют Git и проверяют настоящий индекс или снимок; отсутствие Git не считается успешной проверкой этих режимов.
