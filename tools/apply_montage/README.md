# apply_montage

Явно применяет ручной монтаж к существующим принятым комплектам. При сохранении черновика или экспорте пробы этот инструмент не вызывается. Формат входа — `MontageDraft` из [shared/montage.ts](../../src/shared/montage.ts), правила интерфейса — в [описании монтажа](../../docs/montage.md).

```sh
python3 -B tools/apply_montage/apply_montage.py --project /путь/к/клипу --spec plan/montage/manual.json
python3 -B tools/apply_montage/apply_montage.py --project /путь/к/клипу --recover
```

`--project` обрабатывает общий launcher; относительный `--spec` отсчитывается от выбранного проекта. `--no-views` отключает обновление производных документов и карточек; обычный запуск обновляет их штатным `update_scene_views`, не добавляя ручных записей в ROADMAP и не пересобирая аниматик.

Пример одного участка; вместо заглушек нужны SHA-256 **сырых байтов** текущих файлов:

```json
{
  "schema_version": 1,
  "name": "Выбранный участок",
  "audio": {"path": "source/track.mp3", "start_frame": 3300, "end_frame_exclusive": 3444},
  "clips": [{
    "id": "clip-M31",
    "scene": "M31",
    "path": "assets/shots/M31/original.mp4",
    "kind": "video",
    "source_start_frame": 12,
    "source_end_frame_exclusive": 156,
    "source_frames": null
  }],
  "base_scenes_sha256": "SHA256_plan/scenes.json",
  "base_manifest_sha256": {"M31": "SHA256_assets/shots/M31/manifest.json"}
}
```

## Условия применения

- Только `video` из `generation.original` либо текущего `accepted_edit.video` той же принятой сцены. Пути относительные, от корня проекта. Произвольные рабочие ролики и карточки можно использовать в пробе, но применять к комплектам нельзя.
- Сцены перечислены по одному разу, соседствуют в исходном порядке `plan/scenes.json`. Внешние границы выбранного окна и исходная песня совпадают с реестром. Сумма `source_end_frame_exclusive − source_start_frame` равна длине окна `audio`; промежутков и перекрытий нет.
- Внутренний стык разрешается переносить: длины обоих соседних клипов меняются вместе с их `accepted_edit` и границами в реестре. Остальная постановка, песня, разметка и аудио липсинка сохраняются.
- Все кадры относятся к сетке 30 FPS после преобразования входа. Источник проверяется настоящим `ffprobe`, а `source_frames` остаётся подсказкой интерфейса. Скорости, удержаний, эффектов и автоматического дополнения недостаточного источника здесь нет. Фильтр обрезки и масштаба считает `build_review`; `accept_shot.render_edit` проверяет итоговый формат 1920×1080, 30 FPS и число кадров. Выходные клипы не содержат звука.
- Граница плана входит в [отпечаток его постановки](../scene_registry/README.md#принятие-планов), поэтому перенос стыка меняет отпечатки обоих соседей. Для каждого плана монтажа, принятого по текущей постановке (сохранённый `plan/production-status.json` → `shots.Mxx.scene_sha256` совпадает с отпечатком по прежнему реестру), записывается отпечаток по новому реестру: план остаётся принятым. План, постановка которого уже изменилась после приёмки, остаётся `stale` с прежней записью: ручной монтаж не отменяет необходимость нового производства. Прочие поля статуса и записи других планов сохраняются; при неизменных отпечатках файл не меняется.
- Хеш всего реестра и хеши выбранных манифестов проверяются перед рендером и непосредственно перед публикацией; `plan/production-status.json` — непосредственно перед публикацией, его изменение во время рендера (например, принятие сборки в приложении) останавливает применение. После рендера повторно проверяются файлы комплектов и выбранные входы с песней. Устаревший черновик требует заново открыть материалы.

## Хранение и восстановление

Ни один старый монтажный клип или оригинал не перезаписывается. Новое видео хранится как `assets/shots/Mxx/revisions/<revision>/video.mp4`; рядом `previous-manifest.json` содержит точные предыдущие байты локального манифеста. Его внутренние пути по-прежнему относятся к папке сцены. Старые файлы остаются на прежних местах, в том числе при следующем применении.

В `accepted_edit.rebuild.source` и `stages[].input` записаны точные локальные байты выбранного источника. Для среза принятого клипа это сохранённый предыдущий клип, а не повтор всей прежней цепочки с дополнительной потерей H.264. Прежняя цепочка остаётся в архивном манифесте; актуальный `asset_package --from-original` штатно воспроизводит новый срез из указанного локального входа. Копирование `accepted_edit.video` возвращает точные принятые байты, повтор FFmpeg гарантирует обработку без обещания идентичного H.264.

Все выбранные сцены сначала рендерятся и проверяются в staging. Там же штатно строятся документы и карточки. Только после успеха создаётся журнал `plan/montage-history/<revision>/journal.json`, резервные копии меняемых файлов в `before/` и публикуется новый комплект состояния. Статус производства с новыми отпечатками пишется в staging до обновления представлений и публикуется в той же транзакции: журнал, резервные копии и откат охватывают `plan/production-status.json` наравне с реестром. При ошибке записи реестр, статус производства, выбранные манифесты и производные файлы восстанавливаются вместе. Staging после успеха или полного отката удаляется; исходники, прошлые версии, `draft.json`, журнал и резервные копии остаются.

При аварийном завершении процесса журнал со `state: "publishing"` позволяет закончить откат: следующий `apply` выполняет восстановление до проверки нового черновика; отдельный `--recover` делает только восстановление. Приложение восстанавливает этот же журнал без Python при старте окна для известных проектов и при явном открытии проекта. Перед откатом проверяются SHA-256 текущих файлов и backup; если после аварии файл изменён вручную, автоматическое восстановление останавливается и показывает путь к журналу. Подтверждённая публикация имеет `state: "committed"`, полный откат — `rolled_back`.

Инструмент не удаляет рабочие пакеты или пробы в `plan/batches`, не чистит историю и не принимает полный аниматик. Сохранённые черновики и ручные экспорты сохраняют свои зависимости по [montage_files](../montage_files.py).

## Проверки

```sh
python3 -B tools/apply_montage/test_apply_montage.py
python3 -B tools/run_tests/run_tests.py --only test_apply_montage
```

Проверяются срез той же длины, перенос внутреннего стыка сразу двух принятых сцен, сохранение принятия по новым границам только для ранее актуальных планов и запись статуса в журнал, устаревшие данные, недостаточный исходник, отказ без частичного изменения, rollback публикации, восстановление после аварии, сохранность оригиналов, точные прежние манифесты и повтор среза принятого источника. Тесты используют только временные копии `sample-project` и настоящее локальное FFmpeg.

У ранее готового производного плана с явным `shots.Mxx.source_review` применение монтажа сохраняет подтверждённую версию источника и обновляет только `accepted_video_sha256` на новый принятый клип. Подтверждение не создаётся и не исправляется у ранее устаревшего плана. Сведения `generation` о происхождении остаются неизменными.
