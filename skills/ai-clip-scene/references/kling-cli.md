# Kling CLI: среда, вход, правило длительности, подготовка команды

Читать перед первым обращением к Kling в сессии. Это официальный CLI с браузерным входом, а не developer API с ключами. Объявления моделей меняются: источник истины вывод `capabilities` для текущего аккаунта, а не даты в документах. Провайдер, разрешение, пропорции, логотип и правило длительности берутся из соответствующего блока `generation.video` или `generation.image` в `plan/project.json` проекта (см. [«Настройки генерации»](../SKILL.md#настройки-генерации)).

## Проверка и настройка

В готовой поставке приложения официальный `@klingai/cli-global` уже включён и работает на runtime Electron. Node.js, npm и Kling CLI пользователю устанавливать не нужно. Из папки клипа запускай команды через управляемый launcher; в Windows он имеет расширение .cmd:

```bash
./.songframe/run-kling --version
./.songframe/run-kling who_am_i --quiet
```

Вне проекта файл приложения поддерживает `--songframe-kling <аргументы>`. После перемещения приложения или проекта открой проект в приложении: оно обновит `run-kling`. Этот launcher не добавляет `--project`. Первый вход также доступен кнопкой на странице «Среда».

Если вход ещё не выполнен, пользователь завершает `./.songframe/run-kling login` в браузере. Официальный CLI хранит вход в файле `.kling/.credentials` домашней папки пользователя; приложение не создаёт другого хранилища токенов. Пароли, cookie, токены и credentials не запрашивать и не читать. Работающий вход не повторять: новый `login` может сбросить локальную авторизацию. Смена аккаунта — штатный `logout`. До настройки входа готовить материалы локально, не обещая готовность Kling.

Информационные команды без расхода: `./.songframe/run-kling who_am_i --quiet`, `./.songframe/run-kling account --quiet`, `./.songframe/run-kling tool_list --quiet` и `./.songframe/run-tool kling_request capabilities`. Полный профиль и сырые ответы не сохранять; подписка и остаток — текущие сведения. Ссылку пополнения брать из ответа сервера; подписку и кредиты не покупать.

### Внешний CLI при разработке

Только в разработке без подготовленного `build/runtime/kling` приложение использует обычный `kling` из PATH. Для этого внешнего режима нужен Node.js 18+; `command -v kling`, `kling --version` и `node --version` проверяют именно внешнюю установку. Если она требуется, предложи установку и вход, уточнив регион аккаунта. Оба пакета дают команду `kling`, вместе их не ставить, существующий регион молча не менять. Встроенная поставка использует международный пакет.

| Аккаунт | Кабинет | Установка внешнего CLI |
| --- | --- | --- |
| Международный | [Kling AI](https://kling.ai/) | `npm i -g @klingai/cli-global --registry=https://registry.npmjs.org` |
| Китайский | [可灵 AI](https://klingai.com/) | `npm i -g @klingai/cli-cn --registry=https://registry.npmjs.org` |

У внешнего CLI обычный `kling login`; без прав на глобальную установку предложить пользовательский способ, `sudo` не использовать. Эта настройка не требуется пользователю готового приложения.

## Длительность и монтажный запас

Длительность запроса `D` вычисляется из монтажного окна `T` по `generation.video.duration_rule` проекта и сетке длительностей выбранной модели из `capabilities`:

| `duration_rule`                              | Правило                                                                                                                   | Примеры при шаге 1 с                                                                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `min_supported_strictly_greater_than_window` | Минимальная поддерживаемая длительность строго больше окна                                                                | 4,9 с → 5 с; ровно 5 с → 6 с; 5,1 с → 6 с. Если доступны только 5 и 10 с, окну ровно 5 с нужен запрос на 10 с: равная длительность запаса не создаёт |
| `min_supported_not_less_than_window`         | Минимальная поддерживаемая длительность не меньше окна                                                                    | 4,9 с → 5 с; ровно 5 с → 5 с; 5,1 с → 6 с                                                                                                            |
| `exact_window`                               | Длительность равна окну; если сетка модели такого значения не содержит, остановиться и согласовать другую модель или окно | 5 с → 5 с; 5,1 с → остановка                                                                                                                         |

Секунду до округления не добавлять. При окне длиннее доступного предела модели согласовать разбиение или другую постановку, а не сдвигать окна и не склеивать генерации самостоятельно. Применённое правило указывается в таблице запроса строкой «Время».

## Подготовка команды

1. Объявления аргументов и слотов модели: `capabilities --command image_to_video [--model …]`; при сомнении сверить с `./.songframe/run-kling who_am_i`. Статическая справка без входа не подтверждает возможности сервера; платной отправкой их не проверять.
2. Модель и режим выбираются по [model-selection.md](model-selection.md). Настоящие первый и последний кадры слоты `first_image` и `tail_image`; промежуточные `keyframe_N` у моделей, где они объявлены. Слоты `image_1…7` у omni-моделей референсы, не кадры; согласованный набор опор не сокращать до одного-двух кадров без решения пользователя.
3. Входные изображения передаются через `--input имя=путь` либо `--image`/`--tailImage`, без смешивания и без повторного занятия слота. В спецификации `kling_request` это `inputs[].flag` и `slot` по [формату запроса](../../../tools/kling_request/request-format.md). Референсы сущностей берутся из `source/<папка типа>/...` по кастингу.
4. Для моделей, объявляющих `prefer_multi_shots` (по справке CLI 0.2.3 это `kling-video-v3_0` и `kling-video-v3_0_omni`), единый план всегда идёт с `prefer_multi_shots=false`: у `v3_0` значение по умолчанию `true`. `prepare` отклоняет такой запрос без параметра. Моделям без объявления флаг не передавать; непрерывность плана дополнительно описать в промпте.
5. `resolution` и `aspect_ratio` подставляются из `generation.video` проекта. У `kling-video-v4_0` разрешение по умолчанию 720p, поэтому `resolution` обязателен, а `aspect_ratio` при переданном первом кадре не передаётся. Звук отключать, если параметр объявлен; иначе указать требования в промпте и фактическое поведение в таблице. Число результатов `imageCount`/`outputs`.
6. Промпт передаётся инструментом отдельным аргументом без интерпретации оболочкой; текст, начинающийся с `--`, отклоняется при подготовке. Прямые вызовы внутренних endpoint, извлечение токенов и подмена провайдера исключены.

Локальные пути загружаются при вызове CLI, поэтому `file_upload` и `submit` до разрешения на запрос запрещены; разрешение на запрос включает передачу перечисленных входов. Для кадров в Kling есть `text_to_image` и `image_to_image`, для смешанных референсов `omni_ref_video`; каждый такой запрос платный и требует отдельного показа и разрешения. Elements из файлов проекта автоматически не создавать.

Один запуск, ожидание и получение выполняет `./.songframe/run-tool kling_request` (`submit`, `watch`, `resume`, `status`): встроенный `--poll` не использовать, ID сохраняется локально до ожидания, видео скачивается без логотипа (`generation.video.watermark: false`) и без перекодирования. Изображения сохраняются как фактический PNG/JPEG/WebP по сигнатуре байтов, включая opaque/extensionless URL; расширение URL и HTTP Content-Type не задают формат оригинала. Формат входного референса проверяется отдельно по контракту команды, а формат выхода определяется после получения. Сбои по [recovery.md](recovery.md).

## Image-команды и актуальные объявления

Для `generation.image.provider=kling` запрашивай capabilities отдельно для `text_to_image` и `image_to_image`: один model ID может поддерживать разные команды, параметры и слоты. `who_am_i`/актуальная help объявляют модели аккаунта; статические video-параметры не задают image resolution, aspect ratio или quality. Для локальных референсов CLI выполняет загрузку при разрешённом вызове генерации, поэтому локальный `prepare` и `quote` остаются без отправки файлов и расхода.

[Официальное руководство](https://kling.ai/app/mcp/guide) описывает `who_am_i` → выбор объявленных моделей/параметров, T2I/I2I с автоматической загрузкой локальных референсов и получение через `query_tasks`. Результаты доступны ограниченное время (24 часа); скачивай original после завершения, повторная отправка не служит восстановлением истёкшей ссылки. Отменить уже отправленную генерацию нельзя; остановка локального ожидания не отменяет задание сервиса.

Image-оценка в `cost_check` использует только точную signature из `tools/cost_check/pricing.json` либо явно заданную цену. Наблюдение одной конфигурации не задаёт тариф для других моделей, разрешений, quality, counts или references; video-пересчёт по секундам к нему не относится.
