# Формат попытки генерации

Спецификация попытки для [media_request](README.md): JSON запроса, замороженный пакет, отправка, состояния и восстановление. Ограничения конкретного сервиса (команды, параметры, входы, промпт) описаны в README его адаптера из [таблицы адаптеров](../media_adapters.py); согласования — в [производственном процессе](../../docs/production-workflow.md).

## Спецификация запроса

Пример структуры, **не готовый запрос на генерацию**: команду, модель, параметры и слоты брать из актуальных возможностей аккаунта (`capabilities`). Пути входов и промпта отсчитываются от папки этого JSON; абсолютные пути допустимы.

```json
{
  "schema_version": 1,
  "shot": "M32",
  "kind": "video",
  "provider": "PROVIDER_ID",
  "command": "COMMAND_FROM_CAPABILITIES",
  "model": "MODEL_FROM_CURRENT_CAPABILITIES",
  "parameters": {"duration": 6, "resolution": "1080p", "aspect_ratio": "16:9"},
  "inputs": [
    {"flag": "input", "slot": "first_image", "path": "first.png", "role": "first"},
    {"flag": "input", "slot": "tail_image", "path": "last.png", "role": "last"}
  ],
  "prompt_file": "video-prompt.txt",
  "outputs": 1
}
```

- `provider`: обязательная непустая строка — id провайдера из [таблицы адаптеров](../media_adapters.py), без учёта регистра и пробелов по краям. Значение сохраняется дословно в замороженном запросе и входит в SHA; отсутствующий провайдер не подставляется.
- `kind`: `image` или `video`. `command`, `model` — непустые строки; допустимые значения проверяет адаптер.
- Необязательный `model_selection`: объект ровно с полями `preferredModel` (`null` или непустая строка), `selectedModel` (точно совпадает с `model`) и `reason` (непустая строка). Вызывающий код выбирает модель по актуальным возможностям; инструмент только проверяет и сохраняет сведения без нормализации текста.
- `parameters`: объект аргументов команды; значения сохраняются без преобразований.
- `inputs`: локальные файлы с непустыми `flag` и `path`, необязательными `slot`, `role` и `sha256`. Необязательный `sha256` проверяется при подготовке. Сетевые URL не поддерживаются: материалы перечисляются явно и замораживаются до согласования. Дескрипторы assets с `root: "source"` перед подготовкой разрешить через `descriptor_file` из [asset_package](../asset_package/README.md).
- `prompt_file`: промпт сохраняется дословно в UTF-8; пустой промпт отклоняется. Адаптер может отклонить промпт или вернуть предупреждения.
- `outputs`: ожидаемое число результатов, по умолчанию 1.

## Пакет попытки

`prepare` работает без сети и создаёт новую папку с `request.json`, точным `prompt.txt`, входами `inputs/` и `attempt.json`; существующую папку не перезаписывает, папка появляется целиком. Одинаковые байты входов копируются один раз с сохранением всех ролей. Все пути внутри пакета относительные: перенос целой папки не меняет `request_sha256`. Поля `FROZEN_FIELDS` адаптера входят в `request.json`; `model_selection` переносится дословно только при наличии. `submit` и `resume` используют сохранённую модель и не выбирают её заново.

`attempt.json`: `schema_version`, `request_sha256`, `status`, `downloads`, после отправки `generation_id` и необязательный `credits_consumed`; `task_trace_id` — UUID v7 попытки, который общий код записывает при первом `submit`, если адаптер объявляет `TASK_TRACE_ID = True` (адаптер передаёт его сервису с каждым вызовом этой попытки, повторная отправка после `not-created` использует тот же ID); `service_status` — последний статус сервиса только из строчных латинских букв и `_`, иначе `unknown`. В журнал не записываются сырые ответы, адреса результатов и секреты.

## Отправка

`submit --confirm SHA` связывает запуск с конкретным подготовленным содержимым. Перед отправкой сверяются хеши замороженных промпта и входов, состояние `submitting` записывается до вызова адаптера, `generation_id` сохраняется сразу после ответа. Повторный `submit` запрещён, включая `submitting` и `submission_unknown`; новый платный повтор — новый пакет и отдельное согласование. Явный отказ сервиса и недоступность его программы возвращают попытку в `prepared` (отказ — с `last_rejection`); прочие сбои после начала отправки — неизвестный исход, а не доказанное отсутствие списания. Одновременная обработка одной попытки блокируется файловым замком.

## Продолжение, получение и восстановление

Статусы: `prepared`, `submitting`, `submission_unknown`, `submitted`, `running`, `outputs_pending`, `watermark_free_pending`, `downloading`, `download_pending`, `downloaded`, `failed`. Ожидающие статусы требуют продолжения того же задания, `failed` — решения пользователя.

Если отправка оборвалась без ID, исход выясняется по истории генераций сервиса: найденный оригинал загружается `attach` (`downloaded`, `manual_result: true`, ID остаётся `null`), отсутствие генерации отмечается `not-created` (`prepared`, повторный `submit` после нового согласия). Обе команды пишут решение в `unknown_outcomes: [{resolution, at}]`. Изменённые входы или запрос — новая попытка, а не правка пакета.

Оригиналы сохраняются как `original.mp4` либо `original-01.mp4`, `original-02.mp4` и далее; у изображений — `.png`, `.jpg` или `.webp` по сигнатуре полученных байтов, а не по адресу или Content-Type. Байты не перекодируются. Публикуется только полностью полученный файл; намерение записывается заранее (`pending_download`), поэтому обрыв до публикации и между публикацией и журналом восстанавливается повторным `resume` того же задания. Для изображения до публикации записываются номер, конечный путь, размер и SHA-256; при восстановлении сверяются сигнатура, расширение, размер и хеш, новая загрузка не нужна. У журналов без хеша проверяются сигнатура, расширение и размер; `.jpg` и `.jpeg` — один формат. Несоответствие останавливает получение без изменения файла. Зарегистрированные результаты повторно не скачиваются, чужой существующий файл не перезаписывается.

Полученное видео не хешируется, не исследуется через `ffprobe` и не монтируется: `downloaded` означает только сохранение и ожидание просмотра пользователем. Скрипт не обновляет assets, реестр сцен и аниматик; перенос принятого комплекта — по [правилам assets](../../templates/project/assets/README.md).
