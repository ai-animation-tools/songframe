# Закреплённые компоненты

[manifest.json](manifest.json) — встроенный реестр точных артефактов производственного CPU-пути. [manifest.go](manifest.go) читает отдельный снимок и проверяет ссылки, пути, SHA, обязательные части ML-контракта. Чтение не обращается к сети, PATH, профилю или нативной библиотеке. Реестр пока не подключён к пользовательскому API: обнаружение, установка и состояние компонентов реализуются следующим шагом.

## Состав и происхождение

| Компонент | Закрепление | Фактическая проверка |
| --- | --- | --- |
| FFmpeg/ffprobe | BtbN `n8.1.3-9-g29e619e767`, `autobuild-2026-09-30-13-08`, GPL Linux/Windows amd64 | SHA архивов совпали с исходным media-lock и GitHub assets; состав, SHA entrypoints/LICENSE, ELF/PE imports; Linux recipes |
| ORT CPU | Microsoft `1.31.0`, standalone C runtime Linux/Windows amd64 | Загруженные архивы и SHA GitHub assets, обязательные файлы, symlinks, export `OrtGetApiBase`, ELF/PE dependencies |
| Voc FT | `UVR-MDX-NET-Voc_FT.onnx` | Размер/SHA принятого lock, реальные protobuf-метаданные, IR 6 / opset 13 |
| Русский CTC + vocab | HF revision `df5ba1d9e0f9a34c44eec437b441f4ae43c842eb`, quantized ONNX | SHA обоих файлов, один input_values → logits с 39 классами, IR 7 / opset 14; 39 непрерывных vocab ID |

FFmpeg сохраняет прежние пакеты, без замены сборки или самостоятельной урезанной конфигурации. Источник recipes — SongFrame `634fd9429ba0b0cfcb984a52ce95adf8e1674635`: `tools/build_review`, `build_animatic`, `accept_shot`, `apply_montage`, `derive_shot`, `asset_package`, `video_review`, `contact_sheet`, `verify_asset_replay`, `cut_speech`, `common.py`, аудиодекодирование `song_timing`, `src/main/sources.ts`, `runtime-smoke.ts`, `linux-smoke.ts`. Поля `consumers` указывают владельцев; старый checkout для проверки manifest не нужен.

`capabilities` связывают операции с компонентами, FFmpeg features и probe. Входные видео в прежнем коде декодируются автоматически: список проверенных H.264/VP8/VP9 не является обещанием поддержать произвольный внешний codec. JPEG/WebP-обработка прежнего Pillow не превращается в требование FFmpeg. WebM здесь читается; новый WebM-экспорт не добавлен. `libmp3lame`, `anullsrc`, `apad` нужны проверкам разработки. Whisper, Qwen, CTranslate2 и CUDA в выбранный набор не входят; декодирование PCM для принятого CTC сохранено.

`recipe` сохраняет pipeline, MDX и CTC margin/adaptive принятого эксперимента. Восемь потоков — параметр первой регрессии, не обязательный default для любого компьютера. Политика CPU определяется при интеграции ML. Ручные секунды, VAD trimming и Whisper не являются входом. Произвольный `transcribe_local --filter` и вручную изменённые старые filter manifests не создают обещания конечного whitelist для всех внешних CLI-сценариев.

## Значение полей

- `bytes` — точный объём загружаемого файла; `unpacked_bytes` — сумма обычных файлов всего архива, без округления файловой системы. Для одиночной модели это размер файла.
- `install_bytes` — сумма обязательных обычных `files`. Для FFmpeg это нижняя граница: дополнительно сохраняются `doc/**`; размер каталога и место staging рассчитывает будущий установщик. В Windows ORT полный ZIP включает большой PDB, его устанавливать не требуется.
- `root` — каталог верхнего уровня архива; `files.path` и `entrypoints` относительны ему. Для отдельного файла `root` пуст. `entrypoints` задаёт роли явно: `ffmpeg`, `ffprobe`, `ort-library`, `model`, `vocab`.
- `files` — обязательный проверяемый состав с SHA/размером. Для symlink задаётся относительный `target`, без SHA содержимого; цель также обязана входить в `files`. `preserve` сохраняет лицензионные материалы; ffplay, development headers и PDB не являются обязательным runtime.
- `verified` относится к проверке байтов/метаданных. `native_status`, платформенная матрица и `license.status` отдельно показывают остаток проверки; это не состояние установки `ready`.
- `abi.required_api=27` — API закреплённого Go binding; `header_api=31` — максимум header ORT 1.31.0. Реально выбранный API определяется при загрузке. Binding может откатиться до 17; для принятой конфигурации проверяется 27.

Linux FFmpeg требует glibc 2.28. Linux ORT требует glibc 2.28, GLIBCXX 3.4.22 и CXXABI 1.3.11. Windows ORT импортирует VC++ 14 runtime и UCRT, которых нет в архиве: проверка/поддержанная установка относятся к preflight поставки. Нативный Windows-прогон не выполнялся. macOS и остальные OS/arch без подтверждённого пакета не получают подставные URL или готовность.

Binding `SetSharedLibraryPath` настраивается до первого успешного глобального Init. Ошибка Init допускает повтор; после успеха путь не меняется. Shutdown требует закрытых sessions и запрещает следующий Init. Поэтому первая установка может заработать в том же сеансе, а смена уже загруженного runtime требует перезапуска. Проверка именно скачанного standalone runtime, sessions, inference и отмены ещё предстоит; принятый эксперимент этого результата за новое приложение не даёт.

## Проверки

```sh
wails3 task check:components
sh scripts/check-media-capabilities.sh /путь/к/папке/bin
```

Первой команде не нужны FFmpeg, модели, Python или соседние репозитории. Вторая — проверка разработчика с Python 3 stdlib: принимает явную пару программ, генерирует короткие синтетические входы в `/tmp`, ограничивает процессы по времени и удаляет временную папку. Она не устанавливает компоненты и не проверяет системный WebView. Подробности фиксированных входов — [testdata/components](../../testdata/components/README.md).

При наличии распакованных пакетов и моделей можно отдельно проверить обязательные файлы, без исполнения DLL/EXE:

```sh
SONGFRAME_COMPONENT_ROOTS='{"ort-cpu-linux-amd64":"/путь/onnxruntime-linux-x64-1.31.0"}' \
  go test ./internal/components -run TestManifestArtifactFiles -count=1 -v
```

Карта может включать любой непустой набор ID из manifest; для модели значением служит папка, содержащая файл с закреплённым именем. Неизвестный ID, несовпадающий hash/размер или неверный symlink дают ошибку. Без переменной этот добровольный тест пропускается; обычные проверки остаются автономными.

## Лицензии и границы готовности

Ссылки на первичные источники находятся в `license.sources`/`evidence`. Для FFmpeg сохраняются GPL, документация и configure; полнота транзитивных notices проверяется при упаковке. Для ORT сохраняются MIT LICENSE и ThirdPartyNotices из каждого архива. Для CTC/vocab Apache-2.0 заявлена закреплённой карточкой HF; отдельного LICENSE там нет. Для Voc FT MIT заявлена проектом UVR в разделе о моделях, отдельной лицензии внутри ONNX/рядом с asset не найдено. При комплектовании сохраняются исходные тексты, карточки и атрибуция; лицензия приложения не подменяет эти условия.

Это фиксация состава и проверок. Установка из UI, обнаружение/PATH, загрузка/отмена/staging, платформенные bootstrapper, inference и ранняя поставка здесь не реализованы. Реестр не является разрешением автоматически отправлять платные запросы или запускать производство.
