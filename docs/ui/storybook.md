# Статическая витрина Go-интерфейса

Истории показывают рабочие компоненты с чистыми моделями API без настоящих Wails-сервисов, профиля, клипа, ML и платных запросов. Настройка — `frontend/.storybook/`, модели — `frontend/src/renderer/testing/`, браузерный обход — `frontend/tests/storybook/stories.spec.ts`. Витрина использует тему приложения через `createAppTheme` и изолированный ThemeModeValueProvider; история не пишет localStorage/профиль.

## Актуальность при изменении frontend и API

До реализации найдите `*.stories.tsx` затронутого компонента, родительской страницы/оболочки и их модели. В том же изменении обновите весь контур: данные, обработчики, подписки, таймеры, доступность действий и последствия. Изолированная история нового блока не доказывает его интеграцию в страницу. Новый экран без старых историй тоже получает значимые состояния. Общая заглушка «инструмент недоступен» или фиктивный успех не заменяет модель новой функции; недоступность допустима как отдельный честный сценарий.

Изменённый переход в `play` проверяет видимый итог: завершение, отказ/повтор, отмену, сохранность результата и независимые согласования в объёме задачи. Чисто визуальному состоянию не добавляйте искусственные клики. Критичные истории помечайте `tags: ['ci']`. Обход по умолчанию открывает все истории витрины, а `STORYBOOK_TEST_CI=1` — только истории с этой меткой; отдельно добавлять сценарий в набор не нужно.

Модели передаются через props/API interfaces (например WorkspaceBridge и ComponentsAPI), не запускают production adapters, generated bindings и системные диалоги. Рабочий код не импортирует истории/testing. Проверяйте повторный mount, смену темы, очистку подписок/таймеров и поздние ответы после unmount.

## Команды и приёмка

Из корня:

```sh
wails3 task check:frontend
wails3 task storybook
wails3 task check:storybook
```

`wails3 task check:ui` объединяет последние две команды. Из `frontend/` адресно: `yarn build-storybook`, затем `yarn test:storybook --grep "<группа>"`. Результат — `frontend/storybook-static`; Playwright поднимает собственный HTTP preview на `127.0.0.1:6106`, запрещает переиспользовать чужой dev-сервер и проверяет окно 1320×860. Dev-команда `yarn storybook` пригодна для разработки, но HMR/`file://` не входят в приёмку.

Для затронутых страниц проверяйте обе темы, keyboard/focus, пустое/loading/error/disabled состояния, длинные тексты и paths, sticky-панель и наблюдаемый итог действий. Если существующий сценарий покрывает только светлую тему, добавьте/выполните нужную тёмную; размер меньше 1320×860 не вводите. Общая палитра/компоновка требует полного текущего browser-набора, а не одной истории. Скриншот, finished-фаза и сборка не доказывают успешность `play`: проверяйте ошибки взаимодействий, консоль и итоговые assertions. Доступность/a11y оценивайте отдельно от переходов.

В результате перечислите обновлённые истории компонента/страницы, модели, browser-сценарии и фактический исход. Если истории не требуют изменения, объясните конкретно почему; если браузер недоступен, укажите непроверенное. Витрина не подтверждает WebKit codecs, системные диалоги, native drag-and-drop или установленный AppImage: относящиеся к задаче проверки Wails и [поставки](../../dev-skills/songframe-build/SKILL.md) выполняются отдельно.
