# Предложение производственного этапа: контракт ответа

Ответ — один JSON-документ `ProductionStageProposal` (`src/shared/production-workflow.ts` комплекса) без Markdown и текста вокруг. Имена полей регистрозависимы, других полей нет. `schemaVersion` всегда `1`; `stage` совпадает с запрошенным этапом. Приложение проверяет ответ и показывает его для согласования; несоответствие контракту делает предложение недействительным.

## description

```json
{
  "schemaVersion": 1,
  "stage": "description",
  "description": "Постановка, первый кадр, план опор и рекомендуемая модель словами",
  "requestSeconds": 7,
  "keyframes": [
    { "id": "K01", "role": "first", "timeSeconds": 0, "prompt": "Самодостаточное описание первого кадра", "referencePaths": ["source/heroes/hero.png"] },
    { "id": "K02", "role": "last", "timeSeconds": 7, "prompt": "Самодостаточное описание последнего кадра", "referencePaths": ["source/heroes/hero.png"] }
  ]
}
```

- `requestSeconds` — целое число по `settings.duration_rule`: строго больше окна для `min_supported_strictly_greater_than_window`, не меньше для `min_supported_not_less_than_window`, ровно окно для `exact_window`. Дробное окно с `exact_window` несовместимо с целой длительностью: верни понятную ошибку вместо округления.
- `keyframes`: от 2 до 20 опор по возрастанию времени. ID `K01`, `K02`, … подряд; роль `first` у первой (время `0`), `last` у последней (время `requestSeconds`), `middle` у промежуточных строго между ними. При совместимой доработке ID сохраняются.
- `prompt` каждой опоры — полный самодостаточный промпт изображения по [каркасу промптов](prompt-template.md): внешность из кастинга, действие и камера, дословная врезка непрерывности (`before` для первой и промежуточных, `after` для последней).
- `referencePaths` — только PNG/JPEG/WebP из `allowedPaths`; пути не выдумывай.

Применение описания создаёт материал для согласования; оно не принимает описание и не разрешает изображения или видео.

## prompt

```json
{ "schemaVersion": 1, "stage": "prompt", "prompt": "Полный самодостаточный видеопромпт" }
```

Видеопромпт пишется по [каркасу промптов](prompt-template.md) на основе принятого описания и опор, с реальными входами. Ранее принятые опоры остаются входом; принятие нового промпта не подразумевается.

## request

```json
{
  "schemaVersion": 1,
  "stage": "request",
  "request": {
    "model": "идентификатор-из-переданных-capabilities",
    "command": "image_to_video",
    "parameters": { "duration": 7, "resolution": "1080p", "prefer_multi_shots": false },
    "inputs": [
      { "flag": "input", "slot": "first_image", "path": "plan/batches/M01-attempt-01/frames/K01.png", "role": "first" },
      { "flag": "input", "slot": "tail_image", "path": "plan/batches/M01-attempt-01/frames/K02.png", "role": "last" }
    ],
    "outputs": 1
  }
}
```

- `command`: `text_to_video`, `image_to_video`, `omni_ref_video` или `motion_control`; только подтверждённая переданными `capabilities` комбинация команды и модели.
- `parameters`: точные параметры из `capabilities` и настроек проекта; `duration` равна согласованному `requestSeconds`. Не добавляй флаги, отсутствующие в объявлениях модели. Промпт, модель и файлы в `parameters` не передаются: промпт берётся из принятого файла, файлы — только через `inputs`.
- `inputs`: `flag` из `input`, `image`, `tailImage`, `audio`, `video`; `path` — только из `allowedPaths`; `slot` и `role` по необходимости. Опоры в роли первого и последнего кадров, референсы сущностей — с ролями из промпта.
- `outputs` — согласованное число результатов, без дополнительных платных вариантов.

Это черновик: приложение само подбирает совместимую модель по объявлениям, готовит замороженный запрос, таблицу и стоимость. Отправка возможна только отдельным решением пользователя по точному запросу; изменённый запрос согласуется заново.

## frames

Этот этап задание не выполняет. После принятия описания приложение передаёт промпты и референсы опор выбранному генератору изображений (отдельному заданию Codex с `image_gen` или запросу Kling image на одну опору) и регистрирует полученные изображения как непринятых кандидатов; пользователь утверждает их отдельно.
