# Формат запроса Kling

Спецификация попытки для [kling_request.py](kling_request.py): JSON запроса, замороженный пакет, отправка, состояния и восстановление. Команды и условия запуска — в [README](README.md), согласования — в [производственном процессе](../../docs/production-workflow.md), выбор модели по актуальным возможностям — в [промпте производства](../../skills/ai-clip-scene/SKILL.md).

## Контракт

### Спецификация запроса

Пример структуры, **не готовый запрос на генерацию**: `MODEL_FROM_CURRENT_CAPABILITIES`, длительность, параметры и слоты заменить значениями из актуальных возможностей аккаунта (`capabilities`). Пути входов и промпта отсчитываются от папки этого JSON; абсолютные пути допустимы.

```json
{
  "schema_version": 1,
  "shot": "M32",
  "kind": "video",
  "provider": "kling",
  "command": "image_to_video",
  "model": "MODEL_FROM_CURRENT_CAPABILITIES",
  "parameters": {
    "duration": 6,
    "resolution": "1080p",
    "aspect_ratio": "16:9",
    "imageCount": 1,
    "enable_audio": false,
    "prefer_multi_shots": false
  },
  "inputs": [
    {"flag": "input", "slot": "image_1", "path": "first.png", "role": "first"},
    {"flag": "input", "slot": "image_2", "path": "last.png", "role": "last"}
  ],
  "prompt_file": "video-prompt.txt",
  "outputs": 1
}
```

- `provider`: обязательная непустая строка, задающая сервис запроса; адаптер Kling принимает `kling` без учёта регистра. Значение сохраняется дословно в замороженном запросе и входит в SHA. Отсутствующий провайдер не подставляется по команде или имени инструмента.
- `kind`: `image` или `video`. Команды: `text_to_image`, `image_to_image`, `text_to_video`, `image_to_video`, `omni_ref_video`, `motion_control`.
- Необязательный `model_selection`: объект ровно с полями `preferredModel`, `selectedModel`, `reason`. `preferredModel` — `null` либо идентификатор из букв ASCII, цифр, `_`, `.` и `-`; `selectedModel` точно совпадает с `model`, `reason` — непустая строка после проверки пробелов. Пример: `{"preferredModel":"preferred-model","selectedModel":"MODEL_FROM_CURRENT_CAPABILITIES","reason":"Предпочитаемая модель не поддерживает нужную длительность."}`. Вызывающий код выбирает модель по актуальным возможностям аккаунта; инструмент только проверяет и сохраняет переданные сведения, без нормализации текста причины.
- `parameters`: имена CLI-флагов без `--`; строки, числа, bool и JSON-массивы/объекты передаются без shell. Модель и флаги не подменяются догадками или сохранёнными тарифами; `poll`, флаги авторизации и файловые входы здесь запрещены. Для видео на `kling-video-v3_0` и `kling-video-v3_0_omni` обязателен `prefer_multi_shots` (для единого плана `false`), на `kling-video-v4_0` — `resolution`. Актуальные аргументы и слоты выводит `capabilities`.
- `inputs`: локальные файлы с `flag=input` и именованным `slot` **либо** с флагами `image`, `tailImage`, `audio`, `video` без `slot`; способы не смешивать. Для липсинка включить точный WAV в поддерживаемом входе; существующие Elements задавать только согласованными параметрами модели. Несколько `inputs` не означают временные keyframes: порядок, роли и тайминг выражаются форматом выбранного режима (слоты моделей — в [промпте производства](../../skills/ai-clip-scene/SKILL.md#выбор-модели-и-запроса-этап-request)). Поля `workflow.json`, например `time_seconds`, схема не принимает; `imageCount` — число результатов, а не опорных кадров. Необязательный `sha256` входа проверяется при подготовке. Сетевые URL не поддерживаются: материалы перечисляются явно и замораживаются до согласования.
- `prompt_file`: промпт сохраняется дословно в UTF-8; начало, которое CLI может принять за флаг `--...`, отклоняется. Промпт длиннее 2 500 символов подготавливается, но `prepare` возвращает предупреждение в `warnings`: сократить до согласования таблицы.
- `outputs`: ожидаемое число результатов, от 1 до 9; при указанном `imageCount` они совпадают. У обоих медиа приоритет имеют `urlWithoutWatermark` / `url_without_watermark`. Для видео сохраняются только эти адреса; без них обычный `url` не скачивается и попытка остаётся в `watermark_free_pending` до продолжения того же ID. Для изображения при отсутствии явного адреса без логотипа допустим исходный `url` сервиса; сам по себе он не подтверждает отсутствие логотипа. Содержимое изображений не анализируется, логотипы не удаляются и не обрезаются.

Дескрипторы assets с `root: "source"` перед подготовкой разрешить через `descriptor_file` из [asset_package](../asset_package/README.md) и передать путь в `inputs[].path`: `root` — поле контракта assets, а не этой спецификации. Попытка замораживает входы; при переносе принятого результата в assets общие референсы вновь адресуются из `source`.

### Пакет попытки

`prepare` работает без сети и создаёт новую папку с `request.json`, точным `prompt.txt`, входами `inputs/` и `attempt.json`; существующую папку не перезаписывает. Выводит полный промпт, параметры, роли/хеши входов и `request_sha256` для таблицы согласования — показывать замороженные данные, а не изменяемые исходные пути. Пакет содержит хеши промпта и всех входов; одинаковые байты копируются один раз с сохранением всех ролей. Папка попытки — внутри `plan/batches`, `plan/awaiting` или `/tmp`, сами корни партий и очереди запрещены; отложенная попытка обычно лежит в `plan/awaiting/Mxx/request`. Все пути внутри пакета относительные: перенос целой папки не меняет `request_sha256` и не требует повторной подготовки.

Если спецификация содержит `model_selection`, объект дословно переносится в замороженный `request.json` и входит в `request_sha256`. Изменение причины выбора требует новой попытки и согласования. При отсутствии поля оно не добавляется: базовый запрос сохраняет только обязательные поля текущего формата, включая `provider`. `submit` и `resume` используют сохранённую модель и не выбирают её заново, не переписывают причину выбора.

### Отправка

`submit --confirm SHA` связывает запуск с конкретным подготовленным содержимым; условия разрешения — в [README](README.md#контракт). Перед отправкой сверяются хеши замороженных входов, состояние `submitting` записывается до вызова CLI, `generation_id` сохраняется сразу после ответа. Повторный `submit` попытки запрещён, включая состояния `submitting` и `submission_unknown`; новый платный повтор — новый пакет и отдельное согласование. Отсутствие CLI обнаруживается до отправки и оставляет попытку подготовленной; ошибка, таймаут или непонятный ответ после начала отправки — неизвестный исход, а не доказанное отсутствие списания. Одновременная обработка одной попытки блокируется файловым замком.

### Продолжение, получение и восстановление

`resume` опрашивает только сохранённый ID: по умолчанию один раз, с `--wait-seconds` — повторно в пределах 60 секунд с шагом `--interval`. CLI-вызов ограничен `--timeout` (по умолчанию 60 секунд), который может добавиться к ожиданию. `status` читает только локальный журнал. `--cli` выбирает другой исполняемый файл, прежде всего подставной CLI в тестах.

Если отправка оборвалась без ID, сначала установить его штатными средствами Kling, убедиться, что он относится к этой попытке, и привязать без новой отправки: `resume --work-dir … --generation-id KNOWN_GENERATION_ID`. ID не угадывать; привязка разрешена только для неизвестной отправки, существующий ID не заменяется. Изменённые входы или запрос — новая попытка, а не правка подготовленного пакета.

Оригиналы сохраняются как `original.mp4` либо `original-01.mp4`, `original-02.mp4` и далее; у изображений — `.png`, `.jpg` или `.webp` по сигнатуре полученных байтов. Расширение адреса CDN и HTTP Content-Type не задают формат файла: opaque/extensionless URL и JPEG по адресу `.png` сохраняются с фактическим расширением. Оригинальные байты не перекодируются. Публикуется только полностью полученный файл; намерение скачать записывается заранее, поэтому обрыв до публикации и обрыв между публикацией и обновлением журнала восстанавливаются повторным `resume` того же задания, при истёкшем URL он получает свежий адрес. Для изображения сначала скачивается временный raw-файл, затем до публикации записывается `pending_download` с номером, конечным путём, размером и SHA-256. При восстановлении уже опубликованного изображения сверяются сигнатура, расширение, размер и сохранённый хеш; новая загрузка не требуется даже после смены подписанного URL. У прежних журналов без хеша проверяются сигнатура, расширение и записанный размер; `.jpg` и `.jpeg` обозначают один формат. Несоответствие расширения сохранённому оригиналу останавливает получение без переименования или изменения файла. Зарегистрированные результаты повторно не скачиваются, чужой существующий файл не перезаписывается.

В журнал не записываются сырые ответы, подписанные адреса и секреты. Полученное видео не хешируется, не исследуется через `ffprobe` и не монтируется: `downloaded` означает только сохранение и ожидание просмотра пользователем. `watermark_free_pending` и `outputs_pending` требуют продолжения того же задания, `failed` — решения пользователя. Скрипт не обновляет assets, реестр сцен и аниматик; перенос принятого комплекта — по [правилам assets](../../templates/project/assets/README.md), после него рабочая попытка очищается.

## Почему

`prefer_multi_shots` обязателен для `v3_0`: сервис по умолчанию включает авто-раскадровку, и единый план без явного `false` получает внутренние склейки. `resolution` обязателен для `v4_0`: без него сервис отдаёт 720p. Предел 2 500 символов — документированный предел API Kling.
