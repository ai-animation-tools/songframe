# Тексты интерфейса

Текущий этап — централизация русских текстов. Переключение языка, переводы и редактура формулировок выполняются отдельными задачами. Первый перенос сохраняет фразы, пробелы, пунктуацию, параметры, переходы и поведение дословно.

## Источники и формат

Общие подписи и сообщения принадлежат чистым TypeScript-модулям `src/shared/texts/`:

- `common.ts` — общие действия, сообщения, оболочка и предусловия страниц;
- `navigation.ts` — названия страниц и блоков, падежные формы; технические маршруты и якоря остаются у навигации;
- `<домен>.ts` — тексты рабочего процесса, общие для main и renderer;
- `agent-instructions.ts` — общая обвязка инструкций; особенности конкретного агента остаются в его реестре;
- `components.ts` — общие компоненты: загрузка файлов, просмотр изображений, состояния планов, редактор состояния и карточки заданий;
- `production.ts` — страница производства, подписи попыток/предложений и main-сообщения пакетов, опор, согласований и приёмки;
- `scenario.ts` — редакторы сценария, сравнение предложений, подтверждения сохранения и main-ошибки проверки/применения сценария;
- `montage.ts` — ручной монтаж, материалы, шкала, подтверждения, main-проверки, восстановление и отдельное окно плеера;
- `project.ts` — обзор проекта, настройки генерации, проверка готовности и пакет для монтажёра;
- `sources.ts` — исходники, обложка, типы референсов и их описание, main-проверки файлов/манифеста и сообщения временной генерации обложки;
- `cast.ts` — сущности кастинга, образы и редактор словаря свойств, main-проверки структуры/сохранения и дополнение из исходников;
- `scenes.ts`, `animatic.ts` — обзор сцен, сравнение материалов, плеер, main-диагностика свежести и принятие аниматика;
- `application.ts` — общие сообщения и диалоги обвязки IPC, системного открытия файлов и восстановления при запуске; сами операции и каналы остаются у главного процесса;
- `settings.ts`, `environment.ts` — настройки текстового агента, аккаунт/лимиты и диагностика среды, включая main-проверки настроек, чтение аккаунта и моделей, Python и медиапоставку;
- `agents.ts` — общая main-диагностика CLI, ошибки JSONL и отображаемые фазы заданий; команды, промпты и особенности конкретных агентов остаются у адаптеров;
- `projects.ts`, `jobs.ts`, `help.ts` — создание/история и main-статусы проектов, сообщения заданий, обвязка журнала и справки; статьи справочника остаются в `HelpPage/glossary.ts`;
- `local-files.ts` — общие ошибки чтения/атомарной записи файлов состояния; `diagnostics.ts` — пользовательский аварийный диалог, без содержимого журналов и отчёта разработчика;
- `media.ts` — общая main-диагностика каталога моделей, валидации/подбора запроса, согласования агентных изображений и сохранения оригиналов; конкретные сервисы передаются параметрами;
- `technical.ts` — видимые подписи без кириллицы (фильтр MP3, проценты); расширения файлов и числовые алгоритмы остаются данными/кодом;
- `ai-access.ts`, `generation.ts`, `providers.ts` — доступность исполнителей, стоимость/согласование и нейтральные подписи реестров;
- `timing.ts` — разметка песни, плеер, установка и выбор локальной модели Whisper, рекомендации ресурсов и загрузка, main-проверки разметки и диагностика локального распознавания;
- `lyrics.ts`, `project-data.ts` — пользовательские подсказки/ошибки текста песни и отображаемые подписи проекта. Сохраняемые значения данных в эти словари не переносятся.

Импортируйте домен напрямую: `import { checksTexts } from '@shared/texts/checks'`. Обязательного общего объекта или barrel нет. Словари содержат константы и функции с типизированными параметрами, без React, DOM, Node/Electron API, файловой системы, побочных эффектов и импортов из main/renderer. Домен может использовать `common` и `navigation`; циклы между доменами не допускаются. Одинаковые общие действия, поля, управление плеером и сообщения имеют один источник в `common`; прежние доменные ключи могут ссылаться на него. Случайно совпавшие фразы разных процессов не объединяются только из-за одинакового написания.

```ts
// Целая фраза позволяет править текст без поиска его частей по компонентам.
export const exampleTexts = {
  remove: ({ filename }: { filename: string }) => `Удалить файл «${filename}»?`
} as const;
```

Ключи называйте по назначению фразы, а не по номеру строки или имени переменной. Функция возвращает целую фразу; не собирайте предложение из отдельных слов или окончаний. При нескольких параметрах используйте именованный объект. Согласование чисел принадлежит существующим `plural`/`countLabel` из `src/shared/plural.ts`; сохранение прежней грамматики при первом переносе имеет приоритет перед исправлением склонения.

Даже подписи только одной страницы хранятся в доменном словаре: это исключение из правила локальности страниц. Hooks, типы, функции и компоненты страницы остаются в её папке. Не создавайте вторую таблицу подписей рядом с уже перенесённой.

## Владельцы исключений

- Названия, команды и особенности текстовых агентов и медиапровайдеров остаются в реестрах и адаптерах. Общий словарь принимает название параметром и не перечисляет сервисы.
- Содержимое справочника остаётся в `HelpPage/glossary.ts`; общая обвязка страницы переносится отдельно.
- Промпты, инструкции провайдеров и скиллы производства остаются у своих нынешних владельцев.
- Регулярные выражения, ID, маршруты, якоря, маркеры и строки формата данных остаются в контракте/коде.
- Журналы, smoke-проверки, сообщения Python-инструментов и внешних программ не входят в каталог UI. Видимую пользователю диагностику классифицируйте отдельно.
- Тесты, fixtures и `testing/` могут содержать независимые ожидаемые фразы и образцы данных.

Не исключайте смешанный файл целиком ради промптов или журнала. Для действительно служебного литерала в завершённом файле допустимо узкое отключение `no-restricted-syntax` с русским объяснением, как у журнала в `task-notifications.ts`. Оно не отключает остальные правила ESLint.

## Поведение, зависящее от текста

До переноса найдите производителей и потребителей строки. Сейчас режимы уведомлений различаются по заголовку: `checksTexts.reviewPlanOnlySuffix` используется и при создании задания, и при классификации уведомления, `notificationsTexts.animaticCheckTitle` — при создании и распознавании проверки аниматика. Одного `job.kind` недостаточно. Общий ключ сохраняет прежнее поведение; переход к явному режиму требует отдельной задачи.

В `DestructiveButton` default и сравнение, выбирающее значок удаления, используют один `commonTexts.delete`. Изменение алгоритма выбора значка не является частью переноса.

`LinkedText` распознаёт кавычки, падежные формы и контекст предложения, включая название провайдера рядом со «Средой». Изменение текста может менять ссылку. Проверяйте итоговые маршруты, якоря, параметры текущей страницы и неизменность текста при склейке сегментов. Служебные строки, сохраняемые в данных и разбираемые регулярками, нельзя незаметно превращать в редактируемые UI-подписи.

`ScenesPage/components/ShotStateBlock.tsx` фильтрует вычисленные main-данные по служебному `BRIEF_STATE_UNSET_PREFIX` из `shared/types.ts` рядом с контрактом `BriefResult`. Производитель в `main/scenario.ts` использует тот же маркер. Формат `continuity_brief`, разделители строк и префикс остаются данными, их не редактируют как подписи UI. Общая константа сохраняет прежнюю строку и фильтрацию без нового поля протокола.

В `production-workflow.ts` доступность image-опор исключает проблему настроек видео через `startsWith`. `productionTexts.main.workflow.videoSettingsRequired` и `videoSettingsIncomplete` используют один префикс словаря. Менять его только у производителя или только у фильтра нельзя; новая проверка подтверждает, что отсутствие видеоисполнителя не блокирует отдельно настроенные опоры.

Main продолжает возвращать готовую строку через прежние поля и `Error.message`. Централизация не требует изменения IPC, JSON внутри ошибок или нового протокола.

## Текст с элементами React

Обычная строка или функция предпочтительны. Ссылки на страницы и блоки передавайте существующему `LinkedText`.

Смешанный JSX используется в `SettingsPage/components/AgentInstructions.tsx`, где команда CLI остаётся элементом `<code>`, и в `ProductionPage/components/DerivedShotNotice.tsx`, где код исходного плана остаётся ссылкой. Целая фраза словаря содержит именованный слот `{command}` или `{source}`; общий `components/SlottedText.tsx` подставляет ReactNode. На странице проекта слот сохраняет элемент даты проверки, а в настройках Whisper — ссылки на инструкции CUDA и cuDNN. В сценах и аниматике слоты сохраняют жирные подписи постановки и дату сборки; в среде — nullable-путь и ссылку входа, в справке — подсветку синонимов и ссылки примера. Он сохраняет порядок и повторения, оставляет неизвестный слот видимым, учитывает собственные ключи объекта, допускает явно пустое значение и не разбирает HTML или вложенные подстановки. Пользовательские строки экранирует React. Помощник перенесён из настроек в общие компоненты после появления второго реального потребителя; расширять его до глобальной подсистемы шаблонов не требуется.

## Контроль и приёмка

В `eslint.config.mjs` запрет кириллических `JSXText`, `Literal` и декодированных `TemplateElement` включён на весь `src/**/*.{ts,tsx}`, включая preload и вложенные адаптеры. Исключения области — сами словари `src/shared/texts/**`, статьи `HelpPage/glossary.ts`, тесты, `testing/` и служебные `main/linux-smoke.ts`/`runtime-smoke.ts`. Общие сообщения всех страниц, main и адаптеров перенесены; остатки и владельцы исключений проверены отдельно. Конкретный провайдер не является основанием исключать смешанный файл целиком. Не включайте предупреждения на незавершённую область: `yarn lint` использует `--max-warnings 0`.

Оставшиеся служебные строки в завершённых областях имеют точечные исключения с русской причиной:

- `media-providers.ts` — конкретные особенности провайдеров;
- `types.ts` — исходные типы, записываемые в `source/manifest.json`, и служебный префикс формата `BriefResult`;
- `timing-sections.ts` и `timing-verification.ts` — сохраняемые имена и заметки музыкальной карты, включая фразы рядом с разбирающей их регуляркой;
- `components/searchText.ts` — техническая замена букв при поиске;
- `state.tsx` — ошибка программного контракта hook;
- `main/task-notifications.ts` — журнал сбоя доставки.
- `ScenarioPage/useScenario.ts` — распознавание частей песни; `ScenarioPage/components/SceneList.tsx` — маркер незаполненной постановки;
- `MontagePage/sourceThumbnails.ts` — служебные причины отказа очереди превью, которые не показываются пользователю;
- `SourcesPage/components/CoverGenerateDialog.tsx` — исходный промпт обложки, который отправляется исполнителю;
- `TimingPage/timing.ts` и `TimingPage/TimingPage.tsx` — сохраняемые status, clock и заметка ручной разметки; `TimingPage/useTimingPlayer.ts` — русская горячая клавиша «м»;
- `HelpPage/search.ts` — техническая нормализация букв для поиска по статьям;
- `main/production.ts` — SHA-сентинелы отсутствующих файлов/результата; `production-proposal.ts` — промпт проверки совместимости;
- `main/production-workflow.ts` и `keyframe-images.ts` — инструкции/JSON-формат ответа агента, добавление замечания в замороженный промпт и протокол аргумента `--middle`;
- `main/scenario.ts` — данные формата `continuity_brief`; `scenario-workflow.ts` — инструкции сценарному агенту;
- `main/ipc.ts` — журнал очистки временной обложки и предлагаемое имя экспортного файла как значение пути операции сохранения;
- `main/cast.ts` — начальные свойства и сущность мира из `FALLBACK`, сохраняемые в `plan/cast.json`;
- `main/timing.ts` — сохраняемые `status` (вместе с разбирающей его регуляркой) и `clock` в `plan/audio/timing.json`;
- `main/media-runtime.ts` — составной маркер ожидаемых файлов модели `vocabulary.json или vocabulary.txt`;
- `main/agent-manager.ts` — промпты, обвязка stdin и записи журнала; `agent-history.ts` — перехватываемые внутренние причины отказа чтения и журнал повреждённой записи;
- `main/agent-protocol.ts` — служебные маркеры редактирования секретов; `agent-adapters.ts` и `agent-probes.ts` — особенности потокового протокола и разные подтверждения входа конкретных CLI;
- `main/agent-account.ts` — инструкция повторного входа Codex; `claude-account-transport.ts` и `codex-account-transport.ts` — специфичные отказы протокола и перехватываемые ошибки служебных команд; `codex-models.ts` — ошибки формата и пагинации каталога конкретного агента.

К новым исключениям общих main-модулей относятся:

- `projects.ts` — содержимое служебного `GIT-INIT-FAILED.txt`;
- `jobs.ts` — внутренние перехватываемые причины чтения истории и записи журнала шагов/доставки событий; отображаемый `job.error` берётся из словаря либо внешнего вывода;
- `diagnostics.ts` — формат журнала/копии задания и отчёта разработчика, включая цепочку `Причина:`; `app-diagnostics.ts` — записи событий Electron и сеанса, при этом текст аварийного диалога берётся из словаря;
- `desktop-notifications.ts` и `index.ts` — технические сообщения доставки/запуска/очистки; пользовательские диалоги восстановления и запуска централизованы;
- `provider-guides.ts` — заголовок разбираемого раздела документа и обвязка провайдерных инструкций в промпте;
- `providers/codex/codex-cover-runner.ts` — промпт встроенному `image_gen` и подсказка о доступности этого инструмента; общие ошибки/название задания обложки принадлежат `sources`;
- `providers/codex/codex-image-provider.ts` — диагностика конкретного каталога моделей; общие ошибки подготовки/согласования изображений принадлежат `media`;
- `providers/kling/index.ts` — ограничение параметра `watermark`, особенности входа/поставки клиента и служебный Python smoke; общие сообщения входа принадлежат `providers`, ожидание проверки — `environment`.

Служебные HTTP-ответы локального протокола файлов, команды, ID, имена полей и форматы данных не становятся UI-подписями даже без кириллицы. Имя приложения SongFrame, названия технологий в распознавании ссылок, примеры кодов/путей, часы/timecode, locale и клавиши сохраняют своих владельцев. Подписи CPU/RAM/FPS/OK и единицы размеров принадлежат соответствующим доменам. MUI получает русские доступные имена через `ruRU` в общей теме.

Регулярка распознавания ошибки внешнего CMD остаётся в `main/environment.ts` как контракт stderr. Встроенный Python script тоже остаётся у своего владельца; только отображаемый fallback `доступен` подставляется из словаря через строковую сериализацию, без изменения протокола stdout/stderr.

Правило не определяет назначение текста и не видит все подписи без кириллицы. Проверяйте оставшиеся литералы вручную, включая единицы, доступные имена и `ok`. Словари сохраняют остальные проверки ESLint. Нулевой остаток кириллицы сам по себе не доказывает завершение.

Ожидаемые тексты и маршруты в тестах должны быть независимы от словаря и таблиц реализации. Для параметризованных фраз проверяйте целый результат, кавычки, пути и спецсимволы; для новых функций чисел — 0, 1, 2, 5, 11, 21, отрицательные и дробные значения. Для слотов проверяйте видимый текст, повторения, отсутствие значения, ссылки и безопасный вывод. Перенос не является поводом менять текущую грамматику.

Перед приёмкой пакета выполняйте `yarn format:check`, `yarn lint`, `yarn typecheck`, `yarn test`, `yarn build` и проверяйте затронутые состояния в интерфейсе, когда окружение позволяет. Указывайте ограничения ручной проверки. Storybook, сборка установщиков, платные запросы и нативный Windows-прогон не подразумеваются централизацией текстов.
