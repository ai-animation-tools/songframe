# Проверка видео и статусы

Читать при порученной проверке конкретного видео и для определений статусов. По умолчанию результат Kling сохраняется в файл, сопровождается технической сводкой `contact_sheet` и чек-листом непрерывности и передаётся пользователю через приложение: он смотрит и решает сам. Разрешение сгенерировать, сохранить или показать видео, а также `retry` и `regenerate`, не разрешают перечисленные ниже проверки; разрешение проверить одну попытку не распространяется на повтор.

## Чек-лист непрерывности на этапе 5

Сверка с записанным состоянием входит в этап 5 без отдельного поручения: первый кадр из `contact_sheet` проверяется по вопросам `continuity_brief Mxx`, последний по `continuity_brief Mxx --phase after`. В карточке называются только несоответствия словами из чек-листа («Одежда: красная куртка? На кадре куртка синяя»). Это не поиск дефектов генерации и не оценка движения.

## Проверка видео только по явному поручению

Техническая проверка: `ffprobe`/`ffmpeg` или существующий инструмент комплекса; размеры, пропорции с учётом pixel aspect ratio, длительность, частота кадров, аудиопотоки, полное декодирование, SHA-256 при необходимости фиксации. Имя файла и ответ сервиса не доказывают фактические параметры. Апскейл, поля и локальную смену частоты кадров не выдавать за нативное качество.

```bash
ffprobe -v error -show_format -show_streams -of json ORIGINAL_VIDEO
ffmpeg -v error -i ORIGINAL_VIDEO -f null -
```

Монтажный участок определяется только при порученном подборе или по указанию пользователя: начало включительно, конец исключительно, длительность по числу кадров на целевой частоте; если окно не представимо целым числом кадров, показать расхождение и согласовать окно, а не сдвигать склейку молча. Выборки кадров хранить во временной папке; последний декодируемый кадр не «кадр за секунду до конца».

Визуальный анализ: просмотреть видео целиком в движении, спорные места замедленно; статические выборки не подтверждают отсутствие временных дефектов. Если среда не позволяет смотреть движение, сказать об этом и попросить пользователя оценить эти пункты.

- Лицо и личность стабильны; зрачки в пределах глаз, без скачков и дрейфа взгляда.
- Кисти, конечности и контакты не меняют анатомию; нет лишних людей, срастаний, проникновения в поверхности, внезапного исчезновения предметов.
- Действие, скорость, география и камера соответствуют плану; нет скрытых склеек, реверса, мерцания, пульсации масштаба, деформации фона.
- Речь не теряет слов, синхронизация губ проверена по видео и звуку, если входит в задачу.
- Стыки: конец предыдущего участка → начало текущего, конец текущего → начало следующего, с учётом задуманных пропусков и смен ракурса.

Если действие завершилось за пределами окна или запаса не хватает, показать проблему; не ускорять речь, не добавлять стоп-кадр, не сдвигать склейку без разрешения. Производные сохранять отдельно, оригинал не заменять обрезкой. Если поручена только техническая проверка, художественный анализ не добавлять, и наоборот.

## Статусы сцен

Вычисляет [shot_status](../../../tools/shot_status/README.md); таблицы для `list=` печатаются из его вывода, файлы ради списка не меняются. Определения:

| Статус | Критерий |
| --- | --- |
| `planned` | Постановка есть, работа не начата по доступным данным |
| `progress` | Есть пакет очереди, попытка в `plan/batches`, полученный результат, незавершённое исправление или отметка в реестре работ; выбранного видео в assets нет. Этап берётся из `attempt.json`, иначе из `workflow.json` |
| `completed` | Есть `assets/shots/Mxx/manifest.json`; незавершённая альтернатива показывается примечанием и готовность не отменяет |
| `unknown` | Файлы пакета повреждены или этап не определён; не выдавать за доказанно неготовую сцену |

Принятые изображения без принятого видео и принятая генерация без выбранного участка (`edit_review`) остаются `progress`. Пакет с ожидающим вопросом (`pending_decision`) тоже `progress` на своём этапе. Включение в полную сборку и её принятие отдельные признаки. Порядок кандидатов `next` массив `scenes` реестра, то есть монтажная шкала; при непустой очереди без явного Mxx сначала предлагается выбор из очереди.

## Журнал

`workflow.json` ведёт `shot_workflow` (этап, кандидаты опор, ожидающий вопрос, последний ответ), `attempt.json` ведёт `kling_request`, рецепт пробы `build_review`; состав assets его контракт ([assets/README.md](../../../templates/project/assets/README.md)). В журналах нет сырых ответов, подписанных адресов, секретов, цитат и хронологии переписки. Проба не является принятием; `downloaded` это получение файла и ожидание просмотра; принятие сцены не разрешает пересборку аниматика ([plan/animatic/README.md](../../../templates/project/plan/animatic/README.md)), commit или push.
