# kling_request

Адаптер провайдера генерации `kling` для [media_request](../media_request/README.md): знает команды и ограничения Kling, собирает вызовы MCP-сервера Kling собственным клиентом, разбирает ответы, выбирает адреса оригиналов без логотипа, читает остаток аккаунта, выполняет вход и хранит таблицу цен. Самостоятельной командной строки нет: приложение вызывает `media_request` и `cost_check`, а те находят адаптер по [таблице](../media_adapters.py). Состояние попытки, SHA, замок и сохранение оригиналов ведёт общий код. Платные запросы ради проверки адаптера не запускать: [тесты](#тесты).

## Возможности

- Команды по видам медиа: `image` — `text_to_image`, `image_to_image`; `video` — `text_to_video`, `image_to_video`, `omni_ref_video`, `motion_control`.
- `capabilities(kind)` проверяет наличие команды через `tools/list` и читает объявления моделей аккаунта из `who_am_i {tools: [команды вида]}`: аргументы (длительности, разрешение, пропорции, `prefer_multi_shots`, звук), слоты кадров и ограничения (`combined_item_cap`, `combined_item_caps`, `element_support`). Один свежий снимок `tools/list` + `who_am_i` на вызов независимо от числа команд. Неизвестная или повреждённая команда попадает в `problems`, ошибка общего discovery — исключение без сырого ответа. Наружу возвращаются только объявления команд, без полей аккаунта. Отсутствие объявлений для отдельной команды не подтверждает проблему входа в аккаунт.
- `login(open_browser=True, timeout=300)` → `{"ok", "message"}` и `auth_status(timeout=30)` → `{"status": "authenticated" | "unauthenticated" | "unknown", "message"?}`: `authenticated` — только после успешного `who_am_i`, без сохранённого входа или с отвергнутым токеном — `unauthenticated`, без сети или при ошибке сервера — `unknown`. Их вызывают `media_request login` и `auth-status`.

## Ограничения запроса

- `command` из списка выше, `kind` соответствует команде (`*_image` — изображение), `model` и `preferredModel` выбора — идентификаторы из букв ASCII, цифр, `_`, `.` и `-`.
- `parameters`: имена аргументов модели; строки передаются как есть, числа, bool и JSON-массивы/объекты — компактным JSON. `prompt`, `model`, `rationale`, `taskTraceId`, `poll`, флаги авторизации (`token`, `credential`, `password`, `base_url`) и файловые входы здесь запрещены. Для видео на `kling-video-v3_0` и `kling-video-v3_0_omni` обязателен `prefer_multi_shots` (для единого плана `false`), на `kling-video-v4_0` — `resolution`.
- `outputs` от 1 до 9; при указанном `imageCount` они совпадают (`imageCount` — число результатов, а не опорных кадров).
- `inputs`: обязательны для команд не `text_to_*`; только `flag=input` с именованным `slot` из объявления модели, слот не повторять. Короткие флаги `image`/`tailImage`/`audio`/`video` приложение раскрывает в слоты до фиксации SHA; вход без слота отклоняется до создания папки, а уже подготовленная попытка с таким входом — до отправки (попытка остаётся `prepared`). Порядок, роли и тайминг выражаются форматом выбранного режима; для липсинка включить точный WAV в поддерживаемом входе.
- Промпт передаётся отдельным аргументом `prompt` без изменений. Промпт длиннее 2 500 символов (`PROMPT_WARNING_CHARS`) готовится, но попадает в `warnings`; тот же предел `shot_workflow approve-prompt` берёт у адаптера для предупреждения при утверждении промпта.
- В замороженный запрос добавляется `video_without_watermark: true` (входит в SHA).

## Отправка и получение

- `TASK_TRACE_ID = True`: общий `attempt.submit` записывает в `attempt.json` UUID v7 попытки `task_trace_id`; клиент передаёт его как `taskTraceId` во всех вызовах попытки (загрузки, отправка, опрос).
- `submit` делает `initialize`, загружает локальные входы (`file_upload` → multipart на адрес тикета) и один `tools/call <command>` с конвертом `{model, arguments: [{name: "prompt", value}, {name, value: строка}…], inputs: [{name: slot, inputType: "URL", url}], rationale: "", taskTraceId}`; у `text_to_*` без входов поле `inputs` не передаётся. Таймаут вызова генерации — 300 с.
- Классификация: нет входа, нет соединения до отправки, сбой `initialize` или загрузки входа — `NotSubmitted` (попытка остаётся `prepared`, задание не создано); `isError` инструмента генерации — `RejectedRequest` (явный отказ, например «Invalid parameters» или перегрузка сервера); HTTP-ошибка, ошибка JSON-RPC, таймаут или обрыв после отправки, ответ без `generationId` — неизвестный исход. `SONGFRAME_KLING_DEBUG_FILE` дописывает при неизвестном исходе тип ошибки, HTTP-статус и тело ответа (без заголовков и токенов) в явно указанный файл вне проекта.
- `poll` вызывает `query_tasks {generationId}`. Статусы `completed`, `partial_completed`, `succeed(ed)`, `success` — успех; `failed`, `cancelled`, `rejected`, `error` — `failed`; прочие — `running`. Результаты отбираются по `contentType` вида медиа; их меньше `outputs` — `outputs_pending`.
- У обоих медиа приоритет имеет явный `urlWithoutWatermark` / `url_without_watermark`. Видео без такого адреса остаётся в `watermark_free_pending`, обычный `url` не скачивается; продолжение ждёт тот же ID. Для изображения при отсутствии явного поля используется исходный `url` сервиса: сам адрес не подтверждает отсутствие логотипа, адаптер не исследует изображение и не удаляет логотипы.
- `fetch` скачивает только HTTPS-адрес и сверяет размер с `Content-Length`.
- `account` вызывает `query_membership_and_credits` и возвращает только число и имя поля остатка (предпочтительно `remain`/`available`/`balance`/`left`); нет входа, нет ответа или ответ без числа — неизвестный остаток с пояснением.
- [pricing.json](pricing.json) — базовая таблица цен Kling для `cost_check` (`pricing_file()`): входит в поставку и инструментами только читается, владелец обновляет её в комплексе по кабинету Kling. Наблюдения `learn` пишутся не сюда, а в `<каталог состояния>/providers/kling/pricing-observations.json` и при оценке объединяются с таблицей. Формат и порядок — в [cost_check](../cost_check/README.md#таблица-цен-и-наблюдения).
- `snapshot_warnings` предупреждает `lint_registry` о снимке принятого комплекта модели с авто-раскадровкой без `prefer_multi_shots`.

## Клиент

[kling_mcp.py](kling_mcp.py) — клиент сервера `https://kling.ai` только на стандартной библиотеке Python; адрес меняется лишь в тестах переменной `SONGFRAME_KLING_BASE_URL`. Файлы официального Kling CLI (`~/.kling`) не читаются и не пишутся.

- **Discovery**: `/.well-known/oauth-protected-resource` и `/.well-known/oauth-authorization-server/auth` поверх умолчаний `/auth/authorize`, `/auth/token`, `/auth/register`, `/auth/revoke`, resource `<base>/mcp`, scope `generation.create generation.read account.credit.read`.
- **Вход** `login()`: регистрация публичного клиента (`client_name: "songframe"`, `application_type: "native"`, колбэки `http://127.0.0.1:<p>/callback` и `http://localhost:<p>/callback` для портов 8787–8790, без секрета), loopback-сервер на первом свободном из этих портов на `127.0.0.1`, PKCE S256, `state`, `resource`. Браузер открывается `webbrowser.open`; адрес авторизации всегда печатается в stderr строкой `AUTHORIZE_URL <адрес>`, а если браузер не открылся — дополнительно строка `BROWSER_NOT_OPENED`. Ожидание — 5 минут. После успешного обмена кода запись заменяется, прежний refresh token отзывается без влияния на результат.
- **Токены**: `<каталог состояния>/providers/kling/credentials.json` (`tools.common.local_directory()`, то есть `SONGFRAME_LOCAL_DIR` приложения): `client_id`, `access_token`, `refresh_token`, `expires_at` (секунды epoch, 0 — срок неизвестен), `token_endpoint`, `revocation_endpoint`, `resource`, `scope`. Запись атомарная, права 0600 там, где ОС их поддерживает.
- **Обновление**: если до истечения меньше 60 с или сервер ответил 401, токен обновляется под межпроцессной блокировкой `credentials.lock` (Linux `flock`, Windows `msvcrt.locking`); после захвата файл перечитывается, и уже обновлённый другим процессом токен используется без нового запроса. Ротируемый refresh token сохраняется, без нового остаётся прежний. Отказ `invalid_grant` — `AuthRequired`.
- **MCP**: `Session(timeout, trace_id)` делает `initialize` (протокол `2025-11-25`) и `notifications/initialized` один раз на экземпляр, затем `tools/list` и `tools/call`. Заголовки `Authorization: Bearer`, `Content-Type: application/json`, `Accept: application/json, text/event-stream`, после `initialize` — `mcp-protocol-version`; дополнительные заголовки сервера — словарь `EXTRA_HEADERS` (пуст). Ответ `text/event-stream` разбирается по строкам `data:`.
- **Ошибки**: нет записи входа или повторный 401 — `AuthRequired` («Войдите в Kling на странице «Среда».»); соединение не установлено (отказ, DNS, TLS) — `NotSent`; прочие HTTP-статусы — `TransportError(status, текст)`; таймаут или обрыв после отправки — `TransportError(None, …)`; ошибка JSON-RPC или неразборчивый ответ — `ProtocolError`; `isError: true` — `ToolError(текст)`. Обычные вызовы — 60 с.
- **Загрузка** `Session.upload(path)`: `file_upload {filename, contentType, size, taskTraceId}` → `ticket` + `uploadUrl`/`upload_url` → multipart POST полей `ticket` и `file` без токена; таймаут 120 с + 1 с на каждые 64 КиБ; адрес результата — первый http(s) из ключей `url`, `file_url`, `fileUrl`, `resource_url`, `resourceUrl` при рекурсивном обходе. Принимаются PNG, JPEG, MP4, WAV и MP3, прочие расширения отклоняются до сети.
- Журнала запросов нет: токены, коды, verifier и подписанные адреса не печатаются; адрес авторизации кода не содержит.

## Почему

`prefer_multi_shots` обязателен для `v3_0`: сервис по умолчанию включает авто-раскадровку, и единый план без явного `false` получает внутренние склейки. `resolution` обязателен для `v4_0`: без него сервис отдаёт 720p. Предел 2 500 символов — документированный предел API Kling. Собственный клиент вместо официального CLI даёт длинный таймаут платной отправки, одно обновление токена под блокировкой, атомарное хранение и точное различие «не отправлено», «явный отказ» и «исход неизвестен».

## Тесты

Поддельный сервер [fake_kling_server.py](fake_kling_server.py) на `127.0.0.1` реализует discovery, регистрацию, authorize с редиректом, token (код с проверкой PKCE и refresh с ротацией), revoke, MCP (JSON и SSE, 401, isError, JSON-RPC error, HTTP-статусы, задержки) и приём multipart; браузер в тестах заменён прямым переходом по адресу авторизации. Клиент: регистрация и параметры входа, права и состав файла токенов, повторный вход с отзывом, вход без браузера, таймаут входа, занятый порт и чужой state, обновление с ротацией и без нового refresh token, одно обновление при параллельных сеансах, 401 → обновление → повтор, повторный 401 и отвергнутый refresh token, один `initialize` и `taskTraceId` в каждом вызове, UUID v7, ошибки инструмента, JSON-RPC и транспорта, SSE, загрузка multipart без токена. Адаптер: стабильный SHA замороженного запроса, правила запроса до создания папки, точный конверт отправки с загрузкой входов, общий `task_trace_id`, явный отказ, сбой загрузки/входа/сети без расхода попытки, неизвестный исход при 5xx, ответе без ID и таймауте с отладочной записью, адреса без логотипа, статусы `query_tasks`, непрозрачный ID, HTTPS и полнота загрузки, discovery, остаток, состояние входа и `media_request auth-status` без проекта. Общий жизненный цикл попытки проверяется в [media_request](../media_request/README.md#тесты) на тестовом провайдере.

```sh
python3 -B tools/kling_request/test_kling_mcp.py
python3 -B tools/kling_request/test_kling_request.py
python3 -B tools/run_tests/run_tests.py --only test_kling_mcp test_kling_request
```

## Исключение: снимки оплаченных отправок

Правило одного актуального формата данных здесь сознательно нарушено. Снимок `generation-request.json` принятого комплекта и `request.json` уже оплаченной отправки неизменны: они фиксируют то, за что заплачено, и их нельзя переписать под текущий формат. Снимки, сделанные прежним Kling CLI, задают входы короткими флагами `image`/`tailImage`/`audio`/`video` без слота, а отправка принимает только именованные слоты. Поэтому необязательная функция адаптера `normalize_inputs(spec)` при повторе по такому снимку до заморозки нового запроса раскрывает флаги в объявленные слоты модели из текущего каталога аккаунта (`image` → `first_image`/`image_N`/`keyframe_N`, `tailImage` → `tail_image`, по порядку объявления); сам снимок не меняется. Её вызывает [regenerate_shot](../regenerate_shot/README.md) при подготовке повтора; если подходящего слота нет, повтор останавливается с объяснением до создания пакета. Других чтений прежних форматов адаптер не делает.
