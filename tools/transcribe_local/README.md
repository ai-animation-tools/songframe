# transcribe_local

Локально распознаёт песню для рабочих речевых ориентиров. Приложение вызывает распознавание через [align_lyrics](../align_lyrics/README.md) при разметке трека (кнопка «Разметить»); отдельный запуск нужен только разработчику для аудиоанализа. Результаты ASR не являются доказанными границами слов и не меняют постановку.

```sh
python3 -B tools/transcribe_local/transcribe_local.py --model /absolute/path/to/local-model --output /tmp/recognition.json --allow-network
```

Модель должна быть заранее загружена; нужны `faster-whisper`, NumPy и FFmpeg. Приложение для Linux и Windows поставляет Python-библиотеки и FFmpeg/ffprobe через [runtime](../../scripts/runtime/README.md). Веса модели устанавливаются отдельно по [инструкции для Linux и Windows](../../README.md#модель-распознавания): кнопка загрузки в окне разметки запускает [download_whisper_model](../download_whisper_model/README.md) со встроенным Python, системные Python, pip и hf не нужны. Прогресс виден в журнале задания; повторный запуск использует уже скачанные файлы. Общий launcher приложения задаёт PATH на собственные бинарники и `SONGFRAME_MODEL_DIR`, а `align_lyrics` передаёт этот путь через `--model`. Флаг `--allow-network` снимает только проверку OS-изоляции: модель по-прежнему берётся только с диска (`local_files_only`), включены `HF_HUB_OFFLINE`, `HF_HUB_DISABLE_TELEMETRY`, `TRANSFORMERS_OFFLINE`. Аудио внешним сервисам не передаётся. Читает `source/track.mp3` текущего проекта, пишет указанный JSON с сегментами и словами. В JSON дополнительно записываются фактические `model_path` и `python_executable` для проверки поставки. Черновик разметки по этому JSON строит [align_lyrics](../align_lyrics/README.md).

Для ручного изолированного запуска можно использовать прежнюю команду `unshare -Urn python3 -B ...` без `--allow-network`; приложению это не требуется. Ошибка `unshare: write failed /proc/self/uid_map` относится к разрешениям namespace и возникает до загрузки Whisper. Поле `network` результата отражает фактический способ запуска и офлайн-настройки, а не заявляет изоляцию при прямом вызове.

По умолчанию `--device auto` использует CUDA при совместимой NVIDIA, достаточном объёме видеопамяти и доступных cuBLAS для CUDA 12/cuDNN 9; иначе CPU/int8. Помощник `hardware.py` используется и подсказкой в приложении, и ASR. Можно передать `--device cpu`, например при нехватке видеопамяти. Число CPU-потоков не больше восьми и не больше доступных системе. В JSON поля `hardware` и `method` отражают фактический выбор. Модель не ограничена medium: small, medium, large-v3-turbo и large-v3 используют тот же локальный формат CTranslate2.

Необязательные параметры: `--start`/`--end` в секундах полного трека, `--filter` для локального FFmpeg-фильтра, `--prompt` для подсказки ASR.

`--vocal-result /absolute/path/to/result.json --song-models /absolute/path/to/song-models` включает [распознавание готового вокала и CTC-уточнение](../song_timing/README.md). Вокал сначала выделяется отдельным [separate_vocals](../separate_vocals/README.md), затем выбирается пользователем; повторного вызова MDX здесь нет. Передать нужно оба флага: один `--song-models` даёт понятный отказ до ASR. Нужны одновременно локальная модель из `--model` и компонент `alignment` из [download_song_models](../download_song_models/README.md). SHA MP3, модель/рецепт в метаданных, SHA и точные параметры stereo WAV проверяются до и после обработки. SHA распознавания остаётся SHA исходного MP3. ONNX работает на CPU, Whisper использует выбранный `--device`. Режим обрабатывает полный трек: сочетание с `--start`, `--end` или непустым `--filter` даёт ошибку. Читает точные строки `source/text.md`; неподдерживаемые и ненайденные строки возвращает в `unmatched` с причиной. В результате `segments` содержит границы целых исходных строк с `source_line`, `alignment` указывает CTC-метод; `raw_segments` сохраняет исходный ответ Whisper. Отдельное поле `candidates` содержит сомнительные реальные пути `{source_line, start, end, reason, acoustic_score?}`; слабые результаты не превращаются в `segments` и не подтверждаются автоматически. Кандидаты со средней вероятностью букв ниже прежнего порога 0,45 не публикуются; остальные сохраняются при отказе порогов 20-го процентиля, сходства или длины. Пересечения предложений разрешаются в редакторе, пороги принятия не ослаблены. Без CTC поле `candidates` пусто. Обычный режим без флага остаётся доступен. ASR получает mono16k из готового WAV без обрезки тишины; исходные MP3, текст и готовый вокал не перезаписываются. Итоговый JSON публикуется атомарно после завершения ASR и CTC и проверки неизменности исходников; ошибка, отмена или изменившийся во время работы MP3/текст сохраняют прежний JSON результата. Пустой ответ Whisper сохраняется полноценным JSON с пустым `segments`, промежуточные сегменты не публикуются.

## Защита качества распознавания

Оба режима используют обычный `WhisperModel.transcribe` с Silero VAD: пауза для разделения 2000 мс, запас вокруг голоса 400 мс. `faster-whisper` сам восстанавливает времена сегментов и слов к полной шкале; инструмент прибавляет только явный `--start`. Полная `decoded_duration` и аудио для CTC не сокращаются до длины найденного голоса. Пустой ответ VAD остаётся пустым распознаванием, а не поводом включать скрытый повтор на исходном MP3.

Включена штатная защита `hallucination_silence_threshold=2.0`. При неудачном декодировании возможны четыре попытки с температурами 0/0.2/0.4/0.6 и порогами compression ratio 2.4, log probability −1.0, no-speech 0.6. `condition_on_previous_text=False` не переносит ошибку прошлого окна дальше. Глобальный запрет повторов и слов не применяется: припевы законны, а высокий no-speech score сам по себе не доказывает отсутствие пения. Параметры не гарантируют отсутствие галлюцинаций и требуют проверки на слух. Контракт закреплён по [faster-whisper 1.2.1](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py).

Служебный [quality.py](quality.py) проверяет пригодность временных ориентиров. Нулевые/нечисловые интервалы и многословные фрагменты, у которых большинство времён схлопнулось в точку с недостаточной суммарной длительностью, не используются как опоры разметки. Это проверка времён, а не определение истинности текста: высокая вероятность слова не отменяет сломанный таймкод. Все исходные ответы сохраняются в `raw_segments`, исключённые отмечаются в `rejected_segments` индексом и причиной, пригодные находятся в `segments`. В режиме CTC `segments` затем заменяется найденными исходными строками; сырой ответ сохраняется без потерь. Неконечные числа в исходном ответе приводят к отказу публикации, сохраняя прежний JSON; raw не исправляется молча. JSON содержит `asr_options` с фактической политикой этого запуска, в том числе VAD и последовательностью температур.

Текст песни автоматически не превращается в полный `initial_prompt`: ограниченное окно подсказки может сохранить только конец длинной песни и подтолкнуть модель к переписыванию вместо распознавания. Явный `--prompt` остаётся доступен разработчику; исходный текст независимо используется акустическим уточнением.

Тесты без модели и сети: `python3 -B tools/run_tests/run_tests.py --only test_transcribe_local test_quality`. Проверяют локальную загрузку и офлайн-настройки, прежнюю проверку ручного изолированного запуска и корректное поле `network` при прямом вызове, пустой ASR, отдельную публикацию кандидатов и отказ при нечисловой оценке, ошибки ASR/CTC и атомарной записи, изменение исходников во время обработки и запрет записи результата поверх MP3/текста.
