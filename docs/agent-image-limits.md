# Изображения в заданиях агентов

Внешние источники проверены 1 ноября 2026 года. Локальные версии при той проверке: Codex CLI `0.159.2`, Claude Code `2.1.284`. Это датированный справочник: перед расширением ограничений сверять текущие первичные источники. MB в документации сервиса и МиБ в коде приложения не считать одной единицей.

Транспорт вложений и пределы приложения сверяют эталоны `agents-protocol` и `agents-cli` ([описание](../testdata/golden/README.md)). Общий порядок запуска агентов — в [заданиях агентов](agents.md).

## Codex CLI и внешний API

SongFrame передаёт каждый файл отдельным `--image <путь>` в `codex exec`; промпт поступает через stdin. Изображения не включаются в stdin приложением как base64. Это задаёт адаптер `codexAdapter.Args` ([adapters.go](../internal/agents/adapters.go)); на дату проверки это соответствовало локальной справке `codex exec --help` версии `0.159.2` и [официальной справке CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli): несколько файлов передаются повторением `--image` либо списком путей. Вложения допускаются только в режиме чтения; задание кандидатов изображений (`workspace-write`) их не принимает.

В проверенной справке CLI и локальном `--help` **не опубликованы отдельные численные пределы количества изображений, размера файла и общего размера вложений Codex CLI**. Это неизвестные пределы, а не обещание неограниченного ввода. Возможные ограничения сервера, выбранной модели, контекста и способа входа проверяются отдельно. Успешная обработка одного пакета не доказывает максимальный поддерживаемый объём.

Для внешнего API [Images and vision: Image input requirements](https://developers.openai.com/api/docs/guides/images-vision#image-input-requirements) на дату проверки указывает:

| Поверхность | Опубликованное ограничение |
| --- | --- |
| API: общий payload запроса | До 512 MB |
| API: количество | До 1500 изображений на запрос |
| API: форматы | PNG, JPEG, WebP и неанимированный GIF |
| Модель и контекст | Дополнительно действуют пределы контекста, габаритов и обработки изображений выбранной модели и уровня `detail` |

Это сведения об API анализа изображений. Они не устанавливают пределы `codex exec`, входа через ChatGPT или генерации изображений. Не переносить их на CLI и не расширять по ним бюджеты приложения без отдельной проверки нужного маршрута.

## Claude Code и внешний API

SongFrame передаёт Claude Code изображения как блоки `image` с `source` типа `base64` в сообщении `user` через `--input-format stream-json` (`claudeAdapter.Input`, [adapters.go](../internal/agents/adapters.go)); без вложений промпт идёт обычным текстом (`--input-format text`). Интерфейс описан в [CLI reference](https://code.claude.com/docs/en/cli-reference) и [Agent SDK Streaming Input](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode).

[Headless: Pipe data through Claude](https://code.claude.com/docs/en/headless#pipe-data-through-claude) указывает предел piped stdin **10 MB**. Раздел не уточняет область применения к inline-изображениям `stream-json`: к одному JSONL-сообщению или потоку целиком. Отдельные численные пределы количества и размера именно inline-вложений CLI в проверенных страницах не опубликованы. Нельзя автоматически переносить лимиты веб-чата, инструмента Read или API на установленный CLI. Автоматическое уменьшение отдельных путей ввода не заменяет подготовку изображений приложением.

Внешние пределы [Claude Vision](https://platform.claude.com/docs/en/build-with-claude/vision#request-limits):

| Поверхность | Опубликованное ограничение |
| --- | --- |
| API: количество | 100 изображений при контексте 200k; 600 для остальных моделей |
| API: размер | 10 MB на изображение после base64; Amazon Bedrock — 5 MB после base64 |
| API: габариты | 8000×8000; при более 20 изображениях рекомендовано не превышать 3000 px по каждой стороне |
| Форматы | JPEG, PNG, GIF, WebP; у анимации используется первый кадр |
| claude.ai | 20 изображений на сообщение; это предел веб-чата |

[API overview: Request size limits](https://platform.claude.com/docs/en/api/overview#request-size-limits) указывает **128 MB** для Messages/Token Counting и **32 MB** для Sessions/Agents/Environments. Это разные endpoints. Обобщение «любой запрос Claude ограничен 32 MB» не использовать. Для партнёрских платформ действуют собственные ограничения. Значения API не являются проверкой доступности или пределов конкретного способа входа Claude Code.

На странице Vision есть расхождение по Google managed между основной таблицей и блоком Availability; гарантированный предел для этого маршрута здесь не устанавливается.

## Сопоставление двух агентов

| Что сравнивается | Codex CLI | Claude Code |
| --- | --- | --- |
| Передача изображений из SongFrame | Повторяемые `--image <путь>` | Base64-блоки `image` в stdin `stream-json` |
| Подтверждённый численный предел вложений самого CLI | В проверенной справке не найден | Для inline-вложений не найден; headless guide отдельно указывает 10 MB piped stdin с неуточнённой областью применения |
| Внутренний бюджет изображений проверки | 16 МиБ исходных байтов | 6 МиБ исходных байтов |
| Дополнительный предел транспорта в приложении | Отдельный предел полного stdin не введён; изображения передаются путями | 10 000 000 байт полного сериализованного stdin |

Зачем нужна политика ниже, показывает проверка видео: набор из 23 PNG общим размером 21,94 МиБ был отклонён общим менеджером SongFrame (`INVALID_INPUT`) **до вызова Codex** — сообщение про 64 изображения, 5 МиБ на файл и 20 МиБ суммарно описывало правила приложения. После упаковки тот же набор из 23 изображений занял 3,79 МиБ; количество кадров, ID и таймкоды сохранились. Эти измерения — проверка конкретного пакета, не установление максимальных пределов CLI.

## Политика SongFrame

Числа ниже выбраны приложением и **не являются заявленными лимитами Codex или Claude Code**.

| Уровень | Ограничение |
| --- | --- |
| Общий менеджер вложений | До 64 PNG/JPEG; до 5 МиБ на файл и до 20 МиБ исходных байтов суммарно |
| Проверка видео | До 32 кадров и 20 опор; максимум 960 px по большей стороне |
| Бюджет изображений проверки для Codex | До 16 МиБ исходных байтов |
| Бюджет изображений проверки для Claude Code | До 6 МиБ исходных байтов |
| Отдельное изображение проверки | Не более `min(1 МиБ, бюджет / число изображений)` |
| Полный stdin Claude Code | Не более 10 000 000 байт UTF-8 после сериализации JSON, включая base64 и текст |

Общий менеджер (`readImages` в [manager.go](../internal/agents/manager.go)) проверяет вложения до диагностики CLI и создания записи истории: абсолютный путь, расширение `.png`/`.jpg`/`.jpeg`, непустой обычный файл и сигнатуру формата, совпадающую с расширением. Бюджет проверки видео берётся из записи выбранного агента в реестре (`VideoReviewBudget`, [internal/app/videoreview.go](../internal/app/videoreview.go)); без выбранного агента берётся бюджет записи Codex. Бюджет вне диапазона от 1 байта до `videoreview.DefaultImageBudget` (16 МиБ) подготовка кадров отклоняет.

Base64 занимает `4 × ceil(число байтов / 3)` байт. Поэтому 6 МиБ изображений превращаются примерно в 8 МиБ base64; оставлен запас для промпта, контекста и JSON. Полный фактический stdin Claude Code дополнительно проверяется до запуска CLI (`INVALID_INPUT`). Консервативный предел применяется независимо от неподтверждённых различий версий `stream-json`.

Подготовка сохраняет число кадров, ID и фактические таймкоды. Кадры извлекает FFmpeg (компонент, который находят в системе или ставят кнопкой; без него проверка видео недоступна), копии опор учитывают EXIF-ориентацию и уменьшаются до 960×960 без увеличения. PNG в бюджете остаются неизменными; большие приватные копии переходят в JPEG с качеством 85, 70, затем 55, а если и этого мало — уменьшаются на четверть с сохранением пропорций, и попытки повторяются. Кодек и расширение берутся из фактического результата. Байты переупакованных JPEG и копий опор зависят от кодека и эталонами не сравниваются; размеры, порядок и правила выбора качества — сравниваются. Исходные видео, опоры и платные оригиналы не изменяются. Подготовка выполняется до запроса модели; ошибки размера не повторяют его автоматически.

Владельцы правил:

- [frontend/src/shared/agent-providers.ts](../frontend/src/shared/agent-providers.ts) и [internal/agents/registry.go](../internal/agents/registry.go) — бюджеты изображений проверки выбранных агентов (`reviewImageBudgetBytes`, `ReviewImageBudgetBytes`);
- [internal/agents/adapters.go](../internal/agents/adapters.go) — транспорт вложений и предел полного stdin Claude Code;
- [internal/agents/manager.go](../internal/agents/manager.go) — общий предел вложений;
- [internal/videoreview](../internal/videoreview/extract.go) (`extract.go`, `images.go`) — извлечение кадров, копии опор и упаковка в бюджет.
