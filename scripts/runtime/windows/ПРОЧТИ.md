# Проверка Windows-поставки

Windows-установщик собирается на Linux. В Windows VM на прежней ZIP-поставке с тем же составом приложения проверены встроенный Python и библиотеки, FFmpeg/ffprobe и короткий медиапрогон, вход в провайдера генерации (прежним официальным CLI; собственный клиент провайдера в VM не проверялся), загрузка модели и локальное распознавание. Эти проверки не подтверждают полный производственный цикл. Сам установщик в Windows не проверялся. Обе поставки, Linux AppImage и Windows-установщик, собираются на Linux; проверка установщика подтверждает целостность его архива и состав ресурсов, без исполнения Windows-кода. Новые VM-прогоны выполняются по явному поручению.

Запустите `songframe-<версия>-win-x64-setup.exe`. Установщик не задаёт вопросов и не требует прав администратора: он ставит приложение в профиль пользователя, в папку `%LOCALAPPDATA%\Programs\songframe`, создаёт ярлыки на рабочем столе и в меню «Пуск» и сразу запускает SongFrame. Устанавливать Node.js, Yarn, Python или pip не нужно.

Папка установки содержит `SongFrame.exe`, папку `resources`, `check-runtime.cmd` и этот файл. Чтобы открыть её, вставьте `%LOCALAPPDATA%\Programs\songframe` в адресную строку Проводника или выберите «Расположение файла» в контекстном меню ярлыка SongFrame.

Новая версия устанавливается запуском её установщика поверх прежней, удалять старую не нужно. Удаление — в «Параметры → Приложения». Настройки, история, текущий проект и вход в провайдера генерации хранятся в папке состояния приложения и сохраняются при обновлении и удалении.

Для технической проверки откройте `check-runtime.cmd` в папке установки двойным щелчком. Он проверяет встроенный Python, библиотеки, вложенный интерпретатор, FFmpeg/ffprobe, короткое кодирование и чтение тестового файла, запуск инструмента и задания приложения во временном проекте в папке с кириллицей и пробелами, клиенты встроенных провайдеров генерации (без сети) и загрузчик модели. Python-процессы получают в PATH только встроенные медиабинарники; пользовательские проекты и платная генерация не используются. Проверка клиента провайдера не отправляет генерацию и не подтверждает вход.

Отчёты `result.json` и `check.log` сохраняются **в папке установки, рядом с EXE и check-runtime.cmd**: она в профиле пользователя и доступна на запись. Установка новой версии заменяет содержимое этой папки, поэтому нужные отчёты скопируйте заранее. Оба файла создаются до запуска приложения. Начальный `result.json` с `stage: launcher` означает, что приложение ещё не записало результат; успешная проверка заменяет его на `ok: true`, ошибка приложения — на `ok: false` с текстом причины. Если запуск не удался, отправьте оба файла и текст показанной Windows ошибки. Для проверки пути с кириллицей и пробелами можно скопировать всю папку установки в такой каталог и запустить `check-runtime.cmd` оттуда.

Веса faster-whisper устанавливаются отдельно: кнопкой «Скачать модель …» в окне автоматической разметки. Скачивание и распознавание требуют отдельной модели; обычная runtime-проверка её не загружает. Вход в провайдера генерации выполняется на странице «Среда»; авторизация сохраняется в папке состояния приложения (подпапка `providers\<id>` провайдера).

Клип ведётся кнопками приложения; командная строка для работы с проектом не нужна. Для текстовых этапов установите Claude Code или Codex по официальной инструкции для Windows (нативная установка или `npm install -g`) и выполните вход; приложение найдёт программу в `Path`, `%USERPROFILE%\.local\bin` или `%APPDATA%\npm`. Встроенные провайдеры генерации с прямым вызовом и Python-инструменты этих агентов не требуют.
