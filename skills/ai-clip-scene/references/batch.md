# Партия независимых планов

Читать при вызове `batch=M01,M03,M05`. Партия готовит несколько планов в одном диалоге, чтобы сократить число раундов; деньги, вопросы в пакетах и приёмка остаются поплановыми.

1. **Проверка.** `shot_status --independent M01 M03 M05`. Конфликт по состоянию (более поздний план наследует изменения более раннего) исключает план из партии: предложи сузить состав. Предупреждение о соседях по шкале требует ответа пользователя: соседи допустимы, если стык это смена ракурса или намеренный монтажный пропуск; при непрерывном переходе более поздний план готовится после приёмки предыдущего. Не более трёх планов в партии.
2. **Этап 1 вместе.** Для каждого плана `shot_workflow init Mxx --dir plan/batches/Mxx-attempt-NN --batch <имя>`; субагент готовит описания всех планов в порядке шкалы (один субагент на план допустим, если среда позволяет параллельные вызовы). Основной поток ставит `ask --stage description_review` в каждом пакете и выполняет `wait` по очереди в порядке шкалы; карточка в чате одна на партию. Вердикт `revise` одного плана не останавливает остальные.
3. **Этапы 2–3 по планам, одним раундом каждый.** Опоры всех планов готовятся одним раундом, в каждом пакете свой `ask --stage keyframes_review`; затем промпты всех планов и `ask --stage prompt_review` в каждом. Правка из `note` затрагивает только тот пакет, в котором она записана.
4. **Этап 4 по планам.** `prepare` и `cost_check` для каждого пакета; таблицы запросов лежат в пакетах, в карточке строка с суммой оценок и остатком. Сумма сверяется с остатком: если суммы не хватает или хоть одна оценка неизвестна, скажи об этом в карточке до вопросов. `ask --stage request_choice` в каждом пакете, `wait` по очереди: вердикт `send` разрешает ровно один `submit` именно этого пакета, `park` сохраняет его в очередь. Пакет без вердикта не отправляется.
5. **Ожидание и результат.** Один `kling_request watch --work-dir …` на все отправленные пакеты (в субагенте); затем `contact_sheet` и этап 5 для каждого плана отдельно со своим `ask --stage downloaded`. Приёмка по планам через `accept_shot`; стык между соседями партии проверяется пробой после получения обоих.

Планы, снятые с партии, не теряют подготовку: их пакеты остаются на своём этапе и продолжаются по одному. `regenerate=true` с `batch=` не сочетается: повтор запроса вызывается для одного плана.
