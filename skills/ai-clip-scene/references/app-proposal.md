# Предложение производственного этапа для приложения

Читать только при `output=proposal`. Этот режим имеет приоритет над ручным порядком навыка: CLI агента читает переданный приложением контекст и возвращает один JSON-документ без Markdown и текста вокруг. Не записывать файлы проекта или пакета, не запускать `ask`, `wait`, `decide`, генерацию изображений, `kling_request prepare/submit`, платные команды, приёмку, commit или push. Вопросы, применение предложения и продолжение принадлежат приложению.

Текстовые предложения готовит глобально выбранный Claude Code или Codex. Изображения выбираются независимо через проектный `generation.image`: Codex использует глобальный профиль `imageAgent`, Kling — свой адаптер. Видео использует адаптер `generation.video` (Kling). Режим не вызывает Skill tool: инструкции поступают через stdin существующего CLI.

## Вход и границы этапа

Приложение передаёт `scene`, `stage`, папку проекта, текущий пакет, настройки генерации, постановку и контекст непрерывности, кастинг с путями изображений, принятые материалы и замечание при корректировке. Используй сведения только для выбранного плана. Сохраняй принятые совместимые опоры и исправляй только затронутый этап; источники, реестр и кастинг здесь не меняются. Если контекста недостаточно, заверши задание с понятной ошибкой: не выдумывай внешность, файлы, параметры модели или факт согласования.

Схема результата — `ProductionStageProposal` из `src/shared/production-workflow.ts` комплекса. Имена JSON-полей регистрозависимы. `schemaVersion` всегда `1`; `stage` совпадает с запрошенным этапом.

## description

```json
{
  "schemaVersion": 1,
  "stage": "description",
  "description": "Постановка и план опор словами",
  "requestSeconds": 7,
  "keyframes": [
    { "id": "K01", "role": "first", "timeSeconds": 0, "prompt": "Самодостаточное описание первого кадра", "referencePaths": ["source/heroes/hero.png"] },
    { "id": "K02", "role": "last", "timeSeconds": 7, "prompt": "Самодостаточное описание последнего кадра", "referencePaths": ["source/heroes/hero.png"] }
  ]
}
```

`requestSeconds` — целое число по `generation.video.duration_rule`: строго больше окна для `min_supported_strictly_greater_than_window`, не меньше для `min_supported_not_less_than_window`, ровно окно для `exact_window`. Дробное окно с `exact_window` несовместимо с целой длительностью инструмента; верни понятную ошибку вместо округления. Опоры идут по времени: первый кадр в `0`, последний в `requestSeconds`, промежуточные только при обоснованной необходимости; ID вида `K01`, `K02` уникальны и сохраняются при совместимой доработке. Для каждой опоры передай полный промпт и существующие пути референсов внутри проекта; пути не выдумывай. Включи внешность из кастинга, действие и камеру, дословную врезку непрерывности (`before` для начала, `after` для конца), ограничения изображения из настроек проекта. Правила содержания промптов — [prompt-template.md](prompt-template.md), состояния — [state.md](state.md).

Применение описания создаёт материал для согласования. Оно не принимает описание и не разрешает изображения или видео автоматически.

## frames

В обычном задании `output=proposal` этот этап не рисуется. При `generation.image.provider=codex` после принятия описания приложение запускает отдельное задание Codex с `image_gen`, передавая утверждённые `keyframes` с промптами и референсами. Только это задание создаёт изображения в разрешённой папке кандидатов и возвращает:

```json
{ "schemaVersion": 1, "stage": "frames", "images": [{ "id": "K01", "path": "/абсолютный/путь/к/созданному/кадру.png" }] }
```

ID должны соответствовать переданному набору опор, пути — реально созданным изображениям. Приложение проверяет результат и регистрирует кандидатов; пользователь принимает их отдельно. Задание изображений не принимает кадры, не меняет workflow, не продолжает видеогенерацию и не получает разрешения на Kling. При отсутствии `image_gen` возвращается понятная ошибка. Проверка наличия CLI не доказывает доступность image tool конкретного Codex аккаунта. Без смены настройки приложение не подменяет backend платной командой.

При `generation.image.provider=kling` та же кнопка маршрута опор готовит один frozen image-запрос для одной Kxx, без генерации в текстовом `output=proposal`. `set-image-request` записывает отдельную image-историю, активные кадр/попытку и вопрос `image_request_choice`; video request остаётся прежним. Диалог показывает image model/command, точный промпт, входы, SHA, стоимость и остаток; `quote` ничего не отправляет. Только отдельное подтверждение разрешает один `submit` показанной попытки. `resume`/получение продолжают тот же ID и дают `image_downloaded`. Выбор `select-image` из скачанных оригиналов создаёт кандидата `approved: false`; после всех кандидатов отдельно задаётся `keyframes_review`. Ни скачивание, ни выбор не принимают опоры, сцену или assets. Общий `executor=app|agent` сохраняет одного владельца продолжения; UI-задание не перехватывает ручную отправку и наоборот.

## prompt

```json
{ "schemaVersion": 1, "stage": "prompt", "prompt": "Полный самодостаточный видеопромпт" }
```

Пиши по [prompt-template.md](prompt-template.md) на основе принятого описания и опор, используя переданные реальные входы. Не ссылайся на локальные коды и имена без визуального описания. Приложение сохраняет предложение для отдельного согласования; ранее принятые опоры остаются входом, принятие нового промпта не подразумевается.

## request

```json
{
  "schemaVersion": 1,
  "stage": "request",
  "request": {
    "model": "идентификатор-из-переданных-capabilities",
    "command": "image_to_video",
    "parameters": { "prompt": "Принятый видеопромпт", "duration": 7 },
    "inputs": [{ "flag": "input", "path": "plan/batches/M01-attempt-01/frames/K01.png", "role": "first" }],
    "outputs": 1
  }
}
```

`command`: `text_to_video`, `image_to_video`, `omni_ref_video` или `motion_control`; выбирай только подтверждённую переданными capabilities комбинацию команды и модели для `generation.video`. Для image-подготовки используются собственные T2I/I2I capabilities, а не этот video-черновик. `parameters` содержат точные параметры из контекста, настройки проекта и принятый промпт; не добавляй отсутствующие в возможностях флаги. Для каждого входа: `flag` из `input`, `image`, `tailImage`, `audio`, `video`, существующий проектный `path`, при необходимости `slot` и `role`. `outputs` — согласованное число результатов, без дополнительных платных вариантов.

Это только черновик для локальной подготовки замороженного запроса. Приложение само проверяет входы, готовит таблицу и стоимость и записывает вопрос с `executor=app`. У агента нет прямой отправки Kling в режиме UI. Применение JSON, принятие описания, опор или промпта не разрешают расход. Платная отправка возможна только отдельным действием приложения после решения `send` по точному запросу и проверки стоимости; изменённый запрос согласуется заново. Текущий шаг подготовки не выполняет отправку независимо от прежних решений или `regenerate=true`.
