# Предложение производственного этапа: контракт ответа

Ответ — один JSON-документ `ProductionStageProposal` (`src/shared/production-workflow.ts` комплекса) без Markdown и текста вокруг. Имена полей регистрозависимы, других полей нет. `schemaVersion` всегда `1`; `stage` совпадает с запрошенным этапом. Приложение проверяет ответ и показывает его для согласования; несоответствие контракту делает предложение недействительным. Если этап выполнить нельзя, вместо JSON верни одну-две фразы с причиной: приложение покажет их как отказ. Противоречия сценария на этапе description описывает отказ [`blocked`](#blocked).

## description

```json
{
  "schemaVersion": 1,
  "stage": "description",
  "description": "Постановка, первый кадр, события плана, план опор и рекомендуемая модель словами",
  "requestSeconds": 7,
  "keyframes": [
    { "id": "K01", "role": "first", "timeSeconds": 0, "prompt": "Самодостаточное описание первого кадра", "referencePaths": ["source/heroes/hero.png"] },
    { "id": "K02", "role": "last", "timeSeconds": 7, "prompt": "Самодостаточное описание последнего кадра", "referencePaths": ["source/heroes/hero.png"] }
  ]
}
```

- `requestSeconds` — целое число по `settings.duration_rule`: строго больше окна для `min_supported_strictly_greater_than_window`, не меньше для `min_supported_not_less_than_window`, ровно окно для `exact_window`. Дробное окно с `exact_window` несовместимо с целой длительностью: верни понятную ошибку вместо округления. При `manualGeneration=true` модель не выбирается: возьми наименьшее целое число по правилу, без сетки длительностей моделей и пределов `lipSync`.
- `keyframes`: опоры по возрастанию времени, от 1 до 20; сколько — по разделу «Длительность и опоры» скилла. Если передан `keyframeCount` — ровно столько. Одна опора — только `K01` (роль `first`, время `0`), без `last`. ID `K01`, `K02`, … подряд; роль `first` у первой (время `0`), `last` у последней (время `requestSeconds`), `middle` у промежуточных строго между ними. При совместимой доработке ID сохраняются. При `manualGeneration=true` — ровно одна опора `K01` (роль `first`, время `0`).
- `prompt` каждой опоры — полный самодостаточный промпт изображения по [каркасу промптов](prompt-template.md): внешность из кастинга, действие и камера, дословная врезка непрерывности (`before` для первой и промежуточных, `after` для последней).
- `referencePaths` — только PNG/JPEG/WebP из `allowedPaths`; пути не выдумывай. Кадр другого плана из `continuityFrames` указывай только у опоры, которой нужно совпадение с ним; приложение извлечёт его в пакет при применении описания.
- `copyOf` — необязательное поле опоры, которая кадр в кадр повторяет более раннюю опору или кадр принятого плана: ID более ранней опоры, которая сама не копия, либо `path` кадра из `continuityFrames`. У копии `prompt` — пустая строка, `referencePaths` — пустой список: её не создают, а получают файлом источника — опоры после её утверждения, кадра другого плана при утверждении описания. Пример конечного кадра, удерживающего промежуточный: `{ "id": "K03", "role": "last", "timeSeconds": 9, "prompt": "", "referencePaths": [], "copyOf": "K02" }`. Пример первой опоры, продолжающей последний кадр предшественника без смены точки: `{ "id": "K01", "role": "first", "timeSeconds": 0, "prompt": "", "referencePaths": [], "copyOf": "<path кадра M06 last из continuityFrames>" }`.

Применение описания создаёт материал для согласования; оно не принимает описание и не разрешает изображения или видео.

## blocked

Отказ этапа description из-за противоречий сценария (правила — в разделе «Противоречия сценария» скилла):

```json
{
  "schemaVersion": 1,
  "stage": "blocked",
  "reason": "Два противоречия с действием плана M07: первый кадр не подготовить",
  "problems": [
    { "phase": "before", "entity": "vera", "property": "position", "conflict": "Значение «За рулём машины» (из начального состояния кастинга) расходится с действием «Вера выходит из подъезда и идёт к машине»: на первом кадре она ещё у подъезда.", "fix": "У двери подъезда, в нескольких шагах от машины" },
    { "field": "camera", "conflict": "Камера «из салона машины» не видит подъезд, из которого выходит Вера." }
  ]
}
```

- `reason` и `problems` обязательны, других полей нет; в `problems` хотя бы один элемент.
- Элемент значения врезки: `phase` (`before` или `after`), `entity` — ID сущности кастинга, `property` — ключ её свойства, `conflict` — текст, `fix` — новое значение строкой или `null`.
- Элемент постановки: `field` (`action`, `camera`, `continuity`, `references`, `viewpoint` — точка съёмки на карте) и `conflict`, без `phase`, `entity`, `property` и `fix`.

## prompt

```json
{ "schemaVersion": 1, "stage": "prompt", "prompt": "Full self-contained video prompt", "translation": "Тот же промпт по-русски" }
```

- `prompt` — видеопромпт на языке указаний провайдера видео по разделу «Видеопромпт» [правил промптов](prompt-template.md): по принятому описанию и приложенным опорам, с реальными входами.
- `translation` — тот же промпт по-русски, полный: пользователь видит его при согласовании и может отправить вместо оригинала. Если промпт и так русский, `translation` совпадает с `prompt`.

Ранее принятые опоры остаются входом; принятие нового промпта не подразумевается. Если опора не даст пригодного видео (раздел «Видеопромпт», шаг «Найди дефект опоры»), вместо JSON верни одну-две фразы: какая опора, что не так и что исправить.

Если передан `promptMaxChars`, длина промпта не больше этого числа символов: более длинный промпт приложение не даст утвердить. При `manualGeneration=true` или `manualVideo=true` видео создаёт пользователь на сайте провайдера: не используй обозначения входов (`图片1` и подобные), называй опоры и звук словами.

## frames

Этот этап задание не выполняет. После принятия описания приложение передаёт промпты и референсы опор выбранному провайдеру изображений (отдельным заданием провайдера-агента или платным запросом на одну опору) и регистрирует полученные изображения как непринятых кандидатов; пользователь утверждает их отдельно.
