# video_review

Извлекает отдельные кадры локального видео для смыслового анализа агентом. Сам инструмент не оценивает изображение и не принимает дубль; он готовит проверяемую привязку изображения к моменту видео.

```sh
python3 -B tools/video_review/video_review.py --video /tmp/original.mp4 --out /tmp/video-review --reference /tmp/keyframe.png --json
```

Проект не требуется; необязательный `--project` принимается для совместимости с PythonLauncher и не используется.

Оба пути абсолютные: вход — существующий локальный файл, выход — новая или пустая папка с существующим родителем. FFmpeg и ffprobe берутся из PATH, который задаёт общий PythonLauncher. Сетевые протоколы отключены. Исходник не изменяется, непустой выход не перезаписывается. Результат сначала готовится во временной соседней папке и публикуется после успешного извлечения всех кадров.

Необязательный повторяемый `--reference /абсолютный/путь.png` принимает до 20 опор. Pillow готовит отдельные копии `R001.png` или `R001.jpg` и далее, применяет EXIF-ориентацию и уменьшает до 960×960 без увеличения. Исходники не изменяются. Поле `references` всегда есть: без опор это `[]`, с опорами — `[{"id":"R001","source_path":"/tmp/keyframe.png","path":"/tmp/video-review/R001.png"}]`.

Выход: `F001.png`/`F001.jpg`, `F002.png`/`F002.jpg` и далее, `manifest.json`; тот же JSON печатается в stdout (флаг `--json` обозначает этот формат, он же используется по умолчанию). Контракт:

```json
{"schema_version":1,"duration_seconds":2.5,"references":[],"frames":[{"id":"F001","time_seconds":0.0,"path":"/tmp/video-review/F001.png"},{"id":"F002","time_seconds":0.5,"path":"/tmp/video-review/F002.png"}]}
```

Пример показывает форму, а не полный набор кадров. Выбираются реальные ближайшие кадры к шагу 0,5 секунды, обязательно первый и последний. Если требуется больше 32 кадров, целевые точки распределяются равномерно между первым и последним. Повторяющиеся индексы удаляются: короткое видео может дать один кадр. `time_seconds` — фактический presentation timestamp кадра относительно первого кадра, а не расчёт `индекс/FPS` или конец контейнера; это работает и при переменной частоте. `duration_seconds` — длительность видеопотока (при отсутствии — контейнера).

Размер изображений ограничен 960 пикселями по большей стороне с сохранением пропорций, увеличения маленьких кадров нет. Ограничения: видео до 600 секунд, частота до 120 кадров/с, до 72 000 декодированных кадров, ожидание каждого FFmpeg/ffprobe не более 120 секунд. Пустое видео, отсутствие потока/меток времени, некорректные параметры и ошибки декодирования завершаются кодом 1 с сообщением в stderr; готовый отчёт при этом не публикуется.

## Размер вложений

Все кадры и опоры вместе по умолчанию ограничены **16 МиБ** исходных байтов файлов, каждый файл — минимумом из **1 МиБ** и целой части `общий бюджет / число изображений`. Необязательный `--image-budget-bytes` задаёт меньший положительный целый бюджет, не больше `16777216` байт; например `--image-budget-bytes 6291456` задаёт 6 МиБ для выбранного Claude Code. Приложение передаёт бюджет выбранного агента, для Codex остаётся 16 МиБ. Это локальная политика подготовки копий с запасом, а не заявленный лимит внешнего сервиса; base64 и текст сообщения в сумму файлов не входят. PNG, который укладывается в свою долю, сохраняется побайтно. Крупные PNG в приватной папке подготовки переупаковываются в RGB JPEG: качество 85, при необходимости 70 и 55; если этого недостаточно, размеры последовательно уменьшаются с сохранением пропорций и попытки повторяются. Увеличения разрешения нет.

Набор кадров, опор, ID и фактические таймкоды не сокращаются. Меняется только копия изображения и расширение; поле `path` в stdout и `manifest.json` указывает на фактический PNG или JPEG, `source_path` опоры остаётся путём оригинала. Перед публикацией проверяются каждый размер и общая сумма. Если даже минимальное изображение не помещается в лимит, результат не публикуется. Исходные видео и изображения не переупаковываются.

## Тесты

```sh
python3 -B tools/video_review/test_video_review.py
```

Тесты создают синтетическое FFmpeg-видео только в `/tmp`: проверяют совпадение PNG с независимо извлечённым кадром, фактический последний таймкод, VFR, один кадр, предел 32 кадров, уменьшение без увеличения, JSON CLI без проекта, отказ для повреждённого видео, сохранность непустого выхода, уменьшение опор без изменения оригиналов и ограничение их числа. Отдельные тесты проверяют набор из 52 шумовых PNG общим размером больше 20 МиБ, сохранение всех ID при упаковке до 16 МиБ, неизменность маленьких PNG, дополнительное уменьшение при тесном бюджете, реальные пути JPEG в отчёте отсутствие частичного результата при невозможном лимите, CLI-бюджет 6 МиБ на шумовых опорах и отказ от нулевого, отрицательного или превышающего 16 МиБ бюджета до извлечения.
