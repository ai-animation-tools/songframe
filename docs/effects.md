# Эффекты кадра

Эффекты кадра — дождь, свет и зерно, которые приложение считает само, без агента и платного сервиса. Они применяются в двух местах:

- в сборке [статичного кадра](production-workflow.md#статичный-кадр) из опор-состояний;
- поверх принятого плана. Об этом второй случай ниже.

Параметры человек подбирает на глаз. Результат определяется рецептом: одинаковые входы и параметры дают одинаковый ролик.

| Что | Где |
| --- | --- |
| Эффекты, схема параметров, рендер кадров в FFmpeg | [internal/effects](../internal/effects/effects.go) |
| Эффект поверх принятого плана: рецепт, свежесть, видео плана для монтажа | [internal/shoteffects](../internal/shoteffects/shoteffects.go) |

## Набор эффектов

Эффект — модуль Go. У модуля есть:

- идентификатор, название и версия;
- схема числовых параметров: подпись, диапазон, значение по умолчанию и шаг.

По схеме проверяется рецепт и строится панель параметров. Новый эффект добавляется одним файлом с регистрацией в реестре пакета; остальное приложение узнаёт о нём только из реестра. Версия эффекта меняется вместе с изменением результата при тех же параметрах: так производный ролик с прежней версией считается устаревшим.

Цепочка эффектов применяется по порядку. Свет, стоящий раньше дождя, подсвечивает капли.

## Эффект поверх принятого плана

Платный оригинал, принятое `video.mp4` и весь комплект `assets/shots/Mxx/` эффект не меняет. Результат — производный ролик и рецепт в `assets/effects/Mxx/`:

- `recipe.json` хранит (версия FFmpeg записывается для сведения и в свежесть не входит):
  - источник — путь и SHA-256 принятого видео комплекта;
  - цепочку эффектов — заданные человеком значения, необязательный ветер, версию эффекта и полные значения параметров;
  - частоту, число кадров и версию FFmpeg;
  - путь и SHA-256 ролика.
- `video-<начало SHA-256>.mp4` — ролик с эффектом в кадре и длине принятого видео. У каждого результата своё имя: файл, который сейчас показывает плеер, не заменяется. Прежние ролики удаляются после записи рецепта.

Рецепт пишется только вместе с готовым роликом; незаконченный ролик рендера получает своё временное имя. «Убрать эффект» сначала удаляет ролик рецепта: если его держит плеер или другая программа, эффект остаётся как был и показывается ошибка. Затем удаляются рецепт и папка плана, и монтаж снова берёт принятое видео. Папку плана, удалённого из сценария, страница не показывает — её удаляют вручную.

### Свежесть

Эффект свеж, пока совпадают:

- принятое видео комплекта (путь, SHA-256, частота и число кадров);
- версии эффектов;
- полные значения параметров, пересчитанные по текущей точке съёмки плана;
- байты ролика.

Новая приёмка плана, ручной монтаж, изменивший `video.mp4`, разворот камеры при дожде с ветром, новая версия эффекта или правка ролика делают эффект устаревшим. Устаревший эффект в монтаж не идёт: потребители берут принятое видео, а страница эффектов называет причину. Эффект нужно применить заново.

### Где используется

Видео плана для монтажа выбирается в одной точке ([`MontageVideo`](../internal/shoteffects/shoteffects.go)): свежий ролик с эффектом, иначе принятое видео комплекта. Через неё план берут:

- аниматик и его проверка свежести, в том числе в `ROADMAP.md`;
- пробы стыков;
- пакет для монтажёра: `accepted_clip` указывает на ролик с эффектом, строка получает `effect: true`. Сведения о повторной сборке по-прежнему описывают принятое видео комплекта.

Принятое видео без эффекта используют:

- кадры для опор соседних планов;
- ручной монтаж и его применение;
- производные планы.

Эффект — последний слой поверх готового плана.

### Цвет

Ролик с эффектом декодируется в RGB и кодируется обратно с одной и той же матрицей (bt601) и без тегов цвета, как остальные ролики, которые кодирует приложение. Нетронутые эффектом пиксели сохраняют значения YUV принятого видео, даже если оно помечено bt709: в аниматике план с эффектом не отличается по цвету от соседей и от себя без эффекта.

### Дождь и ветер

Погоды на весь клип нет: погода меняется от плана к плану, и дождь — эффект отдельного плана.

Ветер необязателен и задаётся в дожде плана:

- направление — куда дует, в градусах против часовой стрелки от востока, как направление камеры точки съёмки;
- сила — горизонтальная скорость в долях скорости падения.

Экранный наклон капель считается из ветра, направления и наклона камеры первого кадра. Наклон ограничен диапазоном параметра и округлён до 0,1°. Свой наклон плана важнее ветра. Без ветра и своего наклона дождь вертикален. Ветер без точки съёмки с направлением камеры — ошибка: задайте наклон вручную или точку съёмки.

Чтобы соседние планы шли под одним дождём, параметры копируют с другого плана. Наклон из ветра при этом пересчитывается под камеру каждого плана.
