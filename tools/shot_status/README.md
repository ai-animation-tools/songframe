# shot_status

Сводит статусы всех планов из первичных источников: реестр сцен, локальные комплекты в assets, очередь `plan/awaiting`, рабочие попытки в `plan/batches` и реестр работ. Использовать для таблицы планов с отбором `--filter all|planned|progress|completed|stale|unknown`, кандидата следующего плана `--next` и проверки `--independent`, можно ли готовить несколько планов одновременно. Файлы проекта не изменяет, к сервисам не обращается.

```sh
python3 -B tools/shot_status/shot_status.py
python3 -B tools/shot_status/shot_status.py --filter progress
python3 -B tools/shot_status/shot_status.py --next
python3 -B tools/shot_status/shot_status.py --json
python3 -B tools/shot_status/shot_status.py --independent M52 M53 M55
```

Статусы и этапы: `completed` — есть `assets/shots/Mxx/manifest.json`, и комплект принят по текущей постановке плана; `stale` («постановка изменена») — комплект есть, но отпечаток постановки в `plan/production-status.json` → `shots.Mxx.scene_sha256` отсутствует или не совпадает с текущим, либо у производного плана (`derived_from`) источник не готов, отсутствует/повреждён его выбранный клип, сохранённая версия источника неизвестна или отличается от текущей, либо связь источника расходится со сценарием; этап объясняет собственную правку, изменённый материал источника, неизвестный снимок или недоступный источник; для производного плана требуется пересборка и приёмка, новая работа по плану дописывается к этапу. Правило — [принятие планов](../scene_registry/README.md#принятие-планов); `progress` — есть пакет очереди, попытка в `plan/batches` или отметка в реестре работ; `planned` — только постановка; `unknown` — файлы пакета повреждены или этап не определён. Для `progress` показывается фактический этап: из `attempt.json` при отправленной попытке, иначе из `stage` и `wait_reason` в `workflow.json`. Незавершённая проба или альтернативный пакет у готового плана показываются примечанием и не отменяют готовность.

`--next` выводит первый не готовый план (`stale` готовым не считается) в порядке монтажной шкалы и очередь ожидающих пакетов; выбор между ними делает пользователь. `--independent` сообщает конфликты партии: более поздний план наследует состояние после непустых `state_changes` более раннего плана из той же партии; при конфликте код возврата 1 (с `--json` код 0, конфликты только в поле `conflicts`). Отдельно предупреждает о соседних по шкале планах: их стык можно сверить с фактическим кадром только после получения обоих, поэтому в одной партии они допустимы лишь при смене ракурса или намеренном монтажном пропуске, что подтверждает пользователь. Независимые планы можно готовить параллельно; отправка остаётся по одному запросу. `--json` даёт те же данные для приложения: полную сводку, с `--next` — только `next` и `queue`; `--filter` действует лишь на текстовую таблицу и при `--json` не применяется.

## Тесты

Пять статусов, `stale` после правки действия и у производного плана при устаревшем источнике, этапы из очереди и попытки, повреждённый пакет, примечание о пробе, кандидат next и конфликты партии на временной фикстуре проекта.

```sh
python3 -B tools/shot_status/test_shot_status.py
python3 -B tools/run_tests/run_tests.py --only test_shot_status
```

Тесты находятся рядом со скриптом; рабочие сцены не изменяют. Для полного набора — [run_tests](../run_tests/README.md).
