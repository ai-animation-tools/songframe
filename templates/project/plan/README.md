# Содержимое plan

Постановка и монтажная шкала клипа, текущее состояние работы, рабочие пакеты и единственная полная сборка аниматика. Владельцы сведений по всему проекту в [карте навигации](../README.md#источники-сведений), правила в [AGENTS.md](../AGENTS.md). Команды выполняются из папки клипа через проектный launcher: `./.songframe/run-tool` в Linux либо `.\.songframe\run-tool.cmd` в Windows. Он сам передаёт папку проекта; справочники находятся в `.songframe`.

| Путь | Что хранит | Как обновляется |
| --- | --- | --- |
| [project.json](project.json) | Название проекта `name`, имя выходного MP4 `animatic_video` и блок `generation`: провайдер, разрешение, пропорции, логотип, правило длительности запроса | Первичный источник; после изменения обновить представления и карточки |
| `cast.json` | Кастинг: сущности клипа (персонажи, транспорт, локации, предметы, мир и любые другие типы), их изображения в `source`, роль, внешность, начальное состояние и словарь свойств состояния | Первичный источник; создаётся инструментом `cast_registry init` или на странице «Кастинг» приложения; `references` реестра сцен выводятся из него |
| `treatment.json` | Трактовка: логлайн и части песни с временем, действием и участниками; вход каркаса реестра сцен | Первичный источник первого прохода скилла `ai-clip-scenario`; после появления реестра части редактируются в `scenes.json` |
| `scenes.json` | Постановка каждого Mxx, камера, действие, непрерывность, референсы, общие визуальные правила, последовательности, кадровые границы и граф состояния `state_from`/`state_changes` | Первичный источник; постановку и монтажные окна менять только здесь |
| [production-status.json](production-status.json) | Незавершённая работа, следующий шаг, указатель на полную сборку и состояние её просмотра; без копий постановки и параметров генераций | Вручную при изменении состояния работы |
| `storyboard.md` · `edit-list.md` | Читаемая постановка и монтажная таблица | Автоматически из `scenes.json` |
| `context/characters.md` | `visual_direction` реестра и вычисленный список речевых планов | Автоматически |
| `audio/timing.json` · `audio/timing.md` | Оценки начала и конца строк и частей песни, ограничения точности; читаемое представление | Источник вручную или скиллом `ai-clip-audio`; представление автоматически. Монтажные окна не задают |
| [animatic/README.md](animatic/README.md) | Правила, входы и порядок полной сборки | Вручную |
| `animatic/cards/Mxx.png`, `Mxx.last.png` · `cards/manifest.json` | Карточки планов без комплекта: по референсам или из принятых опор (последняя опора отдельно для растворения); опись с хешами PNG, реестра и референсов | Автоматически, инструмент `update_scene_views` комплекса |
| `animatic/latest/` | Манифест-снимок сборки и README; MP4 лежит рядом, но в Git не хранится | Инструмент `build_animatic` комплекса |
| `animatic/.cache/` | Производные фрагменты с квитанциями, вне Git | Инструмент `animatic_cache` комплекса (раздел «Хранение и очистка кэша» его README) |
| `awaiting/Mxx/` | Самодостаточные отложенные пакеты: `workflow.json`, `request.json`, `attempt.json`, входы и промпт | [Контракт очереди](awaiting/README.md) |
| `batches/` | Рабочая подготовка, текущие попытки и пробы; может быть пустой (`.gitkeep`) | Скилл `ai-clip-scene` комплекса · инструмент `build_review` комплекса |
| `montage/` | Сохранённые черновики ручного монтажа: участки исходников на сетке 30 FPS, окно песни и снимок хешей реестра/комплектов | Страница «Монтаж пробы»; сохранение и экспорт не меняют принятые сцены |
| `montage-history/<revision>/` | Применённый черновик, журнал публикации и резервные копии изменённых реестра, манифестов и представлений | `apply_montage`; незавершённая публикация восстанавливается по журналу, история не удаляется автоматически |

Производные файлы (`storyboard.md`, `edit-list.md`, `context/characters.md`, `audio/timing.md`, карточки) появляются после первого обновления представлений; в пустом проекте их нет.

Сохранённые `sections` в `audio/timing.json` задают самостоятельную музыкальную карту. Редактор «Тайминги» показывает её без пересчёта и сохраняет границы, названия и заметки при правке вокальных строк. Если карта отсутствует или пуста, части строятся автоматически. Кнопка «Пересчитать секции» явно заменяет карту по текущим строкам; результат применяется только после сохранения, отмена правок возвращает прежние секции.

Состояние до/после нужного Mxx вычисляет инструмент `scene_registry` комплекса; отдельной редактируемой копии нет. Принятые оригиналы, монтажные клипы, кадры, промпты, WAV и рецепты в [assets/shots/Mxx](../assets/README.md); общие референсы в [source](../source/README.md). Условия очистки пакетов и проб задают скилл и [правила assets](../assets/README.md#очистка-завершённых-видеопроб).

Явное применение ручного монтажа инструментом `apply_montage --spec plan/montage/<имя>.json` меняет выбранные принятые комплекты и их внутренние границы в реестре вместе. Нужны соседние сцены в исходном порядке, прежние внешние границы окна и актуальные хеши. Оригиналы, песня и разметка сохраняются; новые клипы и прежние манифесты остаются в истории [комплектов](../assets/README.md#ручной-монтаж-принятых-сцен). При аварийном завершении отдельный `apply_montage --recover` завершает откат по журналу до дальнейшей работы.
