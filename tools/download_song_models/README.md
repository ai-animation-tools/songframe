# download_song_models

Скачивает один выбранный компонент локальной обработки песни. В окне «Разметить» модель уточнения границ устанавливается отдельно от модели выделения вокала; приложение запускает загрузчик фоновым заданием Jobs. Веса не входят в проект клипа или установщик.

## Запуск и состав

```sh
python3 tools/download_song_models/download_song_models.py --output /absolute/models
python3 tools/download_song_models/download_song_models.py --output /absolute/models --component kim-vocal-2
```

`--output` — обязательная абсолютная папка весов. `--component` выбирает только один из четырёх компонентов; по умолчанию `alignment`. Необязательный `--project` принимает общий запускатель инструментов; загрузчик не читает и не меняет проект. Произвольные URL и иные модели не поддерживаются.

| `--component` | Файлы | Размер, байт |
| --- | --- | ---: |
| `alignment` | `alignment.onnx`, `vocab.json` | 317 350 438 |
| `voc-ft` | `vocals.onnx` (Voc FT) | 66 762 490 |
| `kim-vocal-1` | `kim-vocal-1.onnx` (Kim Vocal 1) | 66 759 214 |
| `kim-vocal-2` | `kim-vocal-2.onnx` (Kim Vocal 2) | 66 759 214 |

Файлы, URL, размеры, SHA-256 и параметры разделения закреплены в [models.json](../song_timing/models.json); происхождение и лицензии — в [song_timing](../song_timing/README.md#модели-и-лицензии). Установленные компоненты используют одну папку, загрузка выбранной модели не скачивает остальные. При замене существующих весов требуется место и под прежний файл, и под загружаемый `.part`.

Приложение передаёт папку моделей из постоянного каталога состояния ОС. Сам загрузчик путь ОС не выбирает и настройку приложения не меняет. Для ручного выделения передайте ту же папку в `--models` у [separate_vocals](../separate_vocals/README.md); `--song-models` у [align_lyrics](../align_lyrics/README.md) использует только компонент `alignment` и уже готовый вокальный результат.

## Происхождение параметров разделения

Веса Voc FT, Kim Vocal 1 и Kim Vocal 2 берутся из [первичного выпуска UVR](https://github.com/TRvlvr/model_repo/releases/tag/all_public_uvr_models). Параметры сверены по настоящим весам и [UVR model_data_new.json](https://github.com/TRvlvr/application_data/blob/4621ca87e42bba17738b6ca0d0b5348763eb68ad/mdx_model_data/model_data_new.json). У всех трёх моделей `fft=7680`, `hop=1024`, `bins=3072`, `frames=256`, `primary_stem=Vocals`; коэффициенты `compensate` равны 1.021, 1.043 и 1.009 соответственно. `frames` получается из `2**mdx_dim_t_set`, фиксированный шаг описан в [UVR separate.py](https://github.com/Anjok07/ultimatevocalremovergui/blob/b20ab2508066b0372631a1b3b5d6b0e04b45d7eb/separate.py).

`uvr_model_hash` в манифесте — служебный ключ UVR: MD5 последних `10000 * 1024` байт файла; для меньшего файла UVR берёт MD5 целиком ([алгоритм UVR](https://github.com/Anjok07/ultimatevocalremovergui/blob/c941cafc76c7c7879277db257195dd1f138cf495/UVR.py#L707-L729)). Это не SHA-256 загрузчика. У Voc FT ключ `77d07b2667ddf05b9e3175941b4454a0`, Kim Vocal 1 — `73492b58195c3b52d34590d5474452f6`, Kim Vocal 2 — `970b3f9492014d18fefeedfe4773cb42`. Предсказание этих весов уже является вокалом; вычитание его из исходного стерео дало бы сопровождение. При выборе других весов назначение выхода определяет `primary_stem`, а не название файла.

## Прогресс, повтор и отмена

Прогресс каждого файла выводится в stdout примерно каждые 5 процентов; готовый файл отмечается «Проверено», уже установленный — «Уже готово». В приложении вывод доступен в журнале задания. Код 0 и сообщение «Модели … готовы» означают, что файлы выбранного компонента прошли проверку размера и SHA-256.

Каждый файл загружается в соседний `<имя>.part`; после проверки размера и SHA-256 `os.replace` атомарно публикует его под рабочим именем. Атомарность относится к одному файлу: готовые файлы сохраняются при сбое следующего. Прежний рабочий файл не удаляется до успешной публикации замены.

После сетевого сбоя, короткого ответа или отмены оставьте `.part` и повторите ту же команду. Загрузчик проверяет готовые файлы и продолжает частичный HTTP Range-запросом; при полном ответе сервера начинает только `.part` заново. Неверный Content-Range вызывает отказ без дописывания данных, в том числе при первом запросе. Неверный SHA-256 или избыточный размер удаляет повреждённый `.part`; следующая попытка скачает файл заново. Ошибка публикации сохраняет проверенный `.part` для повтора без сети. При каждом явном запуске загрузчика выбранные готовые файлы хешируются; обычная проверка наличия в приложении использует имена и размеры.

Ошибка сети, проверки файлов или записи даёт код 1 и причину в stderr; неверные аргументы — 2. Ctrl-C и SIGTERM от Jobs дают код 130 без traceback, оставляя закрытый `.part` для докачки. Прежние проверенные файлы сохраняются. Тайм-аут сетевой операции — 60 секунд, автоматических повторов нет: повтор запускает пользователь.

## Тесты

Адресные проверки без сети проверяют выбор компонента и значение по умолчанию, публикацию после SHA-256, сохранение прежних весов при неверном хеше, докачку короткого ответа, сервер без Range, неверные границы Range, превышение размера, уже готовый файл, полный `.part`, Ctrl-C/SIGTERM, отказ создания папки и отказ атомарной замены с последующим повтором.

```sh
python3 -B tools/run_tests/run_tests.py --only test_download_song_models
```

Реальная загрузка и CPU ONNX-проба выполняются отдельно во временной папке по [инструкции модуля](../song_timing/README.md#проверки). Подставной HTTP в тестах не доказывает доступность текущего CDN или качество выделения вокала на песне.
