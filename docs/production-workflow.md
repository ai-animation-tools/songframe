# Производство плана через приложение

Страница «Производство» ведёт один выбранный план `Mxx` и один его рабочий пакет. Агент готовит предложение, приложение показывает его до записи, пользователь применяет предложение и отдельно согласует сохранённые материалы. Описание, опоры, видеопромпт, платный запрос, полученный ролик и принятый монтаж имеют отдельные решения.

Новая подготовка требует актуального утверждённого сценария и заполненных настроек `generation` на странице «Проект». Глобальный текстовый агент Claude Code/Codex и проектные `generation.video`/`generation.image` независимы. При провайдере Codex поле `generation.image.model` выбирает модель агента, который вызывает image_gen; оно не переключает внутреннюю модель генератора. Codex CLI находится автоматическим поиском, как и текстовый агент. При явном Codex backend пустая модель означает «Как указано в Codex CLI»: параметр --model не передаётся, скрытая модель старого профиля не подставляется. Старый профиль сохраняется как данные совместимости, а fallback действует только для прямых старых вызовов без image backend. Image backend выбирается как Codex или Kling; video backend — Kling. Python нужен для производственных инструментов, Kling CLI — для чтения возможностей аккаунта, проверки остатка, отправки и получения. Просмотр сохранённых материалов не запускает агентный CLI или Python-инструменты.

## От описания до запроса

1. Выберите план и нажмите «Подготовить описание». Приложение передаст агенту постановку выбранного плана, нужные сущности кастинга и референсы, врезки непрерывности, настройки, текущие материалы и замечание, если оно есть. Текстовый агент работает в режиме чтения и возвращает один JSON. Завершение задания показывает предложение; новый пакет ещё не создаётся.
2. Просмотрите описание, длительность запроса и промпты опор. «Применить предложение» создаёт новый `plan/batches/Mxx-attempt-NN`, сохраняет описание и план опор, затем задаёт вопрос согласования. Нажатие «Принять» подтверждает описание; применение само его не принимает.
3. После принятия описания используйте выбранный image backend: «Создать опоры в Codex» запускает отдельное задание, «Подготовить запрос изображения (Kling)» готовит один frozen request для одной Kxx без отправки. Для Kling отдельно подтверждаются SHA и стоимость; после получения выбирается original кнопкой «Выбрать как опору». Также можно импортировать свои PNG, JPEG или WebP через «Показать кандидаты» и применить предложение. Каждый маршрут регистрирует кандидатов с `approved: false`; после всех нужных кандидатов требуется отдельный ответ на `keyframes_review`.
4. После принятия опор «Продолжить подготовку» запрашивает видеопромпт у текстового агента. Применение сохраняет `video-prompt.txt` и задаёт вопрос о промпте. Принятие фиксирует хеш сохранённого текста.
5. После принятия промпта «Продолжить подготовку» запрашивает спецификацию Kling. Приложение проверяет ответ, разрешает только объявленные исходники и утверждённые опоры, затем отдельным Apply вызывает локальный `kling_request prepare`. Возникает новая папка `request-NN` с точным промптом, копиями входов, хешами и `request_sha256`. Существующая папка запроса не перезаписывается. Пакет переходит к `request_choice`; генерация ещё не отправлена.

Опоры имеют последовательные ID `K01`, `K02`, …, первую точку в `0`, последнюю на границе `requestSeconds` и при необходимости промежуточные точки. Длительность целая и соответствует `generation.video.duration_rule`. Для выбора модели и проверки параметров используются актуальные объявления `kling_request capabilities`; приложение не хранит собственный список моделей и не выдумывает их лимиты. Если возможности аккаунта недоступны, подготовка запроса заканчивается диагностикой, сохранённые материалы остаются доступны. Для липсинка нужен подготовленный точный WAV; отсутствие подходящего файла сообщается до подготовки запроса.

На вопросы согласования нужно ответить до следующего этапа; под вопросом перечислены последствия каждого ответа. Пока вопрос не отвечен, блок «Подготовка плана» своё поле замечания не показывает: замечание вводится у вопроса. «Вернуть с замечанием» требует текст исправления и сохраняет ответ; для пакета приложения это действие само не запускает агента. После возврата карточка показывает сохранённое замечание и кнопку «Перейти к доработке». В блоке «Подготовка плана» замечание уже заполнено: его можно уточнить, затем нажать «Запустить доработку с агентом». Только это нажатие запускает задание. Агент готовит предложение, которое пользователь отдельно просматривает и применяет; платная генерация по-прежнему требует своего согласования. Доработка готового повтора без актуальных утверждений опор и промпта возвращается к более раннему доступному этапу, сохраняя прежний замороженный запрос и его файлы. Совместимые принятые опоры сохраняются: проверяются роль, время, промпт и референсы; порядок ключей JSON на совместимость не влияет. Для изменённых опор требуется новое изображение и принятие. Изменение видеопромпта отменяет его прежнее подтверждение и требует подготовки новой таблицы запроса.

## Изображения и профили CLI

Текстовый проход использует `agents.start` с правами чтения и глобально выбранным Claude Code или Codex. Проектный `generation.image.provider` выбирает `CodexImageProvider` или `KlingImageProvider`, `generation.video.provider` — `KlingVideoProvider`. Codex CLI находится автоматическим поиском, модель агента — из `generation.image.model` проекта. Пустая модель означает конфигурацию Codex CLI без `--model`. Он не переключает текстового исполнителя, модель генерации Kling или настройки другого медиа.

При Codex `AgentManager.startImages` запускает отдельное задание с `workspace-write` в `localDir/image-jobs/<UUID>` и копиями референсов. До Apply кадры остаются кандидатами вне проекта. Наличие CLI — только проверка запуска; проверка каталога моделей агента не подтверждает доступность встроенного `image_gen` конкретному аккаунту. Недоступный image tool сообщает ошибку; импорт своих опор остаётся доступен. Размеры и форматы определяет исполнитель, селекторы image формата/alpha из video capabilities не придумываются.

При Kling приложение запрашивает актуальные capabilities для T2I/I2I и проверяет пару command/model, аргументы, allowed values, обязательные слоты и cardinality. Предпочтения `generation.image` — model, resolution/aspect ratio, outputs и options — не считаются доказанными возможностями. Фактический image-аргумент может называться `img_resolution`; формат референса на входе и формат скачанного оригинала проверяются отдельно. Для видео действует собственный snapshot capabilities и `generation.video`; универсального ограничения «21:9 только v4» для изображений нет.

Цикл одного image-запроса: `set-image-request` → `image_request_choice` (`send/park/revise`) → отдельный `quote` и подтверждение SHA/цены → один `submit` → `image_submitted` → `resume` того же ID → `image_downloaded` → `select-image`. История `image_requests` хранится отдельно от video `request_dir`. Выбор скачанного original копирует его без перекодирования в кандидата Kxx с `approved: false`; исходный original и принятые опоры сохраняются. Для следующей Kxx готовится своя попытка, после всех кандидатов отдельно задаётся `keyframes_review`. Скачивание и выбор не утверждают кадр и не принимают assets.

Старый плоский `generation` читается как прежние video-настройки с совместимым image backend Codex. Открытие проекта не записывает миграцию. Явное сохранение пишет вложенные `video`/`image`, сохраняет неизвестные поля и options; отсутствующий блок добавляется явно. Незнакомые провайдеры и значения показываются без сброса, существующие frozen requests остаются неизменными. Приложение проверяет реальные файлы кандидатов, ID, размеры/форматы и неизменность референсов. [Менеджер заданий и история](agents.md) общие для текстовых проходов и Codex изображений.

## Настройки генерации

Для Kling пункт «Автоматически по задаче» выбирает модель, совместимую с требованиями плана. Указанная модель — предпочтение: адаптер проверяет её, затем модель, предложенную агентом для задачи, и остальные объявления той же команды. Длительность, разрешение, число результатов и референсы не уменьшаются ради предпочтения. Если замены нет, подготовка сообщает причины. Обоснование `model_selection` входит в замороженный запрос и SHA, показывается в карточке и диалоге отправки. При получении результата модель не выбирается повторно.

Модели и пропорции выбираются обычными Select. Разрешения и пропорции зависят от предпочтительной модели; при автоматическом подборе объединяются доступные варианты. Подтверждённые ошибки полей подсвечиваются красным и блокируют сохранение. Недоступный или частично полученный каталог CLI не считается доказательством несовместимости значения.

Для изображений Kling используются начальные значения `2k`, `16:9` и один вариант. Ранее сохранённые явные значения остаются прежними. Несколько вариантов одного опорного кадра возвращаются одним запросом, стоимость зависит от выбранной конфигурации.

При Codex пункт «Как указано в Codex CLI» не передаёт `--model` и не подставляет скрытое значение старого профиля. Каталог моделей агента читается штатным `model/list`; этот выбор не переключает внутреннюю модель `image_gen`. Исполнитель создаёт один вариант каждой опоры и не применяет параметры `resolution`, `aspect_ratio` и `outputs` Kling. Поэтому шаблон Codex не содержит этих полей; они добавляются при выборе Kling и убираются при явном переходе на Codex. Неизвестные расширения настроек сохраняются.

Размер через текст запроса `image_gen` не гарантируется: горизонтальное изображение может иметь `1672×941` даже при запросе 4K. Приложение напоминает об этом ограничении. Это наблюдаемый размер, а не объявленный универсальный максимум инструмента.

Новые запросы не разрешают `watermark=true`; если модель объявляет этот параметр, он выключается явно. Старая настройка допустимого логотипа не влияет на подготовку. Получение предпочитает явный адрес без водяного знака. Видео без такой ссылки продолжает ожидать тот же ID; для изображения при отсутствии отдельной ссылки используется original URL сервиса. Локальный инструмент сохраняет байты и не удаляет логотипы из изображения.

## Платная отправка

Откройте подтверждение image- или video-запроса. Диалог показывает замороженный промпт, модель, параметры, входы и `request_sha256`, затем запрашивает стоимость и остаток кредитов. Проверка остатка обращается к информационной команде Kling `account`; оценка стоимости использует штатный [cost_check](../tools/cost_check/README.md) и локальные тарифы или наблюдения. Для image наблюдение совпадает по модели, команде, полному JSON значимых параметров, outputs и входным слотам/ролям/числу референсов; цена T2I не переносится на I2I, иное разрешение, quality или count. Неизвестная цена не заполняется глобальной догадкой «1 кредит».

Если цена неизвестна, приложение показывает «Стоимость: неизвестно» и кнопку «Я согласен». Она разрешает неизвестное списание только для показанной оценки и одной попытки. После согласия нужно проверить промпт и нажать «Отправить и списать кредиты». Обновление оценки, смена запроса или новая попытка требуют нового согласия, даже если промпт и SHA прежние. Известная нехватка средств и неизвестный остаток при известной цене блокируют отправку. Кнопка «Обновить стоимость» повторяет проверку без генерации. При известной цене и достаточном остатке отдельная кнопка «Отправить и списать кредиты» разрешает отправить именно показанный запрос. Перед отправкой главный процесс повторно проверяет стоимость, остаток, материалы и одноразовое подтверждение. Изменившийся запрос или стоимость требуют нового просмотра и подтверждения. Apply описания, кадров, промпта или спецификации разрешения на расход не даёт.

На странице «Производство» кнопка «Очередь (N)» показывает сохранённые неотправленные запросы, в том числе запросы уже принятых сцен. После «Сохранить в очередь» приложение открывает этот список и сохраняет выбор перенесённого пакета, даже когда его папка переименована в ID плана. Сохранение не запускает генерацию автоматически. Нажмите «Открыть запрос» у нужного пакета, затем «Отправить», чтобы проверить материалы и заново подтвердить платную отправку. Отложенный пакет со стадией `ready` отправляется по уже подготовленному запросу. Папка запроса, его входы и `request_sha256` сохраняются; создавать новый `request-NN` для продолжения не нужно. Цена и остаток проверяются заново, затем пользователь отдельно подтверждает отправку. Прежнее согласование или сохранение в очередь не заменяют нового подтверждения. Отложенный запрос убирается из очереди кнопкой «Отказаться от попытки» в открытом пакете. Папка в `plan/awaiting` или папка попытки в `plan/batches` без `workflow.json` (след прерванной операции) показывается в очереди и у плана как повреждённая с кнопкой «Удалить папку»: пока она есть, `shot_workflow park` отказывает сообщением «уже есть в очереди».

После отправки `watch`/`resume` получает состояние того же задания. Для video сохраняется original без логотипа; полностью полученный video переводит пакет в `downloaded` и создаёт вопрос просмотра. Для image получается `image_downloaded` с выбором кандидата, затем отдельным утверждением опор. PNG/JPEG/WebP определяется по сигнатуре полученных байтов, включая opaque URL; original сохраняется без перекодирования. Перед публикацией записывается intent с конечным путём/размером/SHA; после обрыва опубликованный original проверяется и принимается без повторной загрузки или submit. Ошибка сервиса или незавершённое скачивание не создают готовый результат для приёмки. Техническая сводка сопровождает просмотр, но не заменяет решение пользователя. Ответ «Собрать пробу» у пакета приложения открывает страницу «Монтаж пробы» с соседними планами и ставит на дорожку сцены результат показанной попытки (параметр `source=Mxx:путь`); страница предупреждает, что этот ролик не принят, а принятый клип сцены остаётся в материалах с подписью «Принятый». Вопрос о результате остаётся открытым. Если вопрос уже снят прежним ответом, кнопка «Вернуть вопрос о результате» задаёт его снова. Кнопка «Отказаться от попытки» внизу карточки пакета после подтверждения удаляет папку попытки целиком, включая оплаченный оригинал (кредиты не возвращаются); она недоступна принятому пакету, незавершённой отправке и пакету, на который ссылается сохранённый черновик монтажа. После удаления снова доступны новая подготовка и «Подготовить повтор»; то же действие убирает сохранённый запрос из очереди.

## Неизвестный исход и новая попытка

`submitting` и `submission_unknown` означают, что запрос мог быть оплачен. Повторная отправка этой попытки запрещена. Если ID уже записан, используйте «Продолжить получение». Если ID отсутствует, сначала установите ID существующей генерации в Kling, затем введите его в поле «ID существующей генерации Kling» и нажмите «Указать ID и проверить». Эта операция привязывает установленный ID и выполняет получение; нового запроса на генерацию в ней нет. Существующий ID нельзя заменить другим.

Доработка после платной отправки создаёт новый пакет с `retry_of`: старый пакет, журнал попытки и оригиналы сохраняются. Действие «Подготовить повтор» по сохранённому запросу также только создаёт новую попытку; то же делает ответ «Повторить запрос» на вопрос о результате. Созданный пакет открывается на странице сам, его таблицу, цену и платную отправку нужно подтвердить отдельно. У принятой сцены карточка плана показывает пакеты, ждущие решения, с кнопкой «Открыть пакет». В списке планов и на панели страницы план помечается «ждёт вас», когда его пакет ждёт действия пользователя: открытый вопрос, подготовленный запрос без отправки, записанное замечание без запущенной доработки, неизвестный исход отправки или полученный результат; фильтр «Ждут вашего действия» показывает только такие планы. Список планов — сетка карточек, как на странице «Сцены»: при широком окне три карточки в ряд, выбранный план справа закреплён под панелью действий и прокручивается внутри себя; при узком окне карточки заполняют всю ширину, а выбранный план показывается ниже. Выбранная карточка прокручивается в видимую область сама. Для принятого комплекта используются сохранённые команда, модель, параметры, промпт и входы; снимок комплекта использует единый формат с явным `provider` исходной генерации, строковым `prompt`, `prompt_sha256`, явными `command`, `model`, `parameters`, `inputs` и `outputs`. Повтор сравнивает сохранённого провайдера с выбранным в проекте; имена сравниваются без учёта регистра и крайних пробелов. Подготовка копирует запрос локально и не требует доступности ИИ или входа в сервис. Отправка использует только подключённый адаптер этого провайдера: отсутствие адаптера не подменяет провайдера и не разрешает отправку через другой сервис. Если нужных сведений нет или файлы не совпадают с сохранёнными хешами, подготовка останавливается с объяснением. Пока исход прежней отправки неизвестен, подготовка такого повтора блокируется.

## Приёмка и аниматик

Image original сначала выбирается как кандидат и отдельно утверждается на `keyframes_review`; это не video-приёмка и не команда «Принять в assets». Скачанный video original сначала просматривается пользователем. Приёмка — отдельное действие с выбранным полным роликом или монтажным участком и параметрами обработки. Она связана с показанными оригиналами; изменение результата требует нового просмотра. Перенос в `assets` выполняет штатный `accept_shot`. Если у сцены уже есть принятый комплект, диалог приёмки предупреждает о замене и требует явного согласия: новый комплект занимает `assets/shots/Mxx`, прежний целиком переезжает в `assets/replaced/Mxx/<время>` (`accept_shot --replace`), оплаченные оригиналы и манифест сохраняются, аниматик после замены устаревает. Согласование запроса и факт скачивания сами по себе не принимают сцену.

Принятие сцены также не принимает и не пересобирает аниматик. Его свежесть проверяется по фактическим входам: реестру, настройкам, аудио, выбранным принятым клипам или опорам, их хешам и MP4 сборки. Изменение входа делает прежнюю сборку устаревшей, даже если постановка плана не менялась. На странице «Аниматик» требуется отдельная сборка и принятие; история прежнего утверждения сохраняется, но оно не считается текущим для устаревшего результата.

## Черновики, ошибки и восстановление

Предложения хранятся в `localDir/production-workflow`, а не в проекте. Они переживают перезапуск и связаны со снимком использованных входов, настроек, состава и выходов пакета, включая отсутствие будущих файлов, а также с хешами кандидатов. Изменение материалов делает предложение устаревшим. Невалидный JSON, ошибка CLI, отмена или прерывание не применяют предложение.

Изменение декоративной обложки и времени сохранения `source/manifest.json` не меняет снимок производственных входов и показанное согласование. Трек, идея, текст, референсы и остальные содержательные поля по-прежнему проверяются. Подробный ход заданий и результаты инструментов находятся на странице «Журнал заданий»; на странице производства остаются текущие действия и статус.

Перед неплатным Apply сохраняется резерв изменяемого пакета в `localDir/production-apply`. При ошибке возвращаются прежние файлы и отсутствие новых. После аварийного закрытия оконный запуск восстанавливает незавершённую замену. Если проект недоступен или восстановление не завершилось, приложение сообщает ошибку, сохраняет резерв и закрывает текущий проект; другие проекты доступны. Платная попытка автоматически не откатывается и не перезаписывается. Источники и принятые `assets` не входят в заменяемый пакет.

Локальное агентное задание можно остановить общей кнопкой агента. Это не отменяет уже отправленную Kling генерацию: по [официальному руководству](https://kling.ai/app/mcp/guide) отмены после submit нет, результаты нужно получить в течение срока доступности (24 часа). Автоматического повторного запуска CLI или платной отправки после перезапуска нет. Один проект не получает два одновременных агентных задания; операции отправки и получения также учитывают занятость выбранного пакета.

## Контракт приложения

Форма предложений и представления задана в [src/shared/production-workflow.ts](../src/shared/production-workflow.ts), публичный API — в [src/shared/api.ts](../src/shared/api.ts).

| API                                                  | Назначение                                                                                                                         |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `productionWorkflow.view` / `start`                  | Прочитать состояние выбранного плана или запустить текстовое предложение                                                           |
| `productionWorkflow.apply` / `discard`               | Применить актуальное предложение или отклонить его                                                                                 |
| `productionWorkflow.generateFrames` / `importFrames` | По image backend запустить Codex задание либо подготовить одну frozen Kling image-попытку без submit; импортировать свои кандидаты |
| `agents.cancel` / `get` / `onEvent`                  | Остановка, история и поток задания                                                                                                 |
| `production.decide`                                  | Ответить на актуальный вопрос пакета                                                                                               |
| `production.quote` / `submit`                        | Получить стоимость и отдельно подтвердить точный запрос одноразовым подтверждением                                                 |
| `production.resume`                                  | Получить существующее задание, при неизвестной отправке — по установленному ID                                                     |
| `production.selectImage`                             | Выбрать original image по индексу и resultToken как кандидата; утверждение опоры отдельно                                          |
| `media.capabilities`                                 | Прочитать актуальные возможности выбранного image/video backend без генерации                                                      |
| `production.accept`                                  | Принять отдельно просмотренный результат с привязкой к его снимку                                                                  |

Для текстового режима приложение передаёт через stdin [ai-clip-scene](../skills/ai-clip-scene/SKILL.md) и [контракт предложений](../skills/ai-clip-scene/references/app-proposal.md). Режим `output=proposal` возвращает данные без записи файлов и вызова инструментов; вопросы согласования записывает приложение.

Реестр провайдеров, контракты адаптеров и capabilities описаны в [src/shared/media-providers.ts](../src/shared/media-providers.ts). Новый провайдер добавляется записью реестра (виды медиа, исполнитель-агент или прямой вызов, платность, параметры запроса) и реализацией в таблицах главного процесса, заданных как `Record` по провайдеру: пропуск останавливает `yarn typecheck`. Оба image backend работают в одном workflow, который ведёт приложение. Разработка и CI используют Node.js 24 по `.nvmrc`; Kling остаётся внешним CLI, его объявления аккаунта проверяются отдельно.

## Проверка реализации

[Сквозной тест](../src/main/production-integration.test.ts) проходит описание, опоры, промпт, подготовку, оценку стоимости и получение через настоящие менеджеры приложения и PythonLauncher с подставными CLI. Счётчик отправок и хеши защищённых материалов проверяют отсутствие лишнего submit и изменений исходников.

[Предметные тесты](../src/main/production-workflow.test.ts) проверяют этапы, устаревание, совместимость опор, новый пакет после платной попытки, откат и восстановление. Тесты [кандидатов](../src/main/keyframe-images.test.ts), [процессов изображений](../src/main/agent-image-jobs.test.ts) и [профилей](../src/main/settings-profiles.test.ts) проверяют отдельные контракты.

```sh
yarn test src/main/production-integration.test.ts src/main/production-workflow.test.ts src/main/keyframe-images.test.ts src/main/agent-image-jobs.test.ts src/main/settings-profiles.test.ts
```

Подставные CLI проверяют файловый и процессный контракт без платных запросов. Доступ конкретного аккаунта к моделям и фактической генерации проверяется отдельно при явном запуске пользователя. Менеджер заданий внешних Claude/Codex поддерживает только Linux. Встроенный Kling и локальные Python-инструменты поставляются также для Windows; проверка runtime и распознавания не подтверждает полный производственный цикл.
