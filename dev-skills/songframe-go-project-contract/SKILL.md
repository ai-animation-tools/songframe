# Контракты проектов SongFrame

Работай в корне репозитория, сначала прочитай `AGENTS.md`. Шаблон проекта — `resources/templates/project` ([resources](../../resources/README.md)), поведение Electron-версии закреплено эталонами `testdata/golden/`. Скилл не разрешает изменять настоящий клип пользователя. Проектные требования из приватного плана, если он есть в рабочей области, читай адресно по задаче; не копируй их в код или скилл.

## Граница и владельцы

До изменения найди фактических производителей и потребителей поля/пути через поиск. Определи владельца данных, правила чтения/записи и производные представления. Чтение проектов сейчас принадлежит `internal/project/`, сервисы и DTO Wails — `internal/app/`, профиль — `internal/store/`; `frontend/src/platform/` отображает `window.api` на сгенерированные bindings без ручной проверки ответов Go (пустые массивы гарантирует Go, типы сверяет `typecheck`); общие типы/чистая логика находятся в `frontend/src/shared/`. Это текущие границы, а не требование переносить туда будущую несвязанную область.

Принятый JSON-формат сохраняется при миграции: не вводи несовместимый новый формат только ради удобства Go-структуры, скрытые fallback, миграцию при открытии или обход файлов старого Git. Изменение формата меняет результат работы программы: его делают только с согласия пользователя. Замороженный `songframe` не меняется. Внутренние Go-структуры и DTO выбирай сам, если записываемый JSON остаётся прежним. Не подменяй отсутствующий Go-писатель изменением старого шаблона или Python-рецепта.

На границе проверяй структуру, конечность чисел и полезные диагностические ошибки. Сохраняй неизвестные поля, различия отсутствующего ключа/`null`/`[]`, порядок строк и CRLF/LF, ручные секунды без округления, `verified`, пользовательские заметки, оригиналы и решения. Системные заметки отличай по полному признаку происхождения, а не похожему началу текста. Условия и блокеры незавершённой публикации не превращай в автоматический rollback при чтении.

Открытие и повторное чтение проекта ничего не записывают в его дерево. Пути проекта относительны его корню; вычисленные абсолютные пути и временные loopback media URL допустимы в DTO текущего сеанса, но не становятся новым сохраняемым форматом. Профиль приложения отдельный, служебные файлы и копии скиллов в проекте не создаются. Если по текущему поручению добавляется запись, её отказ/отмена должны сохранять прежние файлы пригодными для чтения; проверяй собственную атомарную границу и восстановление, не добавляй вторую систему журналов по инерции.

## Проверки сохранности

Прочитай `testdata/contracts/README.md`. Поведение доменов сверяй с эталонами замороженного оригинала в `testdata/golden/`, промежуточные сценарии с записью — на тестовом клипе или копии в отдельном Git с откатом после проверки; готовый клип пользователя — только на чтение. Общие синтетические `api.json`/`recovery.json` проверяют Go и TypeScript; ожидаемый JSON не пересоздавай из текущей реализации автоматически. При изменении контракта согласованно обнови эталон, Go/TS-потребителей и тесты с объяснением результата. Фикстуры не требуют соседних репозиториев, профилей, медиа пользователя или платных сервисов.

Проверяй на временных копиях: hash/имена файлов до и после чтения, перенос в другой Unicode-путь, повторное открытие, неизвестные поля, повреждённые/неполные документы и сохранность оригиналов при отказах. Текстовые media-заглушки контрактного набора не доказывают воспроизведение кодеков.

Из корня выполняй `wails3 task check:contracts`; адресно — `go test ./internal/project ./internal/app ./internal/store -run Contract`, из `frontend/` — `yarn vitest run src/platform/contracts.test.ts`. Для изменённой доменной логики добавь/запусти тесты её пакета; для Wails API выполни `wails3 task bindings` и `wails3 task check:frontend`. Generated bindings вручную не правь. Если контракт влияет на UI, применяй `songframe-go-ui` и обновляй истории страницы/модели API.

Промпты, шаблон проекта и указания провайдеров — встроенные ресурсы Go-версии; форматы промптов и ответов агента сохраняй у их фактических Go-владельцев, не создавай каталог production-скиллов по образцу Electron. В результате назови изменённый контракт, проверки обеих сторон и неперенесённые части. Нативный Windows-прогон требует отдельного поручения.
