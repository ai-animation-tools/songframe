# lint_registry

Проверяет, что сведения лежат у своих владельцев: реестр сцен, комплекты assets и рабочие пакеты соответствуют схемам, в постановке нет хроники принятий и технических рецептов, референсы живут в `source`, снимки запросов не содержат времени, состояния и баланса. Использовать перед порученным коммитом и после любой правки `plan/scenes.json` или комплекта. Файлы не изменяет.

```sh
python3 -B tools/lint_registry/lint_registry.py
python3 -B tools/lint_registry/lint_registry.py --json
python3 -B tools/lint_registry/lint_registry.py --strict
```

Код возврата 1 при ошибках; `--strict` считает ошибками и предупреждения. Схемы форматов лежат в [schemas/](schemas/): `scenes` (реестр), `cast` (кастинг `plan/cast.json`), `manifest` (комплект assets), `request` (общий замороженный запрос с явным `provider`), `workflow` (пакет `shot_workflow`). Это подмножество JSON Schema без внешних библиотек: `type`, `const`, `enum`, `required`, `properties`, `additionalProperties`, `items`, `pattern`, `minimum`, `minItems`, `minLength`, `anyOf`, `$ref`. Схемы — контракт форматов; описания в README остаются пояснениями.

## Правила

| Проверка | Уровень | Где |
| --- | --- | --- |
| Схема реестра; ссылки `references` только на изображения в `source` | ошибка | `plan/scenes.json` |
| Хроника и рецепты в постановке: факты принятия, номера версий, пробы, пути в assets, `manifest.json`, архив, прежние версии, участки и скорости обрезки, факты сохранения | ошибка в `action`, `continuity`, `notes`, `direction`; предупреждение в `visual_direction` | `plan/scenes.json` |
| Ссылка на производное представление (`edit-list.md`, `production-status.json`) из постановки | предупреждение | `direction` |
| Референс-изображение из assets в визуальном справочнике | ошибка; ссылка на принятое видео как ориентир непрерывности — предупреждение | `visual_direction` |
| Неизвестный референс или главный референс карточки | ошибка | сцены |
| Кастинг (если файл есть): схема `cast`, правила `cast_registry`, изображения сущностей в `source`; карта `references` реестра совпадает с выведенной из кастинга (иначе — `cast_registry sync`) | ошибка | `plan/cast.json`, `plan/scenes.json` |
| В кастинге нет сущности `world` | предупреждение | `plan/cast.json` |
| `derived_from`: форма `{"shot": "Mxx"}` (схема); ссылка на неизвестный план, на сам план или на план, который сам производный (`Mxx.derived_from`), — правила [scene_registry](../scene_registry/README.md#производный-план-derived_from) | ошибка | сцены |
| Герой из `references` не упомянут в сценарии | предупреждение | `source/description.md` |
| Схема манифеста; снимок запроса обязателен | ошибка | `assets/shots/*/manifest.json` |
| Служебные поля в снимке запроса (время, состояние, баланс, цена) | ошибка | `generation-request.json` |
| Снимок без модели, промпта, команды с параметрами или `provider`, без ключа `generation_id`; `null` без `provenance` | ошибка | `generation-request.json` |
| Прежние имена полей снимка (`generationId`, `arguments`, `prompt_file`/`prompt_path`, `service`) засчитываются как канонические с предупреждением: снимки оплаченных отправок неизменны (то же исключение, что у [повтора](../regenerate_shot/README.md)) | предупреждение | `generation-request.json` |
| Предупреждения адаптера провайдера о снимке (необязательная `snapshot_warnings`, [интерфейс адаптера](../media_request/README.md#адаптеры)); ограничения сервиса для нового запроса проверяет адаптер при подготовке, а не этот инструмент | предупреждение | `generation-request.json` |
| Схема `request`: замороженный запрос без непустого `provider`; общая схема не ограничивает сервис, его команды, модели и число результатов сверху | ошибка | `request.json` в пакетах |
| Схема `workflow.json`; пакет в очереди на допустимом этапе | ошибка | `plan/awaiting`, `plan/batches` |
| Поле `shots` статуса производства: объект `{"Mxx": {"scene_sha256": "<64 hex>"}}` ([принятие планов](../scene_registry/README.md#принятие-планов)) | ошибка | `plan/production-status.json` |
| Отпечаток принятия плана, которого нет в реестре или у которого нет комплекта в assets | предупреждение | `plan/production-status.json` |

Правила о хронике намеренно узкие: слова «принято», «ускорение», «сохраняются» в сюжетном смысле не считаются нарушением; нарушением считается связка с пробой, участком, клипом, версией или путём в assets. Ложное срабатывание исправляется уточнением образца в `HISTORY_PATTERNS`, а не отключением проверки.

## Тесты

Чистая фикстура без ошибок, хроника и рецепты против сюжетных слов, нарушения схем и референс вне `source`, состав снимка и пакеты, кастинг (схема, изображения в `source`, сущность `world`, совпадение карты `references`), отсутствие героя в сценарии, форма и адресаты отпечатков принятия в `plan/production-status.json`. Для замороженного запроса проверяются обязательный явный провайдер и независимость общей схемы от команд, моделей, флагов и лимитов сервиса; модельные предупреждения о снимке даёт только адаптер провайдера (`snapshot_warnings`), что проверяется на тестовом провайдере.

```sh
python3 -B tools/lint_registry/test_lint_registry.py
python3 -B tools/run_tests/run_tests.py --only test_lint_registry
```

Тесты находятся рядом со скриптом; рабочие файлы проекта не изменяют. Для полного набора — [run_tests](../run_tests/README.md).
