# Задания Claude Code и Codex

Менеджер заданий работает в главном процессе Electron на Linux. Настройки агента общие для проектов и читаются из существующего `SettingsStore`. Каждый запуск фиксирует провайдера и модель: изменение настроек не переключает уже работающий процесс. Python Jobs сохраняет прежний контракт.

## Провайдеры и адаптеры

Остальной код работает с агентом только через `AgentManager` и реестр провайдеров, не проверяя, какой CLI выбран. Новый CLI подключается в трёх местах:

- `src/shared/agent-providers.ts` — запись реестра: название, имя исполняемого файла, каталог навыков проекта, команды входа и проверки, ссылки на инструкции. Из реестра берутся варианты в настройках, подписи, уведомления, проверка сохранённых настроек и истории, каталоги управляемых навыков.
- `src/main/agent-probes.ts` — распознавание версии и входа: аргументы команды статуса и разбор её ответа. Поиск файла, запуск, таймауты и общие ошибки остаются в `checkAgent`.
- `src/main/agent-adapters.ts` — адаптер `AgentAdapter`: аргументы запуска для режимов `read` и `write`, разбор потока событий в общие `AgentUpdate` и чтение аккаунта. Режим, который CLI не поддерживает, адаптер отклоняет до запуска процесса.

Знак провайдера добавляется в `AgentIcon`. Таблицы реестра, проверок, адаптеров и знаков заданы как `Record` по провайдеру, поэтому пропущенное место останавливает `yarn typecheck`. Генерация опор через Codex относится к провайдерам медиа (`generation.image.provider`), а не к реестру текстовых агентов.

## Назначение и права

Текстовый агент готовит предложение. Промпт и необязательный контекст передаются через stdin; в аргументах находятся настройки CLI. `cwd` соответствует выбранной папке проекта, режим разрешений — чтение. Shell для запуска не используется. Сценарные и производственные предложения применяются отдельными доменными действиями после просмотра. Не нужно устанавливать отдельную подсистему изоляции или менять настройки Linux.

Claude запускается с `-p --input-format text --output-format stream-json --verbose --include-partial-messages`, инструментами `Read,Glob,Grep` и `--permission-mode dontAsk`. Codex запускается с `-a never exec --json --sandbox read-only --skip-git-repo-check --color never -`. Пустая модель использует настройки самого CLI. Поддерживается стабильный контракт Claude 2.1.x и новее в рамках 2.x, Codex 0.159.x и новее в рамках 0.x; другая основная версия и prerelease требуют проверки адаптера. Для старых выпусков, не поддерживающих эти флаги, приложение предлагает обновить CLI. Параметры запуска описаны в [документации Claude](https://code.claude.com/docs/en/headless) и [Codex](https://learn.chatgpt.com/docs/non-interactive-mode).

Отдельный внутренний маршрут `AgentManager.startImages` запускает адаптер в режиме `write`: Codex получает те же аргументы с `--sandbox workspace-write` вместо `read-only`, Claude этот режим отклоняет. Рабочая папка `cwd` — `localDir/image-jobs/<UUID>`. Он получает копии референсов и создаёт только кандидаты опор. При `generation.image.provider=codex` модель агента берётся из `generation.image.model`; пустое значение запускает Codex без `--model`, по его конфигурации CLI. Каталог моделей читается через Codex CLI. Выбор модели агента не переключает внутреннюю модель `image_gen`, а текстовый провайдер и его модель сохраняются. Маршрут создаёт один вариант каждой опоры; параметры количества, разрешения и пропорций Kling к нему не применяются. Прямого `startImages` в preload нет: маршрут вызывается через предметный `productionWorkflow.generateFrames`. Подробности создания, импорта и согласования — в [производственном процессе](production-workflow.md).

Это обычные режимы разрешений доверенного пользовательского CLI. Приложение не добавляет флаги обхода разрешений. Настройки, hooks и внешние интеграции установленного пользователем CLI остаются его ответственностью; собственную систему управления ими приложение не создаёт. Изменение файлов проекта по результату предложения относится к отдельному согласованию и в общий `agents.start` не входит. Отправка Kling, удаление исходников/оригиналов, commit/push этим менеджером не выполняются.

## Аккаунт и лимиты

`AgentAdapter.account(config)` читает сведения выбранного CLI отдельно от запуска рабочих заданий. Настройки вызывают его после загрузки профиля, при смене провайдера или файла CLI и по кнопке «Обновить». Ручной ввод пути отложен на 600 мс; смена модели не запускает новое чтение аккаунта. Ответ прежнего пути или провайдера не показывается после переключения. Снимок существует только в памяти страницы: email, организация и лимиты не попадают в `settings.json`, историю заданий или журнал.

Claude использует [`claude auth status --json`](https://code.claude.com/docs/en/cli-reference): email, `orgName`/`orgId`, `authMethod`, `subscriptionType`. Для Claude 2.1.273+ доступно отдельное короткое соединение control protocol: `initialize` → `get_usage` с `skip_behaviors=true`. Оно вызывается только при подтверждённом входе в подписку первого провайдера; при API key, `apiKeyHelper`, внешнем провайдере или неизвестном способе входа лимиты подписки не запрашиваются, чтобы не показать лимиты сохранённого личного аккаунта вместо рабочего способа списания. Тариф остаётся из `auth status`. Метод объявлен экспериментальным в [официальном Agent SDK](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md), поэтому неподдерживаемый или изменившийся ответ оставляет показатели неизвестными. Пользовательские сообщения и обращения к модели не отправляются, анализ истории за семь дней отключён. Считываются только отчётные окна использования и время сброса; стоимость текущего сеанса не подменяет остаток подписки.

Codex использует [штатный app-server](https://learn.chatgpt.com/docs/app-server): stdio-инициализацию, затем `account/read` с `refreshToken=false` и `account/rateLimits/read`. Диалоги и ходы модели не создаются. Для аккаунта ChatGPT читаются email и `planType`; способ API key показывается отдельно. При наличии `rateLimitsByLimitId` отображаются его окна, иначе используется прежний `rateLimits`. Проценты означают уже использованную долю; время сброса — Unix seconds. Нулевое использование и нулевой остаток сохраняют значение нуля.

Каждый неподтверждённый показатель отображается как «Не удалось уточнить». Эти интерфейсы не сообщают платёжный статус и дату окончания подписки: успешный вход, название тарифа и исчерпанное окно не превращаются в сообщение «подписка оплачена» или «подписка закончилась». Организация не выводится из домена email или названия тарифа. Команды ограничены по времени и объёму вывода, процесс диагностики завершается после ответа; сырой ответ CLI и секреты в renderer не передаются.

## IPC и подписка

Контракт задан в `src/shared/agents.ts` и `src/shared/api.ts`, каналы — `agents:<имя>`:

| Метод `window.api.agents` | Назначение |
| --- | --- |
| `getSettings()` / `saveSettings(config)` | Выбранный текстовый агент; сохранение также обновляет его профиль |
| `getProviderSettings(provider)` / `saveProviderSettings(config)` | Независимые путь и модель Claude Code или Codex |
| `getImageSettings()` / `saveImageSettings(config)` | Совместимость с сохранёнными профилями изображений; модель Codex в проекте выбирается через `generation.image.model` |
| `check(config)` | Проверка показанной конфигурации без сохранения |
| `account(config)` | Текущий аккаунт и доступные лимиты CLI без генерации и записи сведений в историю |
| `start({ project, task, prompt, context?, retryOf? })` | Новый явный запуск с сохранённой конфигурацией; сразу возвращает запись `running` |
| `cancel(id)` | Останавливает процессную группу и возвращает итоговую запись |
| `get(id)` | Снимок записи или `null` |
| `list(project?)` | История от новых записей к старым |
| `onEvent(listener)` | Подписка, возвращающая функцию отключения |

`onEvent` использует `agents:subscribe`, `agents:unsubscribe` и `agents:event`; объект события Electron в renderer не передаётся. В подписке доступны `started`, `text_delta`, `tool_started`, `tool_finished`, `completed`, `failed`. У события есть `jobId`, `project`, `sequence`, `phase`. Начало и итог содержат снимок `job`; текстовые события передают приращение `text`, события инструмента — его название без аргументов и результата чтения файлов. Остановка и прерывание передаются как `failed` с точным статусом в снимке задания.

Подписывайтесь до вызова `list`. До получения списка буферизуйте события; после ответа применяйте только события с номером больше `job.sequence`. Так событие, уже попавшее в снимок, не продублирует текст, а поздний снимок не откатит результат. Страницы «Сценарий» и «Производство» используют общий hook и карточки истории. Доменные запуски доступны на страницах [«Сценарий»](scenario-workflow.md) и [«Производство»](production-workflow.md); там предложение проходит собственные проверки и Apply. Настройки изображений и видео задаются независимо в проекте, отдельно от текстового агента.

## Системные уведомления

Главный процесс показывает штатные `Notification` Electron после автоматической разметки, пробы, аниматика и любого запущенного пользователем задания Claude Code/Codex, включая создание опор. Уведомляется успех или ошибка, но не явная отмена, прерывание или промежуточный ответ; повторное событие одного задания не создаёт второе уведомление. Рецепт пробы и проверка входов аниматика не объявляются готовым видео. Сообщение «Ответ Claude Code/Codex готов» означает завершение ответа: предложение ещё требуется проверить и согласовать.

Нажатие восстанавливает существующее окно и открывает проект результата: разметку, проверки, аниматик, сценарий либо производство. Показ не зависит от подписок renderer и работает при свёрнутом окне, пока приложение запущено; после выхода фоновой работы нет. В Windows приложение задаёт стабильный `AppUserModelID`, регистрацию уведомлений выполняет Electron 45 автоматически. ОС может отключить или подавить показ; сбой доставки не меняет результат задания. Показ уведомлений в Linux и Windows, в том числе при свёрнутом окне, подтверждён пользователем на готовых сборках.

## История и повтор

Запись `localDir/jobs/agent-<UUID>.json` содержит `schemaVersion`, идентификатор, номер события, проект, задачу, провайдера, модель, версию CLI, хеши промпта и контекста, режим `read-only` или `workspace-write` для внутреннего задания опор, состояние, фазу, времена, код завершения, session id, результат и служебный журнал. Идентификаторы Python Jobs с ней не пересекаются. Запись атомарная; промежуточное состояние сохраняется с задержкой до 250 мс, итог — сразу.

Промпт, дополнительный контекст, сырые события и stderr не записываются. Журнал содержит только действия менеджера и краткие причины ошибок. Результат предложения хранится отдельно от журнала; распознаваемые ключи/токены в тексте маскируются. Для задачи доступны до 256 КиБ промпта и 256 КиБ дополнительного контекста, до 256 КиБ на строку JSONL и результат, 8 МиБ суммарного stdout/stderr, 12 тысяч символов служебного журнала. Время рабочего процесса ограничено 20 минутами; для каждой команды проверки версии и входа CLI действует отдельный тайм-аут 10 секунд и предел 32 КиБ для каждого потока вывода. Renderer не может произвольно повышать лимиты.

При старте оконного приложения сохранённое `running` становится `interrupted`, никогда `completed`. История не удаляется. Нераспознаваемая/повреждённая запись сохраняется на диске, её путь отмечается в stderr приложения; остальные задания продолжают читаться. CLI-режим `--songframe-tool` не создаёт менеджер и не меняет состояние живых заданий окна. Смена корня ресурсов также сохраняет существующий экземпляр менеджера.

Ни повтор, ни resume автоматически не выполняются. Session id сохраняется для диагностики, но сам по себе не доказывает совместимость возобновления. У прерванного, ошибочного или остановленного задания есть явное действие повтора. В общем интерфейсе истории оно открывает новый запрос; на предметной странице повтор снова подготавливает соответствующий этап по актуальным входам. Используются текущие настройки агента; прежняя запись сохраняется. Вызывающий код передаёт `retryOf`; задание другого проекта и ещё выполняющееся задание нельзя указать источником повтора. Агентный повтор не восстанавливает платную отправку Kling. Для уже отправленного запроса отдельный `production.resume` получает существующий ID без новой генерации; неизвестный исход требует установить ID, а не повторять отправку.

Один проект резервируется до диагностики, включая пути через symlink; повторный запуск получает `PROJECT_BUSY`. Разные проекты могут иметь независимые задания. Отмена, тайм-аут и закрытие приложения завершают всю собственную процессную группу Linux; поиск и остановка чужих процессов по имени не используются.

## Коды диагностики

| Код | Значение |
| --- | --- |
| `INVALID_INPUT` | Нет проекта, агента, обязательного текста либо параметры недопустимы |
| `PROJECT_BUSY` | Для этого проекта уже есть незавершённый запуск |
| `CLI_NOT_FOUND` / `CLI_UNAVAILABLE` | CLI отсутствует или не запускается |
| `AUTH_REQUIRED` / `AUTH_UNKNOWN` | Вход отсутствует либо его нельзя подтвердить |
| `UNSUPPORTED_VERSION` | Версия не распознана или находится вне проверяемого контракта адаптера |
| `PROTOCOL_ERROR` | Некорректный JSONL или выход без завершающего события |
| `OUTPUT_LIMIT` | Превышен размер вывода, строки или результата |
| `TIMEOUT` | Рабочий процесс не завершился вовремя |
| `RATE_LIMIT` | Провайдер сообщил о лимите использования |
| `CLI_ERROR` | Ошибка рабочего запуска, ответа или сохранения состояния |
| `CANCELLED` / `INTERRUPTED` | Явная остановка либо завершение приложения/перезапуск |

Код `0` без финального события не считается успехом; финальное событие при ненулевом коде также не означает успех. Неизвестные служебные события пропускаются для совместимости, а сломанные JSON-строки останавливают задание. Реальная причина входа/лимита определяется по штатному ответу, произвольный ненулевой код не превращается автоматически в отсутствие входа.

## Проверка

`yarn test src/main/agent-manager.test.ts src/renderer/src/hooks/agentEvents.test.ts` проверяет подставные CLI обоих провайдеров, поток до окончания, stdin и cwd, ошибки, лимиты, отмену дочернего процесса, восстановление и гонку снимка с событиями. Маршрут изображений дополнительно проверяют `src/main/agent-image-jobs.test.ts`, файловые кандидаты — `src/main/keyframe-images.test.ts`, независимые настройки — `src/main/settings-profiles.test.ts`. `src/main/production-integration.test.ts` проходит производственную цепочку через настоящие менеджер и PythonLauncher с подставными Claude, Codex и Kling; комментарий перед финальным JSON не приклеивается к результату. Эти тесты входят в обычный `yarn test` и существующий CI. Подставные CLI не создают настоящие изображения и не отправляют платные запросы. Наличие CLI и вход проверяются в «Настройках», а каталог моделей и параметров медиапровайдера — на странице «Проект». Доступ конкретного аккаунта к генерации и встроенному инструменту изображений подтверждается отдельно, при явно согласованном реальном запуске. Проверка переносимости приложения также выполняется отдельно от тестов адаптера. Менеджер агентских заданий отклоняет запуск вне Linux; внешние Claude/Codex и их обёртки `.cmd` в Windows им не поддерживаются. Это ограничение не относится к проектным `run-tool.cmd`/`run-kling.cmd`, встроенному Kling и локальным Python-инструментам.
