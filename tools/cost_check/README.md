# cost_check

Оценивает стоимость подготовленного запроса и сверяет с остатком кредитов до показа таблицы запроса. Инструмент вызывает приложение перед вопросом «отправить или сохранить?» и при продолжении отложенного пакета; после отправки оно же записывает фактический расход через `learn`. Инструмент не отправляет генерацию; единственное обращение к сервису — информационный остаток через `account()` [адаптера](../media_request/README.md#адаптеры) провайдера запроса.

```sh
python3 -B tools/cost_check/cost_check.py check --work-dir plan/batches/M32-attempt-01
python3 -B tools/cost_check/cost_check.py check --request /tmp/request.json --balance 1824 --no-account
python3 -B tools/cost_check/cost_check.py check --work-dir plan/awaiting/M32/request --json
python3 -B tools/cost_check/cost_check.py learn --work-dir plan/batches/M32-attempt-01
```

`check` читает замороженный `request.json` попытки или спецификацию до подготовки (её проверяют общая форма и адаптер провайдера), берёт тариф из [таблицы цен](#таблица-цен-и-наблюдения) провайдера вместе с наблюдениями, остаток — у адаптера (сохраняется только число и имя поля либо причина, не весь ответ) или из `--balance`, и печатает таблицу с вердиктом: `ok`, `insufficient_balance`, `cost_or_balance_unknown`. Названия вердиктов совпадают с причинами ожидания в [README очереди](../../templates/project/plan/awaiting/README.md). Код возврата 2 при любом вердикте кроме `ok`, чтобы вызывающий код не мог пропустить проверку молча.

В приложении неизвестная цена показывается как «Стоимость: неизвестно». Пользователь может нажать «Я согласен» и отдельно подтвердить промпт и одну отправку с неизвестным списанием. Это одноразовое согласие относится к показанному запросу и оценке; обновление стоимости и новая попытка требуют нового согласия. Оно не меняет вердикт инструмента, не создаёт тариф и не отменяет известную нехватку средств.

Остаток запрашивает адаптер провайдера; без входа, без ответа сервиса или без числа в ответе остаток неизвестен с пояснением. Провайдер без адаптера — ошибка с кодом 1.

## Таблица цен и наблюдения

Базовая таблица цен — файл `pricing_file()` адаптера (обычно `pricing.json` в папке адаптера). Она входит в поставку приложения и инструментами только читается; обновляет её владелец в комплексе. Фактический расход отправленных попыток `learn` записывает наблюдениями в каталог состояния: `<каталог состояния>/providers/<id>/pricing-observations.json` (`{"schema_version": 1, "observed": [...]}`, атомарная замена файла). Каталог состояния — `SONGFRAME_LOCAL_DIR` приложения, без него постоянный userData (на Linux `${XDG_CONFIG_HOME:-$HOME/.config}/songframe`). При оценке наблюдения состояния добавляются после наблюдений базовой таблицы, поэтому из подходящих берётся последнее записанное; повреждённый файл наблюдений — ошибка с кодом 1, файл не перезаписывается. Наблюдение, уже совпадающее с записью таблицы или состояния, повторно не добавляется.

`--pricing` задаёт другой файл вместо базовой таблицы адаптера (только для прогонов без расхода; приложение передаёт его из переменной окружения `SONGFRAME_PRICING_FILE`, если она задана). Наблюдения при этом по-прежнему читаются из каталога состояния и пишутся туда же; файл `--pricing` не меняется.

Базовая таблица заполняется вручную по кабинету сервиса: для видео — `per_second` по уровням разрешения и `base_credits` за запрос, для изображений допустим явно заданный `per_image`. `null` означает «неизвестно», и вердикт становится `cost_or_balance_unknown` с объяснением. `learn` после отправки записывает фактический `credits_consumed` из `attempt.json` как наблюдение. Для видео без цены в таблице оценка берётся по наблюдению того же тарифа: точная по длительности либо пересчитанная по секундам.

Для изображения `learn` сохраняет `kind=image`, модель, `command`, `img_resolution`, `quality`, число результатов и `image_signature`. Подпись — canonical JSON с командой, полным JSON параметров, `outputs` и упорядоченными `flag`/`slot` каждого входа. Текст промпта и поля авторизации исключены; пути, хеши, размеры референсов и локальная подпись `role` не задают тариф. Порядок ключей JSON не влияет на совпадение; число входов и фактические слоты учитываются.

Оценка изображения использует фактический **общий** расход только для точно такой же подписи и модели, даже если отдельной записи `models[model]` нет. Наблюдение T2I не переносится на I2I, `1k` на `4k`, `low` на `high`, один результат на девять или один референс на несколько. Любой новый параметр тоже требует своего наблюдения. Наблюдение изображения без подписи не подтверждает точную цену. При отсутствии совпадения и ручного `per_image` цена остаётся неизвестной; `learn` не создаёт универсальный тариф за изображение. В таблице image-запроса показываются `command`, `img_resolution` и `quality`, без видеодлительности.

## Тесты

Тесты работают на тестовом провайдере `test` ([tools/testing](../testing/README.md)): оценка по таблице и по наблюдениям, неизвестная цена, остаток и таблица цен по умолчанию от адаптера, ручной остаток, вердикты, запись наблюдения в каталог состояния без изменения базовой таблицы, приоритет наблюдений состояния и при явном `--pricing`, повреждённый файл наблюдений. Разбор ответа сервиса проверяют тесты его адаптера. Для изображений проверяются точная конфигурация без отдельной записи модели, различия команды/разрешения/quality/числа результатов/референсов, canonical JSON без промпта и секретов, общий расход без видеопересчёта и image-поля таблицы.

```sh
python3 -B tools/cost_check/test_cost_check.py
python3 -B tools/run_tests/run_tests.py --only test_cost_check
```

Тесты находятся рядом со скриптом; к сервису не обращаются, временные таблицы цен и каталог состояния создают вне проекта. Для полного набора — [run_tests](../run_tests/README.md).
