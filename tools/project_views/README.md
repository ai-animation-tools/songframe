# project_views

Служебный модуль производных документов: чтение источников и генерация представлений. Прямого CLI нет — использовать [update_scene_views](../update_scene_views/README.md).

## Контракт

Настройки `generation.video` и `generation.image` не участвуют в проверке просмотра: повреждение одного блока не мешает читать документы проекта. Их проверяет исполнитель выбранного медиа перед генерацией.

`Sources` читает рабочие файлы напрямую с диска, без требования Git или наличия `.git`; проверка состава и хешей материалов сохраняется. Индекс и исторический снимок читаются через Git, при его отсутствии эти режимы выдают ошибку; `documents` и `render` строят представления из `plan/scenes.json`, локальных assets и состояния работ. Общий индекс и Markdown первичными источниками не являются. Названия в заголовках — из [plan/project.json](../../templates/project/plan/project.json); имена персонажей и локаций остаются в данных реестра. Визуальный справочник `plan/context/characters.md` строится из единого `visual_direction`; список речевых планов вычисляется по `lipsync` у Mxx. Постановку здесь не хранить, текст представлений не править — [AGENTS.md](../../AGENTS.md). [Проверка источников](../scene_registry/README.md#тесты).

Ссылка на текущий полный монтаж в ROADMAP ведёт в `plan/animatic/latest/README.md`, где находятся MP4 и манифест сборки.

Статус сборки в ROADMAP сравнивает реестр, снимок `project_inputs: {name, animatic_video}` и хеши исходных медиа из `source_hashes`. Настройки генерации и форматирование `project.json` на него не влияют. Снимок и хеши обязательны; отсутствие или повреждение этих данных требует пересборки. `source_hashes` содержит только медиафайлы; поля проекта хранятся в `project_inputs`.

ROADMAP включает Mermaid-диаграмму, таблицу состояний с процентами от числа планов и готовность по хронометражу из кадровых границ. Диаграмма и строки планов используют одно вычисление состояния: выбранный комплект в assets имеет приоритет над рабочей отметкой. Нулевые статусы остаются в таблице, но не создают секторы. Проценты округляются до одной десятичной и отдельно не хранятся.

В монтажном списке заголовок таблицы и Markdown-разделитель формируются из одного набора столбцов: их количество должно совпадать, чтобы предпросмотр распознавал таблицу.

## Тесты

Структура Markdown-таблицы монтажного списка, доли готовности и диаграмма, строки ROADMAP, приоритет выбранных assets над прежними рабочими статусами, различие актуальной и устаревшей сборки. Манифест сборки подставляется в памяти; видео не пересобирается.

```sh
python3 -B tools/project_views/test_project_views.py
python3 -B tools/run_tests/run_tests.py --only test_project_views
```

Тесты находятся рядом с модулем; рабочие сцены не изменяют. Для полного набора — [run_tests](../run_tests/README.md).
