# kling_request

Готовит неизменяемую попытку, отправляет её через официальный Kling CLI, ждёт и получает оригиналы. Использовать после подготовки кадров и согласования точного запроса по [скиллу](../../skills/ai-clip-scene/SKILL.md). Скрипт не выбирает модель, не узнаёт цену и баланс, не подтверждает запрос вместо пользователя и не анализирует видео.

## Контракт

Из корня checkout комплекса, для выбранного проекта. В готовом приложении из папки клипа замените `python3 -B tools/kling_request/kling_request.py` на проектный launcher: `./.songframe/run-tool kling_request` в Linux либо `.\.songframe\run-tool.cmd kling_request` в Windows:

```sh
python3 -B tools/kling_request/kling_request.py capabilities
python3 -B tools/kling_request/kling_request.py capabilities --commands text_to_video,image_to_video,omni_ref_video,motion_control --json
python3 -B tools/kling_request/kling_request.py capabilities --command image_to_video --model kling-video-v4_0 --json
python3 -B tools/kling_request/kling_request.py prepare --request /tmp/request.json --work-dir plan/batches/M32-attempt-01
python3 -B tools/kling_request/kling_request.py submit --work-dir plan/batches/M32-attempt-01 --confirm REQUEST_SHA256
python3 -B tools/kling_request/kling_request.py resume --work-dir plan/batches/M32-attempt-01
python3 -B tools/kling_request/kling_request.py status --work-dir plan/batches/M32-attempt-01
python3 -B tools/kling_request/kling_request.py watch --work-dir plan/batches/M32-attempt-01/request --max-minutes 15 --interval 20
python3 -B tools/kling_request/kling_request.py watch --work-dir plan/batches/M52-attempt-01/request plan/batches/M55-attempt-01/request
```

- `capabilities` проверяет наличие команды через `tool_list` и печатает объявления моделей аккаунта из JSON `who_am_i`: длительности, разрешение, пропорции, `prefer_multi_shots`, звук, слоты кадров и общий лимит изображений. Аргументы, слоты и ограничения берутся только из текущего ответа сервиса; статическая или локализованная справка CLI не используется. Генерации нет; отсутствие объявлений для отдельной команды не подтверждает проблему входа в аккаунт. В таком случае обновить возможности, проверить доступность команды и повторить. Использовать на этапе описания плана вместо дат сверки в справочниках.
- `capabilities --commands <команды через запятую> --json` читает один свежий снимок `tool_list` и `who_am_i` на всё обновление каталога. Возвращает `{reports: [{command, models}], problems: [{command, message}]}`; неизвестная или повреждённая команда не скрывает корректные объявления остальных, а ошибка общего discovery завершает вызов с ошибкой. Режим `--command` сохраняется; `--commands` несовместим с `--model`. Повторных параллельных запросов одинакового каталога нет.
- `prepare` работает без сети и создаёт новую папку с точным промптом, входами и хешами. Необязательный `model_selection` сохраняет уже выбранную вызывающим кодом модель и причину выбора в согласуемом SHA; сам инструмент модель не выбирает. Запрос к `kling-video-v3_0` и `v3_0_omni` без `prefer_multi_shots`, а также к `kling-video-v4_0` без `resolution` отклоняется; промпт длиннее 2 500 символов допускается, но попадает в `warnings`.
- `submit` — только после явного разрешения человека на этот SHA по скиллу: для нового пакета — «отправить» после таблицы, для отложенного или после пополнения счёта — подтверждение заново показанной таблицы. Флаг `--confirm` согласия не означает; актуальные цену и баланс перед расходом проверяет агент, не скрипт. Повторная отправка попытки запрещена.
- Изображения сохраняются без перекодирования: PNG/JPEG/WebP определяются по сигнатуре оригинала, включая opaque/extensionless CDN URL и адреса с неверным расширением. Временный raw-файл публикуется только после записи конечного пути, размера и SHA-256; обрыв после публикации восстанавливается без повторной загрузки. Видео сохраняется прежним способом.
- У обоих медиа приоритет имеет явный `urlWithoutWatermark` / `url_without_watermark`. Видео без такого адреса остаётся в `watermark_free_pending`, обычный `url` не скачивается; продолжение ждёт тот же ID. Для изображения при отсутствии явного поля используется исходный `url` сервиса: сам адрес не подтверждает отсутствие логотипа, инструмент не исследует изображение и не удаляет логотипы.
- `resume` продолжает тот же ID; `--wait-seconds 45 --interval 15` ограничивает один короткий цикл ожидания, `--generation-id` привязывает установленный ID неизвестной отправки — выяснить ID, а не генерировать повторно. `status` читает только локальный журнал. `--cli` явно выбирает CLI, включая локальную подмену в тестах.
- `watch` — одно ожидание до 120 минут для одной или нескольких отправленных попыток: опрашивает их по очереди через `resume`, печатает только смену статуса, скачивает готовые результаты и завершается, когда все достигли `downloaded` или `failed`. При истечении времени возвращает код 2, задание не отменяется, повторный `watch` продолжает те же ID. Попытка без ID или с неизвестным исходом отправки сообщается как ошибка и из ожидания исключается — её судьбу выясняют по [справочнику восстановления](../../skills/ai-clip-scene/references/recovery.md).

Папка попытки — внутри `plan/batches`, `plan/awaiting` или `/tmp`; сами корни не могут быть попыткой. Целиком перенесённая замороженная попытка сохраняет SHA и допускает `status`, `submit` и `resume` по новому пути; отложенные пакеты — по [правилам очереди](../../templates/project/plan/awaiting/README.md). Логотип, неприкосновенность assets и аниматика, запрет платного запроса без согласия — [AGENTS.md](../../AGENTS.md). Платные запросы не запускать ради проверки инструмента: [тесты](#тесты). [Формат JSON, пакет, состояния и восстановление](request-format.md).

## Запуск CLI

Приложение передаёт `SONGFRAME_KLING_EXECUTABLE` и `SONGFRAME_KLING_SCRIPT`: официальный CLI из поставки запускается через Electron без отдельного Node.js. Большие ответы discovery захватываются в приватный временный regular file и удаляются после чтения: ранний выход CLI не должен обрывать JSON в pipe. Наружу возвращаются только объявления команды, без полей аккаунта и сырого ответа. Общий адаптер `tools/kling_cli.py` передаёт промпт и пути отдельными аргументами без shell; `ELECTRON_RUN_AS_NODE=1` добавляется только дочернему CLI, окружение Python и приложения не меняется. При повреждённом встроенном комплекте глобальный `kling` не подставляется. Явный `--cli <файл>` имеет приоритет; при самостоятельном запуске без этих переменных сохраняется поиск внешнего `kling` в PATH.

Блокировка попытки неблокирующая: Linux использует `flock`, Windows — один байт `.lock` через `msvcrt.locking`. Занятая попытка отклоняется, освобождение происходит и при ошибке; правила SHA, единственной отправки и восстановления не меняются.

## Тесты

Подготовка, перенос целого пакета в очередь, единственная отправка, таймауты, восстановление и сохранение оригиналов на подставном CLI без сети. Для общего каталога проверяются ровно два вызова CLI независимо от числа команд, свежесть следующего обновления, честные частичные ошибки и отказ при ошибке discovery. Discovery проверяется на статической справке при доступном JSON, отсутствии команды/моделей, camelCase/snake_case, точных аргументах/слотах/ограничениях, большом JSON в приватном файле и неполном/ошибочном ответе без раскрытия аккаунта. Проверяются аргументы и пути с пробелами, приоритет `--cli`, только дочерний Electron-режим, отказ до `submitting` при отсутствующем комплекте и освобождение блокировки после ошибки; Windows-ветка блокировки проверяется подставным системным адаптером, что не заменяет нативную приёмку. Метаданные выбора модели проверяются до подготовки, входят в SHA и сохраняются при отправке/продолжении; без них прежний формат сохраняет байты и SHA. Подмена причины отклоняется до вызова CLI. Для изображений проверяются PNG/JPEG/WebP по байтам при opaque и неверно подписанном URL, отказ для постороннего тела ответа, защита существующего файла и восстановление до/после публикации того же ID без повторной отправки.

```sh
python3 -B tools/kling_request/test_kling_request.py
python3 -B tools/run_tests/run_tests.py --only test_kling_request
```

Тесты находятся рядом со скриптом; рабочие сцены не изменяют, временные результаты создают вне проекта. Для полного набора — [run_tests](../run_tests/README.md).
