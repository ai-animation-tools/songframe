# Сборка SongFrame

Работай в корне репозитория SongFrame (в рабочем пространстве AI Animation Tools это папка `songframe/`); пути ниже отсчитываются от него. Сначала прочитай актуальные `AGENTS.md`, разделы сборки и проверки в `docs/development.md` и при необходимости `scripts/runtime/README.md`. Точный состав проверок перед выпуском — в шаге сборки `scripts/release/release.mjs`. Выполняй только запрошенные платформы и проверки; учитывай имеющиеся изменения в checkout и не изменяй чужие проекты.

## Вызов

| Задача | Codex | Claude Code |
| --- | --- | --- |
| Собрать платформы из запроса | `$songframe-build` | `/songframe-build` |
| Только Linux AppImage | `$songframe-build os=linux` | `/songframe-build os=linux` |
| Только Windows-установщик | `$songframe-build os=win` | `/songframe-build os=win` |

Аргумент `os` необязателен. Без него платформа берётся из запроса пользователя («AppImage» — Linux, «установщик для Windows» — Windows); если платформа не названа, собери обе.

Сборка использует Node из `.nvmrc`, Yarn из `package.json` и зависимости проекта. Команды ниже выполняются из корня репозитория. Готовые поставки находятся в `build/release`, вне Git. Для разовых журналов и временных файлов используй `/tmp`. Не копируй AppImage за пределы репозитория без явного поручения.

## Выбор версии

Перед сборкой прочитай `version` из рабочего и зафиксированного в HEAD `package.json` (`node -p "require('./package.json').version"`, `git show HEAD:package.json`) и последний опубликованный релиз: `gh api repos/ai-animation-tools/songframe/releases/latest --jq .tag_name`. Сравнивай `X.Y.Z` как SemVer, без префикса `v`, а не как строки. Правила версии и сохранности прежних комплектов — в [руководстве разработки](../../docs/development.md#версия-локальной-сборки).

- Явно названную пользователем версию используй для этой локальной сборки через `SONGFRAME_VERSION`, даже если она отличается от `package.json` или уже опубликована. Это не разрешает менять выпуск на GitHub или его локальный архив.
- Без явной версии выбирай версию зафиксированного `package.json`, если рабочий файл содержит ту же версию и она не ниже последнего опубликованного выпуска. При отставании останови сборку и объясни, что сначала нужно обновить каноническую версию; не собирай со старым номером и не увеличивай его молча.
- Ошибку GitHub не считай отсутствием выпусков: при 404 у `latest` проверь доступный список releases без draft/prerelease, а сетевой отказ или ошибка доступа оставляют последнюю версию неизвестной. В этом случае сборка с явно заданной версией допустима с указанием ограничения проверки; без неё не выбирай номер автоматически.

Перед повторной сборкой проверь, не связаны ли файлы в `build/release` жёсткими ссылками с сохранённым комплектом `build/releases/v<версия>/`. Сверь архив с `release.json` и сохрани его метаданные; отвяжи только перезаписываемые пути в `build/release` по [рецепту руководства](../../docs/development.md#версия-локальной-сборки). Архив опубликованного выпуска не меняй.

## Linux

- `SONGFRAME_VERSION=<выбранная-версия> yarn dist:linux` собирает AppImage с ресурсами. Передай выбранную версию явно, чтобы локальный override не потерялся.
- `yarn smoke:runtime` проверяет переносимый Python.
- Для проверки конечного AppImage по рецепту проекта подготовь внешнюю тестовую модель командой `yarn prepare:smoke-model`, затем выполни `yarn smoke:appimage --docker --appimage="$PWD/build/release/songframe-<выбранная-версия>-linux-x86_64.AppImage" --model="$PWD/build/runtime/smoke-model" --output=/tmp/songframe-appimage-check`. Для повторного прогона выбери новую папку отчёта. Подготовка модели может требовать сеть; сама проверка в Docker идёт без сети.
- Успешный smoke создаёт рядом с AppImage файл SHA256 и `linux-smoke-result.json`. Сообщай отдельно о сборке и фактически выполненном smoke.

## Windows

На Linux выполни `SONGFRAME_VERSION=<выбранная-версия> yarn dist:win`, он выпускает установщик NSIS `build/release/songframe-<версия>-win-x64-setup.exe`. Для проверки используй ту же выбранную версию и запусти `python3 -B scripts/runtime/check-windows-installer.py "build/release/songframe-<версия>-win-x64-setup.exe" --version "<версия>"`; нужен системный `7z`. Проверка извлекает архив приложения из установщика, создаёт SHA256 и `build/release/windows-installer-check.json`; она проверяет содержимое и ресурсы, но не исполняет Windows-код. Не делай вывод о работоспособности установщика, runtime или полной поддержке Windows по результату этой проверки. Нативные проверки Windows в VM выполняй только по явному поручению.

В ответе укажи пути полученных файлов, выполненные проверки и их результат, а также существенные невыполненные проверки. Сборка не разрешает commit, push или публикацию; выпуск релиза выполняется отдельно по явному поручению.
