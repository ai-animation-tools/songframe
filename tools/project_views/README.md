# project_views

Служебный модуль производных документов: чтение источников и генерация представлений. Прямого CLI нет — использовать [update_scene_views](../update_scene_views/README.md).

## Контракт

Настройки `generation.video` и `generation.image` не участвуют в проверке просмотра: повреждение одного блока не мешает читать документы проекта. Их проверяет исполнитель выбранного медиа перед генерацией.

`Sources` читает рабочие файлы напрямую с диска, без требования Git или наличия `.git`; проверка состава и хешей материалов сохраняется. Индекс и исторический снимок читаются через Git, при его отсутствии эти режимы выдают ошибку; `documents` и `render` строят представления из `plan/scenes.json`, локальных assets и состояния работ. Общий индекс и Markdown первичными источниками не являются. Названия в заголовках — из [plan/project.json](../../templates/project/plan/project.json); имена персонажей и локаций остаются в данных реестра. Визуальный справочник `plan/context/characters.md` строится из единого `visual_direction`; список речевых планов вычисляется по `lipsync` у Mxx. Шапка раскадровки отсылает за ролями и внешностью персонажей к кастингу `plan/cast.json`, за общими визуальными правилами — к визуальному справочнику. Постановку здесь не хранить, текст представлений не править: владельцы сведений — в [README шаблона](../../templates/project/README.md#источники-сведений). [Проверка источников](../scene_registry/README.md#тесты).

Ссылка на текущий полный монтаж в ROADMAP ведёт в `plan/animatic/latest/README.md`, где находятся MP4 и манифест сборки.

Статус сборки в ROADMAP сравнивает реестр, снимок `project_inputs: {name, animatic_video}` и хеши исходных медиа из `source_hashes`. Настройки генерации и форматирование `project.json` на него не влияют. Снимок и хеши обязательны; отсутствие или повреждение этих данных требует пересборки. `source_hashes` содержит только медиафайлы; поля проекта хранятся в `project_inputs`.

ROADMAP включает Mermaid-диаграмму, таблицу состояний с процентами от числа планов и готовность по хронометражу из кадровых границ. Диаграмма и строки планов используют одно вычисление состояния: выбранный комплект в assets имеет приоритет над рабочей отметкой. «Готово» — комплект принят по текущей постановке, «Постановка изменена» — комплект есть, но постановка плана или его источника `derived_from` изменилась после приёмки ([правило](../scene_registry/README.md#принятие-планов), отпечатки из `plan/production-status.json` → `shots`); такой план не входит в готовые и в готовый хронометраж. Нулевые статусы остаются в таблице, кроме «Постановка изменена», которая появляется только при таких планах; секторов нулевые статусы не создают. Проценты округляются до одной десятичной и отдельно не хранятся.

План с `derived_from` (собирается из материала другого плана, [правила](../scene_registry/README.md#производный-план-derived_from)) помечается источником: в ROADMAP `| **M05** · из M02 |`, в монтажном списке ячейка «План» `M05 · из M02`, в раскадровке после строки монтажа `**Материал:** из [M02](#m02), без собственной генерации.` Строки обычных планов не меняются.

В монтажном списке заголовок таблицы и Markdown-разделитель формируются из одного набора столбцов: их количество должно совпадать, чтобы предпросмотр распознавал таблицу.

## Тесты

Структура Markdown-таблицы монтажного списка, пометка производного плана, доли готовности и диаграмма, строки ROADMAP, приоритет выбранных assets над прежними рабочими статусами, «Постановка изменена» после правки действия принятого плана, различие актуальной и устаревшей сборки. Манифест сборки подставляется в памяти; видео не пересобирается.

```sh
python3 -B tools/project_views/test_project_views.py
python3 -B tools/run_tests/run_tests.py --only test_project_views
```

Тесты находятся рядом с модулем; рабочие сцены не изменяют. Для полного набора — [run_tests](../run_tests/README.md).

Готовность производных комплектов считается общим правилом [scene_registry](../scene_registry/README.md#принятие-планов): свой отпечаток, готовый источник и совпадение сохранённых SHA постановки/выбранного клипа источника. Рабочие представления сверяют фактические байты клипа, представления индекса/снимка Git — сохранённый SHA файла или LFS oid; отсутствие файла означает `stale`. Независимые технические поля манифеста источника готовность не меняют.
