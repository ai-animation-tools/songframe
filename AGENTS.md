# Правила SongFrame Go

SongFrame — комплекс для производства музыкальных клипов с помощью ИИ. Этот репозиторий — его преемник на Go + Wails: после миграции продукт развивается только здесь. Ведётся настольное приложение; агента запускает приложение, клип ведётся только кнопками приложения. Данные каждого клипа живут в отдельной папке проекта, созданной из шаблона; здесь хранятся код, ресурсы, документация и синтетические тестовые данные.

Пока идёт миграция, репозиторий приватный (`git@github.com:ai-animation-tools/songframe-go.git`). При переключении его история переносится в публичный `ai-animation-tools/songframe` как версия 1.0.0, а этот репозиторий архивируется.

## План и источники

- Следующий шаг, этапы и решения ведутся в соседнем приватном `../spec/`. Перед задачей прочитать `../spec/AGENTS.md` и `../spec/plan/README.md`, затем текущий этап. Для сборки и тестов `spec` не нужен; его содержимое сюда не копировать.
- Эталоны поведения, все только для чтения:
  - `../songframe/` — Electron-оригинал, заморожен на `634fd94`. Его код, шаблон, инструменты и скиллы не менять; его Electron/Python-рецепты здесь не применять.
  - `../songframe-go-probe/` — принятый эксперимент CTC.
- Forktopus — только подтверждение работоспособности стека, а не образец продукта.
- Код миграции создавать здесь.

## Главный критерий и решения

**Результат работы программы не должен меняться.** Сохраняются:

- записываемые файлы и форматы проекта, статусы и fingerprints;
- тайминги, промпты, согласования платных операций, медиарезультаты и пользовательские процессы.

Внутреннее устройство выбирай сам: пакеты, типы, алгоритмы, процессы, границы API. Если решение лучше, оптимальнее или проще в сопровождении, чем в оригинале, применяй его сразу, без предварительного согласования. Причину кратко запиши в сообщении коммита и в этапе плана. Не копируй прежнее устройство только ради перевода на Go и не добавляй абстракции ради самого рефакторинга.

Сохранность доказывай проверками:

- **Эталоны оригинала.** Входы/выходы замороженного songframe собираются в `testdata/golden/<домен>/` (по мере переноса доменов); Go- и TS-тесты читают одни fixtures.
- **Тестовый клип `../test-projects/ogorod`.** Это отдельный Git-репозиторий для промежуточных проверок, запись разрешена. Перед проверкой убедись, что его дерево чистое. После проверки покажи изменения и откати их через его Git. Коммитить туда — только по поручению.
- **Готовый клип пользователя — только чтение.** Он должен открываться без ошибок чтения, без изменения файлов, формата и статуса относительно Electron (SHA дерева до/после). Записывающие сценарии на нём не выполнять.

Спрашивай пользователя только о том, что меняет видимый результат или продукт, о платных операциях, публикации и commit/push.

## Продукт

- **Пользователи.** Приложение используют два человека на своих компьютерах: владелец на Linux и его друг на Windows. Это локальное приложение, а не сервис. Не добавлять авторизацию, защиту от внешнего/параллельного доступа, обязательную сетевую изоляцию и проверки «на всякий случай». Обязательны: валидация данных, сохранность исходников и платных оригиналов, согласование платной отправки и защита от её случайного повтора.
- **Один формат данных.** Принятый формат проектов сохраняется. Не добавлять чтение прежних форматов, fallback, скрытые миграции и поиск старых данных в Git. Разовые преобразования и скрипты хранить вне репозитория.
- **Пути.** Пути переживают перенос приложения/проекта и переустановку ОС: не вшивать абсолютные пути машины, имя пользователя или временную папку AppImage. Ресурсы находить относительно приложения, данные — относительно выбранного проекта, состояние — в каталоге ОС. Пути `plan/...`, `assets/...`, `source/...` отсчитываются от папки проекта. Сохранённый путь может устареть: тогда достаточно понятной ошибки и повторного выбора.
- **Агенты.** Codex/Claude — внешние программы, приложение запускает их без shell. В Windows — `.exe` и обёртки npm `.cmd`, без окна консоли. Текстовым этапам нужен явно сохранённый агент. Названия агентов брать из реестра `frontend/src/shared/agent-providers.ts` (`agentTitle(provider)`), в общих текстах UI говорить об «агенте». Кнопки агента — только общий `AgentButton`: ровно один знак, причина блокировки — в `disabledReason`, подтверждение — через `confirmAgent`.
- **Провайдеры медиа.** Сервисы генерации описаны в реестре `frontend/src/shared/media-providers.ts`. Общий код и интерфейс узнают о провайдере только из реестра: не сравнивают имена и не пишут название сервиса в тексты. Особенности провайдера — в одном документе на вид медиа и в его Go-адаптере; «Указания агенту» вкладываются в промпт. Общая логика тестируется на провайдере `test`; удаление провайдера не должно ломать остальные тесты.
- **Платные операции.** Отправка — только после ответа `send` по показанному SHA и цене. Неизвестная цена допускает одну отправку после явного «Я согласен» и отдельного подтверждения промпта. Согласие не переносится на новую оценку, «Ещё» или повтор после ошибки и не отменяет известную нехватку средств. Платные запросы в разработке — только с согласия пользователя.
- **Компоненты.** FFmpeg/ffprobe, ONNX Runtime и модели не входят в базовый пакет: их находят в системе или ставят кнопкой. Без них проект открывается и редактируется.

## Устройство

- **Renderer.** Перенесённый исходный React/MUI-интерфейс; файловую систему не читает и процессы не запускает.
- **Связь с Go.** Единственный путь — контракт `window.api` (`frontend/src/shared/api.ts`): каждый метод отображается на сгенерированный binding Wails (`frontend/bindings`, вручную не править). Ручные валидаторы ответов Go не писать. Go отдаёт `[]` вместо `nil`, соответствие типов проверяет `typecheck`. Метод, ещё не реализованный в Go, явно числится недоступным в адаптере `frontend/src/platform/`.
- **Go.** Владеет файлами проектов, заданиями, процессами, состоянием провайдеров и медиасервером: `internal/app` — Wails-сервисы, `internal/<область>` — логика.
  - Внешние программы запускаются только через общий запуск процессов: без консоли в Windows, с отменой и завершением потомков.
  - Длительные операции идут через общий менеджер заданий.
  - Проектный JSON записывается атомарно.
- **Ресурсы.** Шаблон проекта, промпты, руководства провайдеров и шрифты встраиваются в бинарник.
- **Комментарии.** У функций, методов, структур, интерфейсов и модулей писать содержательные русские комментарии: что делает, зачем устроено так и с чем взаимодействует. Для экспортируемых деклараций и нетривиальной логики это обязательно. По необходимости описывать владельца состояния, побочные эффекты, ошибки/отмену, конкурентный доступ, единицы и инварианты. Не комментировать каждую строку и не пересказывать сигнатуру; при изменении поведения обновлять пояснения.

## Интерфейс

- Перед изменением UI применять [songframe-go-ui](dev-skills/songframe-go-ui/SKILL.md) и [правила UI](docs/ui/README.md).
- Storybook поддерживается в том же изменении: истории затронутого компонента, родительской страницы и их локальные модели API. В результате перечислить обновлённые истории и браузерные проверки.
- Русские тексты интерфейса централизованы в `frontend/src/shared/texts/` по [правилам текстов](docs/ui/texts.md).
- Минимальное и стартовое окно — **1320×860**; на нём проверяются светлая и тёмная темы. Размеры меньше (960×640, 1280×720) в обязательную приёмку не входят. Геометрия окна — в `main.go`, размер браузерной проверки — в `frontend/playwright.config.ts`.

## Поставки

Целевые поставки:

- Linux x86_64 — AppImage и deb-пакет;
- Windows amd64 — установщик NSIS.

Сейчас реализованы ранние AppImage и NSIS. Все поставки собираются локально на Linux; CI их не собирает.

- Сборку и проверку поставки выполнять по [songframe-go-build](dev-skills/songframe-go-build/SKILL.md) и `packaging/README.md`.
- Выпуск — по [songframe-go-release](dev-skills/songframe-go-release/SKILL.md).
- Нативные Windows-прогоны в VM — только по явному поручению; сборка установщика не доказывает работу в Windows.
- Не превращать правку рецепта в пересборку или запуск. Дорогие сборки и матрицы выполнять в порученном объёме.
- SHA и build receipts — внутренние проверки: без запроса не выводить их пользователю и не класть в общую папку VM.

## Работа в репозитории

- Документация, комментарии и сообщения коммитов — по-русски; имена файлов, API и технические термины сохранять как есть.
- Commit, push, remote, релиз и платные запросы — только по поручению.
- Не добавлять в Git приватные документы spec, клипы, веса, аудио, видео, токены, журналы, локальные отчёты и абсолютные машинные пути.
- У Go-версии до переключения свои app ID и каталог состояния; профиль Electron, его токены и клипы автоматически не читаются.
- Проверки: `wails3 task check:all`. Адресно — по `Taskfile.yml` и `frontend/package.json`. Контракты проектов и DTO — по [songframe-go-project-contract](dev-skills/songframe-go-project-contract/SKILL.md).

## Параллельная работа

- Независимые задачи в непересекающихся областях выполнять параллельно субагентами. Каждому давать конкретную подзадачу, границы файлов, критерии приёмки, минимальные обязательные правила и только релевантный контекст.
- Если достаточно отдельного задания, запускать субагента без наследования всего чата и не поручать ему читать весь репозиторий.
- У общего изменяемого файла один владелец, зависимые шаги — последовательно. Основной агент распределяет работу, интегрирует результаты и проверяет итоговое изменение.
