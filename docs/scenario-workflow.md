# Сценарий через Claude Code и Codex

На странице «Сценарий» ручные редакторы и локальное сохранение доступны без CLI. Для агентной подготовки нужны загруженные MP3, текст и идея, корректный manifest и разметка всех строк с подтверждением на слух. Выбор CLI и модели общий, на странице «Настройки».

## Два прохода

1. «Создать трактовку» запускает выбранный CLI в режиме чтения. Ответ содержит предложение кастинга и трактовки; рабочие файлы ещё не меняются.
2. «Просмотреть предложение и сравнение» открывает окно во всё рабочее пространство, как на странице «Производство»: роли, внешность, пути изображений, начальные состояния, логлайн и части песни. В строке действий окна «Применить и утвердить кастинг и трактовку» отдельно подтверждает запись пары, «Отклонить предложение» убирает его, «Закрыть без применения» оставляет на потом. Сравнение разбито на сворачиваемые блоки: изменённые раскрыты и помечены числом изменённых полей, остальные свёрнуты; значения показываются словами, а не разметкой или JSON.
3. «Создать сценарий» становится доступно только при актуальном утверждении. Приложение получает полный каркас от `scene_scaffold --dry-run --json`, агент заполняет постановку без изменения кадровых окон и строк песни.
4. Подробный сценарий тоже сначала показывается как предложение и записывается отдельной кнопкой. «Доработать выбранный план» требует замечание и сохраняет остальные планы; в сравнении показано влияние на наследуемые состояния.

Существующие кастинг и трактовку можно утвердить отдельной кнопкой без повторной генерации. После изменения первого прохода готовый ручной реестр можно просмотреть и «Утвердить текущий сценарий». Это сохраняет возможность закончить работу вручную, не запуская CLI. Утверждение не означает создание или принятие видео.

## Черновики и актуальность

Несохранённые правки редактора сначала нужно сохранить или отменить. Завершение задания не перезагружает редакторы. Невалидный JSON, отмена и ошибка CLI не меняют файлы проекта; повтор подготавливает новый контекст, автоматического возобновления нет.

Предложение связано с хешами входов и файлов назначения, включая отсутствие файла. Изменение исходника, кастинга, трактовки, реестра или производного файла делает предложение устаревшим: требуется новый проход. Утверждение первого прохода связано с фактически сохранёнными данными. Внешние изменения исходников нужно загрузить через форму исходников, чтобы manifest снова соответствовал файлам.

Обложка и время сохранения манифеста не входят в содержательный отпечаток исходников. Их изменение не снимает утверждения пары и сценария и не делает готовое предложение устаревшим. Старые актуальные снимки переводятся без переутверждения только при точном совпадении прежнего хеша с текущими байтами; перед сохранением исходников приложение сохраняет такой перевод, пока прежний манифест ещё доступен. Несовпадающее старое утверждение не восстанавливается автоматически.

При изменении кастинга или трактовки прежний сценарий требует пересмотра. На страницах «Проект», «Сцены», «Производство» и «Аниматик» отображается предупреждение; старый аниматик не считается актуально утверждённым. История принятия видео и принятые медиа сохраняются.

## Применение и восстановление

Первый проход проверяет и записывает только `plan/cast.json` и `plan/treatment.json`. Подробный сценарий проверяется во временной копии: `lint_registry`, `continuity_brief`, создание производных и `update_scene_views --check`. Копия не использует ссылки на изменяемые рабочие каталоги. До публикации хеши проверяются повторно.

Публикуются только целевые JSON и известные производные штатного инструмента: ROADMAP, монтажный список, раскадровка, справочник, Markdown разметки, индекс комплектов и карточки. Документы README принятых комплектов относятся к этим производным; исходники, принятые manifest и медиаданные не перезаписываются.

Перед заменами сохраняются прежние байты, права и признаки отсутствия в каталоге состояния приложения `scenario-apply`. Если любая замена не удалась, возвращается весь затронутый набор. Pending-record и резервы сохраняются при неудаче восстановления. После аварийного закрытия следующий оконный запуск завершает восстановление до показа проекта; headless-вызов инструмента не прерывает применение работающего окна. Если папка проекта перенесена или недоступна, восстановление не создаёт её заново: резервы сохраняются, приложение показывает ошибку и закрывает текущий проект. Верните папку по указанному пути и перезапустите приложение; другие проекты остаются доступны. Не удаляйте каталог восстановления до устранения ошибки.

## Управляемые навыки

При открытии управляемого клипа устанавливаются реальные копии `ai-clip-scenario` в `.agents/skills` и `.claude/skills`, включая `agents/openai.yaml`. Учёт копий — `.songframe/managed-skills.json`. Если после клонирования этот файл отсутствует, приложение восстанавливает учёт каждой полной копии, совпадающей с текущей поставкой для Linux или Windows, с учётом возможного преобразования окончаний строк Git. Команды затем обновляются для текущей ОС.

Изменённые, неполные и содержащие дополнительные файлы копии, неизвестные символические ссылки и повреждённый файл учёта остаются конфликтами. Пользовательские навыки и изменённые копии сохраняются; при конфликте показан конкретный путь. Исправьте конфликт вручную и откройте проект заново. Просмотр и ручное редактирование не блокируются.

Приложение передаёт инструкции навыка и контракт `output=proposal` через stdin. Claude сохраняет набор Read/Glob/Grep, Codex — read-only. Это использование инструкций навыка; нативное обнаружение навыка в интерактивном CLI проверяется отдельно и не подменяется наличием файлов.

## IPC

`window.api.scenarioWorkflow` предоставляет `view`, `start`, `apply`, `approveCurrent`, `approveScenes`, `discard`. Отмена и поток используют прежний `agents` API. Оболочка ответа агента содержит `schemaVersion: 1`, `pass` и `cast/treatment`, `scenes` либо ограниченный список `patches`; форматы файлов проекта остаются прежними. Ошибочные структуры проверяются до обращения к типизированным полям.

Сценарный процесс не отправляет Kling-запросы, не принимает assets и не делает commit/push. Агентные проходы сценария через менеджер Claude/Codex доступны только на Linux; в Windows этот запуск отклоняется. Ручные редакторы и локальные инструменты не требуют агентного CLI.
