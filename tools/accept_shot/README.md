# accept_shot

Переносит принятую генерацию из попытки `kling_request` в комплект `assets/shots/Mxx` по [контракту assets](../../templates/project/assets/README.md#локальный-манифест-и-воспроизведение): полный оригинал, отдельный принятый монтаж, входы без побайтовых дубликатов, промпт, технический снимок запроса без времени и баланса, `preparation.json`, WAV липсинка, `manifest.json` с рецептом воспроизведения. Приложение вызывает инструмент на этапе приёмки после решения пользователя о монтажном участке; инструмент не выбирает участок сам и не заменяет уже выбранный комплект.

```sh
python3 -B tools/accept_shot/accept_shot.py M32 --package plan/batches/M32-attempt-01 --review plan/batches/M32-review/review.json
python3 -B tools/accept_shot/accept_shot.py M32 --package plan/batches/M32-attempt-01 --cut 0:204 --clean
python3 -B tools/accept_shot/accept_shot.py M32 --work-dir plan/awaiting/M32/request --cut 6:150 --speed 1.2 --hold-last 24 --clean
python3 -B tools/accept_shot/accept_shot.py M44 --package plan/batches/M44-attempt-02 --cut 0:141 --audio /tmp/M44/speech.wav --audio-recipe /tmp/M44/audio-recipe.json
```

Источник: `--package` (папка `shot_workflow` с `workflow.json`) или `--work-dir` (папка попытки с `request.json`, `attempt.json` и скачанным `original.mp4`); попытка должна быть в состоянии `downloaded`. Участок: `--review` берёт параметры этого плана из JSON-рецепта пробы и проверяет, что проба собрана из того же оригинала; `--cut НАЧАЛО:КОНЕЦ` с `--speed`, `--hold-first`, `--hold-last` задаёт их напрямую на сетке 30 кадров/с, как в [формате пробы](../build_review/spec-format.md); `--full` — побайтовая копия оригинала, когда он уже совпадает с окном и FPS. Фильтр обработки считает `build_review`, поэтому принятый клип совпадает с тем, что показывала проба. Длина участка с удержаниями обязана равняться окну плана в реестре, иначе перенос останавливается до записи в assets.

Речевой план требует `--audio` с точным WAV и, при наличии, `--audio-recipe`. Дополнительные файлы подготовки (промпты кадров, промежуточные изображения) передаются через `--preparation`. После записи комплект проверяется `asset_package`, фактический расход попытки записывается наблюдением в таблицу `cost_check`, представления обновляются (`--no-views` отключает). `--clean` удаляет пакет попытки и файлы пробы только после успешной проверки; без него они остаются для ручной очистки. `--replace` разрешает приёмку для плана, у которого комплект уже есть: прежний комплект целиком переезжает в `assets/replaced/Mxx/<время>` (оригинал, монтаж, входы, промпт и манифест сохраняются), новый занимает `assets/shots/Mxx`; без флага такой план отклоняется. Неполный комплект никогда не остаётся в assets: сборка идёт во временной папке и переносится целиком.

Изображения, переданные в `--preparation` из папки `source`, сохраняются дескрипторами `root: "source"` с относительным путём и SHA-256, без копии в assets. Уникальные изображения и промпты копируются в комплект. В `source` разрешены только изображения подготовки.

`--clean` — штатный шаг приёмки: приложение всегда передаёт его при «Принять». после успешной проверки комплекта удаляются переданный пакет попытки или пакет очереди, JSON и MP4 пробы, все остальные пакеты и пробы в `plan/batches`, у которых все планы-владельцы уже приняты (владельцы — поле `shot` в `workflow.json` или `request.json`, список `shots` пробы либо код в начале имени папки), и опустевшие папки проб. Проба с ещё не принятым соседом остаётся. Пакеты других планов, очередь других планов и assets не затрагиваются; без флага ничего не удаляется, и папки остаются до ручной очистки.

Сохранённые ручные монтажи в `plan/montage` удерживают используемые рабочие пакеты от `--clean`. Папки ручного экспорта с `montage.json` также сохраняются: эти пробы пользователь оставил для дальнейшей работы.

## Тесты

Обрезка с дедупликацией входов и проверкой комплекта, скорость и удержания, рецепт пробы из того же оригинала и очистка, речевой план без WAV, защита существующего комплекта, общие референсы через ссылки на source рядом с локальными файлами подготовки.

```sh
python3 -B tools/accept_shot/test_accept_shot.py
python3 -B tools/run_tests/run_tests.py --only test_accept_shot
```

Тесты создают настоящее видео FFmpeg во временной папке и не трогают assets проекта. Для полного набора — [run_tests](../run_tests/README.md).
