# align_lyrics

Строит черновик разметки песни `plan/audio/timing.json`: выравнивает точный текст `source/text.md` по словам локального распознавания и оценивает начало и конец каждой строки. Использовать на этапе разметки трека (кнопка «Разметить» приложения) и при повторной разметке после замены трека или текста. Оценки не подтверждены на слух: подтверждение делает пользователь в редакторе таймингов приложения, подтверждённые строки инструмент сохраняет.

## Контракт

Из корня комплекса, для выбранного проекта:

```sh
python3 -B tools/align_lyrics/align_lyrics.py --dry-run
python3 -B tools/align_lyrics/align_lyrics.py
python3 -B tools/align_lyrics/align_lyrics.py --recognition /tmp/recognition.json
python3 -B tools/align_lyrics/align_lyrics.py --model ~/.local/share/songframe/models/faster-whisper-medium --keep-recognition /tmp/recognition.json
python3 -B tools/align_lyrics/align_lyrics.py --vocal-result /absolute/path/to/result.json --song-models /absolute/path/to/song-models --model /absolute/path/to/faster-whisper --device cpu
python3 -B tools/align_lyrics/align_lyrics.py --json
```

- Без `--recognition` запускается [transcribe_local](../transcribe_local/README.md) с моделью из `--model` (в приложении — выбранная пользователем или рекомендованная внешняя модель; в CLI — `SONGFRAME_MODEL_DIR` или каталог данных ОС: `$XDG_DATA_HOME/songframe/models/faster-whisper-medium`, при отсутствии XDG_DATA_HOME — `~/.local/share/...`, на Windows — `%LOCALAPPDATA%/songframe/models/faster-whisper-medium`) напрямую через текущий `sys.executable`, с `--allow-network`. Обязательного `unshare` нет: его наличие не гарантирует разрешение user namespaces, из AppImage возможен отказ записи `uid_map`. Модель читается только локально, скачивание отключено. JSON распознавания сохраняется вне проекта (`--keep-recognition` или временная папка). FFmpeg/ffprobe в Linux- и Windows-приложении берутся из поставки через PATH общего launcher. Пользовательский `--model` имеет приоритет над моделью приложения. Распознавание трека длится несколько минут на CPU.
- Модель скачивается отдельно по [инструкции](../../README.md#модель-распознавания). При проверке папки допускаются `vocabulary.txt` и `vocabulary.json`; `--device auto` (по умолчанию) или `--device cpu` передаются распознавателю. CUDA требует отдельно установленных библиотек, иначе используется CPU.
- Формат проверяется до распознавания: пустые/непарные скобки, заголовок вместе со словами, Markdown-списки и названия частей без скобок вызывают ошибку с номером строки. UTF-8 BOM и CRLF допускаются; пустые строки между секциями необязательны.
- Текст: одна строка песни на строку файла, заголовки частей в квадратных скобках, пустые строки разделяют части. `source_line` в разметке это физический номер строки `text.md`, заголовки и пустые строки нумерацию не сдвигают.
- Обычный режим: глобальное сопоставление последовательностей слов (нормализованных, без пунктуации, ё как е) с нечётким сравнением; строка получает начало первого и конец последнего сопоставленного слова с реальными word timestamps. Сегмент без времён отдельных слов не разбивается равномерно и не даёт обычному режиму речевых ориентиров. Строки без сопоставленных слов не входят в `lines` и доступны в «Неразмеченных строках» приложения. Интерполяции пропусков нет; в `note` записывается число совпавших слов и пометка «сверка на слух не выполнена».
- `--vocal-result <result.json>` вместе с `--song-models <папка>` включает [режим по готовому вокалу](../song_timing/README.md): Whisper → CTC-уточнение точных строк. Вокал заранее создаётся отдельным [separate_vocals](../separate_vocals/README.md) и выбирается пользователем. Без `--vocal-result` флаг `--song-models` даёт понятный отказ до ASR; автоматического отделения нет. CTC-компонент `alignment` устанавливается явно через [download_song_models](../download_song_models/README.md), отдельно от faster-whisper и моделей вокала. Исходный MP3, метаданные результата и SHA WAV проверяются до и после; временная шкала не обрезается. Граница относится к целой исходной строке, неподдерживаемый текст и отсутствие акустической опоры не получают выдуманное время. Сомнительные реальные CTC-пути сохраняются отдельно в `candidates` с физическим `source_line`, точными `start`/`end`, `reason` и необязательными `acoustic_score`, `note`; причины также печатаются в журнале. Предложения могут пересекаться и не считаются подтверждёнными строками. Без флага остаётся обычный Whisper. При `--recognition` используется уже готовый JSON: `--song-models`, `--vocal-result`, `--model` и `--device` не запускают обработку повторно.
- `sections`: части по заголовкам текста учитывают интервалы `lines` и `candidates`; новые секции получают `origin: "auto"`. Когда есть пропуски или сомнительные кандидаты, промежутки длиннее 2 с называются «Не размечено», а не «без вокала». При полной разметке остаются «Вступление», «Проигрыш после «…»» и «Финал без вокала».
- Существующий `timing.json`: строки с `verified: true` сохраняют границы, подтверждение и заметку (по `source_line`), даже если ASR не нашёл строку; идентификаторы `id` перенумеровываются плотно. Ручные заметки сохраняются, неподтверждённые границы пересчитываются. Заметка кандидата `note` сохраняется по `source_line` при повторной разметке и переносится в `lines.note`, если алгоритм принял новые границы; пользовательская заметка прежней строки имеет приоритет. Одна правка заметки кандидата не принимает и не подтверждает его границы. Статус раздельно сообщает число предложений для ручной проверки и число строк без кандидата. Кандидат той же строки убирается при наличии сохранённой подтверждённой границы или нового принятого результата. Полностью ручная карта секций сохраняется целиком; в смешанной карте автоматические секции пересчитываются, ручные имеют приоритет при совпадении названия. `origin: "manual"` обозначает ручную секцию. Прежняя секция без `origin` считается автоматической только по полной системной подписи имени и заметки: название текущей части + `строки N–M`, «Вступление»/«Проигрыш после «…»» + `без вокала`, «Финал без вокала» + `до конца трека`; остальные сохраняются как ручные. `--reset` пересчитывает всё. Если нет ни совпадений, ни кандидатов, ни сохранённых подтверждений, обработка завершается ошибкой без публикации нового файла. Конфликтующие или пересекающиеся канонические строки и нечисловые границы дают отказ. Пересечения предложений не мешают публикации: они остаются отдельными кандидатами до ручного решения.
- `--output` пишет в другой файл, `--dry-run` не публикует `timing.json`, но без `--recognition` выполняет распознавание и может сохранить его промежуточный JSON. Если JSON распознавания содержит `sha256`, он должен совпадать с текущим MP3; устаревшее распознавание отклоняется. Перед публикацией проверяются неизменность MP3, текста и прежней разметки; результат записывается атомарно. Ошибка ASR, выравнивания или записи не заменяет прежний `timing.json`.
- Формат файла использует версию 2 (`version`, `status`, `source`, `sha256`, `duration_decoded`, `duration_container`, `clock`, `lines`, `sections`); у строк есть поле `verified`, необязательные `candidates` хранят сомнительные предложения, `line_order` — очередь физических номеров строк текста. Повторная разметка сохраняет валидную прежнюю очередь и добавляет новые строки в порядке исходника. Разметка не задаёт монтажные окна сцен.

Распознаватель использует VAD и защиту от галлюцинаций; времена возвращаются к полной шкале. Схлопнутые временные ориентиры не участвуют в сопоставлении, исходные ответы и причины исключения сохраняются в JSON распознавания. Политика и границы гарантии — в [transcribe_local](../transcribe_local/README.md#защита-качества-распознавания).

## Тесты

Без `--keep-recognition` каждый запуск создаёт отдельную временную папку распознавания и удаляет её после чтения JSON или исключения. Проекты с одинаковым именем и повторные попытки не делят один файл. Явный `--keep-recognition` сохраняет результат по указанному пути, в том числе при `--dry-run`; для параллельных запусков выбирайте разные пути.

Пользовательская заметка сохраняется и при совпадении начала со служебной фразой: заменяется только полная неизменённая автоматическая заметка. Минимальная длина принятой строки остаётся 0,3 с; числовой допуск 10⁻⁹ с в Whisper-оценке, CTC и итоговой проверке снимает только погрешность `float` у точной границы. Готовый `--recognition` с неконечной, неположительной или нечисловой длительностью отклоняется; перед публикацией весь результат проверяется как строгий JSON, включая сохранённые ручные секции.

Синтетическое распознавание без модели и сети: ошибки распознавания, лишние слова, пропуски без интерполяции, ненайденная первая строка после вступления, полное отсутствие совпадений, части, сохранение подтверждённых строк и заметок (включая изменённые служебные фразы), точные CTC-границы и минимум 300 мс, пересекающиеся кандидаты и приоритет подтверждённых строк, сохранение очереди, пересчёт автоматических секций с сохранением ручных, неверные интервалы/длительности и отказ при NaN/Infinity, атомарная публикация, отдельные временные файлы распознавания и изменение исходников во время работы.

```sh
python3 -B tools/align_lyrics/test_align_lyrics.py
python3 -B tools/run_tests/run_tests.py --only test_align_lyrics
```
