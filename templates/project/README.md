После перемещения приложения или проекта откройте проект заново: системный Python и изменение путей вручную не нужны.

## Kling: вход и команды

В готовом приложении Node.js, npm и Kling CLI устанавливать отдельно не нужно: CLI использует runtime приложения. Из папки клипа запускайте команды для своей ОС:

Linux:

```sh
./.songframe/run-kling --version
./.songframe/run-kling who_am_i --quiet
```

Windows (PowerShell или CMD):

```powershell
.\.songframe\run-kling.cmd --version
.\.songframe\run-kling.cmd who_am_i --quiet
```

Для первого входа запустите тот же launcher с аргументом `login` и завершите авторизацию в браузере. Официальный CLI сохраняет вход в `~/.kling/.credentials` на Linux или `%USERPROFILE%\.kling\.credentials` на Windows; если вход уже работает, повторять его не нужно. Нового хранилища токенов у проекта нет. Вход также доступен на странице «Среда»: «Войти» либо «Сменить аккаунт».

Приложение также поддерживает самостоятельный режим `--songframe-kling <аргументы>`. После перемещения приложения откройте проект заново, чтобы обновить `run-kling`. Только в разработке без подготовленного встроенного CLI используется обычный `kling` из PATH.

## Скилл ai-clip-scene

Подготовка кадров, подтверждение запроса, генерация, повторы и получение результата описаны в скилле `ai-clip-scene` комплекса. Это сообщения агенту, а не команды терминала:

| Задача | Пример |
| --- | --- |
| Конкретный план | `$ai-clip-scene scene=M15`: все опоры согласуются одним сообщением (`approval=shot`) |
| Сложный план по одной опоре | `$ai-clip-scene scene=M15 approval=frame` |
| Партия независимых планов | `$ai-clip-scene batch=M52,M53,M55` |
| Исправленная попытка | `$ai-clip-scene scene=M15 retry="Убрать лишнюю руку"` |
| Предложить следующий план | `$ai-clip-scene scene=next` |
| Список сцен | `$ai-clip-scene list=all` · `list=progress` · `list=completed` |

Ограничения поручения дописываются обычным текстом. Настройки проекта в [AGENTS.md](AGENTS.md).

## Сборка и проверка

В `.vscode/settings.json` подключены локальные JSON-схемы для `plan/scenes.json`, `plan/cast.json`, манифестов сцен и рабочих пакетов: VS Code подсвечивает ошибки структуры при правке. Ссылки ведут в `.songframe` относительно папки проекта. Если приложение или проект перемещены, откройте проект заново в приложении: оно обновит launcher и схемы; исправлять абсолютные пути вручную не нужно.

Linux:

```sh
./.songframe/run-tool check_assets
./.songframe/run-tool build_animatic
```

Windows (PowerShell или CMD):

```powershell
.\.songframe\run-tool.cmd check_assets
.\.songframe\run-tool.cmd build_animatic
```

Проверка комплектов и полная сборка в `plan/animatic/latest` по [правилам аниматика](plan/animatic/README.md). MP4 полной сборки в Git не хранится (`.gitignore`); проверки представлений и владения сведениями выполняет приложение комплекса по [порядку из AGENTS.md](AGENTS.md#git-и-порученный-коммит).

Аудио: [разметка трека](plan/audio/timing.md) и повторный локальный анализ инструментом `transcribe_local` комплекса; временные результаты вне проекта.

Провайдеры генерации в новом проекте не выбраны: `generation.video` и `generation.image` в `plan/project.json` равны `null`. Перед AI-действиями явно выберите агента в приложении и нужного медиапровайдера в настройках проекта, затем сохраните их. Только `provider_selected: true` подтверждает выбор медиапровайдера; старое имя `provider` без этого маркера остаётся доступным для просмотра и перенастройки, но не разрешает запуск.
